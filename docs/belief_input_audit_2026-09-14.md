> **样本**：25 局 / 3756 决策帧；随机对手 + 我方 noop（**不是**训练用的对手池策略 ⇒ 见 §5 局限）。

## §0 结论（三句话）

1. **手牌 / 下一张：没有 headroom。** 信念进入"锁定流"后是**精确 0/1**，实测准确率
   **100.0%**；未锁定阶段（每局开局一段，中位 46 帧）准确率 ≈ 随机——那是因为
   **信息确实还没出现**（只看到 0~3 次出牌），换成"精确枚举"也只能得到同样的后验。
   ⇒ **不建议改**（改了只有 MC 噪声的小幅下降，没有准确率提升）。
2. **圣水：有确凿错误，且可一行级修好。** 现状估计器（`_tick_elixir`）在正常相位
   有 **−0.18 的恒定低估**（= 恰好一帧回复量 0.5/2.8=0.1786，首帧回复未计入），
   双倍圣水相位低估达 **−1.19**（最大 −2.32，硬编码 `dt/2.8` 与引擎 1.4 s/点 不匹配）。
   同一轨迹上用**分段正确**的圣水账，MAE **0.198 → 0.002**（正常相位 **0.000**）。
3. **`elixir_std` 是启发式**（`max(0.5, |est−5|/5)`）：真实误差 ~0.18，它却报 0.5~1.0
   ⇒ **不确定度通道是错的量纲**（可一并修）。

**定位**：这是**正确性修复**（【R12】"能算的不许让网络猜" + 单一常量源），
**不是性能赌注**——【P3′】已实测 belief 通道对局内回报可预测性的增量上限仅 **+0.4pp**。
**但它有一个罕见的优点：维度不变 ⇒ 语义不变 ⇒ 不需要 `--fresh`，旧 ckpt 可直接续训。**

## §1 读数（脚本复算）

### 1.1 循环信念（对手手牌 / 下一张）

| 分组 | 手牌集合 top-4 命中率 | 真手牌概率质量和（4.0=完全正确） | 下一张 top-1 命中 |
|---|---|---|---|
| 全部帧 | 73.9% | 3.6317 | 72.3% |
| **锁定帧（70.0%）** | **100.0%** | **4.0000** | **100.0%** |
| 未锁定帧（30.0%） | 12.9% | 2.7703 | 7.5% |

**未锁定"段"结构**：25 段 / 25 局 ⇒ **每局恰好 1 段**，段长中位 **46 帧**（最长 46）
⇒ **不是"锁被反复打断"，而是每局开局的信息真空期**（需 ~4 次出牌才能重建循环；
随机对手 46 帧内只出得起 ~4 张）。

> 机制：`CycleBayesFilter._lock_from_tail`（`bayes_filter.py:76-87`）用最近 4 张合法出牌
> **精确重建**规范 cycle ⇒ 之后 `hand_probs/next_probs` 为 0/1、熵 0
> （`bayes_filter.py:57-59, 178-184`）。

### 1.2 圣水估计（现状 vs 分段正确的账）

| 相位 | n | 现状 MAE | 现状偏置(估计−真值) | 分段正确账 MAE |
|---|---|---|---|---|
| 全部 | 3756 | **0.198** | −0.198 | **0.002** |
| t<120 s | 3681 | 0.177 | −0.177（最负 −0.179） | **0.000** |
| 120≤t<240 s（双倍） | 75 | 1.189 | −1.189（最负 −2.315） | 0.119 |

**逐帧诊断**（已定位）：估计−账 = **恒定 −0.179**，从第 1 帧起就存在
（第 0 帧 `_last_time is None` ⇒ 直接 return，**首帧回复未计入**）。
⇒ 正常相位的误差**全部**来自这一处；双倍相位的额外误差来自
`dt/2.8` 与引擎 `battle.py:2690` 的 **1.4 s/点** 不匹配（速率差 0.357 圣水/s）。

### 1.3 真值侧检查

真圣水 ≥9.99 的帧占比 **0.0%**（本样本无上限溢出）⇒ "账不准"**不是**由满费溢出造成的。

## §2 建议的最小改动（**修正**，非新能力）

```python
# rl/belief.py::BeliefInference._tick_elixir（现状）
self._elixir_est = min(10.0, self._elixir_est + dt / 2.8)     # ← 硬编码 + 首帧 return
```

**改为**（与引擎常量**同源**，不复述数字）：

```python
# 与 battle.py:2690 同一分段口径：t<120 → 2.8s/点；120≤t<240 → 1.4s/点；t≥240 → 2.8/3 s/点
self._elixir_est = min(10.0, self._elixir_est + dt / _regen_rate(t))
```
外加：**首帧也计入回复**（`_last_time` 初始化改到 `update` 首次调用时按 t=0 起算，
或首个 `dt` 用 `t − t_prev_known`）；`elixir_std` 改为由**已知误差源**推导
（cap 溢出歧义 + Mirror/形态卡费用歧义），而不是 `|est−5|/5`。

**兼容性**：
- **维度不变**（`belief_token` 仍 563）⇒ `belief_mlp` 输入形状不变 ⇒ **不需要 `--fresh`**；
- **语义不变**（这一维仍是"对手圣水估计"，只是更准）⇒ 旧权重继续可用；
- 仍按【R2】**加开关 `elixir_ledger: bool = False`（默认回旧）**，因为默认行为会变；
- 【R7】常量必须单源：`_regen_rate` 应与 `battle.py:2690` 共用（抽函数或加对账 selftest），
  禁止在 belief 侧再写一遍 2.8/1.4。

**验收判据（跑前写死）**：
1. 机制层：同一轨迹上 `elixir_mean` 的 MAE（本脚本复算）——**门槛：≤0.05**（现状 0.198）；
2. 回归：`rl/selftest.py` 全绿 + 新增 1 项"双倍相位圣水账"测试；
3. 行为层 3 项（`forensics_card_usage.py`）与结构层占比——**只作描述**（阈值按【R15/R16】
   在本 run 上标定，禁止照抄）；
4. 阳性对照：`elixir_diff_weight=0`（已知会改读数）；阴性对照：同配置重跑量散布。

## §3 明确**不做**的事（含理由）

| 不做 | 理由（本次实测） |
|---|---|
| 把手牌/下一张的**概率**换成**精确枚举** | 锁定后**已经**精确（100.0%）；未锁定阶段是**信息不足**而非算法不足 ⇒ 无 headroom |
| 注入**真值**特权手牌/圣水 | 同上无 headroom；且【P3′】特权/oracle 通道增量上限 **+1.1pp**；还要付 `--fresh` |
| 接入未使用的**神经 belief token** | 维度 563→627 ⇒ 架构变更 + `--fresh`，收益上限同上 |
| 因为 30% 未锁定帧而"重做信念" | 未锁定 = 每局开局 1 段 46 帧，**是问题本身的性质**（需 4 次出牌才能重建循环），不是 bug |

## §5 局限（预先声明）

1. **对手不是训练用对手池**：本脚本用 `opponent=None`（随机），我方 noop ⇒ 局均 ~150 帧，
   而训练局 217~360 帧 ⇒ **未锁定帧占比（30%）被高估**（开局 46 帧在更长局里占比更小）；
   真实占比**未测 ⇒ 待确认**。
2. **未覆盖 t≥240 s 相位**（本样本 0 帧）⇒ 三倍段（2.8/3 s/点）的误差**未测**。
3. 我方 noop ⇒ 对手行为分布与训练不同 ⇒ `tendency_probs` 等统计量**未审计**。
4. 单 seed、单样本（3756 帧）⇒ 不跨 run 外推（【R5】）。
5. 本审计**只量输入准确度**，**没有**声称修好后能提升强度——收益上限见【P3′】（+0.4pp）。
6. 我在本仪器开发中先后修掉**两个自己的 bug**（`env.reset` 重洗卡组导致 deck 映射过期；
   统计矩阵列索引取错），最终读数均已复核；过程留痕见提交信息。
