## 3 配对实测（**同一批真实对局**，零重算）

数据：`runs/demo20k/replays/league_*.pkl`，7 个评估点 × 40 局 = **280 局**（demo20k 是 20k 试跑，
policy = `solo_main_{0,2500,…,15000}.pt`）。每局终局状态（`t / towers0 / towers1 / crown0 / crown1`）
都在回放里 ⇒ 同一批对局上并存"旧标签 / 训练侧 C′ 标签 / 新标签"。

**复现校验（本页读数的前提）**：脚本用旧口径（评估语义，无边距）重算 280 个标签，
与回放里记录的 `winner` **280/280 逐局一致** ✅ ⇒ 重算可信。

| 口径 | W / L / D | 平局率 |
|---|---|---|
| **旧（评估口径）**：最低塔血百分比 | 140 / 107 / **33** | **11.8%** |
| 旧 + 训练侧 C′ 边距 0.05（`settle_stall(margin=0.05)`） | 135 / 91 / **54** | **19.3%** |
| **新（本次口径）**：三塔血量合计 | 140 / 107 / **33** | **11.8%** |

配对逐局变化：`D→胜负 = 21 局`（**全部来自训练侧的 margin 路径**）；新旧口径之间另有 2 局
W↔L 反向（合计互补，故 W/L 总数不变）。逐点：`eval@10000` 训练侧 6 平 → 评估/新 1 平；
`eval@12500` 22 平 → 18 平；`eval@5000` 26 平 → 14 平。

## 4 关键发现：**用户指定的规则并不能降低"评估侧"平局率**（如实报告）

| 旧口径平局（33 局）解剖 | 局数 | 新口径下的命运 |
|---|---|---|
| **(a) 全程零塔损**（双方塔血都没掉过一点） | **32** | **仍判平**（塔血确实完全相同） |
| (b) 有塔损、三塔合计恰好相等 | 1 | 仍判平 |
| (c) 有塔损、合计不等（旧口径漏判的胜负） | **0** | — |

- (a) 这 32 局的 `t` 中位 = **50.0 s**、帧数中位 **100** ⇒ 它们是**僵局早停**（连续 100 步零塔损）
  在 **50 秒**就结束的对局，不是打到 180/300 秒的对局；
- 旧评估口径下它们本来判平（双方最低百分比都是 1.0），**新口径也判平**（双方塔血合计都是满值）——
  **按用户口径这是正确的**（塔血相同 ⇒ 平局）；
- 结论：**"评估侧 11.8% 的平局"不是标签 bug，而是行为症状**——双方在 50 秒内谁都没能打掉塔
  （与【未决 O3】"不会攒费/不打塔"是同一条病理）。本次改动**修的是训练侧的 21 局伪平局**
  （旧 C′ 边距把"塔血更多的一方"记成平局 —— 这正是用户说的"正常防守被判为平局"）。

## 5 影响面（重要）

- **训练标签与评估标签从此同口径**（旧：训练 19.3% 平 vs 评估 11.8% 平；新：两者都 11.8%）。
  这消除了"训练学的标签 ≠ 评估口径"的错位（也是本 run 里 `mean_reward` 与胜率对不上的一个来源）。
- **与所有历史 run 的标签不再可比**：同一批对局有 **21/280 = 7.5%** 的对局标签发生变化
  （另有 2 局 W↔L）。历史 run 的胜率/平局率若要对比，必须按"旧口径"复算或重跑。
- **旧口径可逐位复现**：`--stall-draw-margin 0.05` 恢复训练侧 C′ 标签；引擎 300 s 的
  最低百分比口径已删除（要复现需 `git revert`，commit 记录在案）。

## 6 未决 / 待用户拍板

**0-0 全程零塔损的僵局（占评估局 11.4%）该怎么算？** 本次改动按用户口径仍判平。三条路：

1. **保持判平**（= 用户口径）。但 50 秒就早停、且占一成局；要减少它只能改**行为**（O3），不是改标签。
2. **取消僵局早停、打满到 300 秒**：标签大概率仍平（塔血仍相同），只增加算力 ⇒ 单纯这样改**无收益**。
3. **把 0-0 视为一种失败**（奖励侧改动，不是裁决规则）：逼策略主动破塔；但这改的是 `draw_penalty`
   或新增"零伤害惩罚"，与本次"裁决口径"是**两个变量**（须另做预注册）。

## 9 追加改动（2026-09-17 用户第二次拍板）：**停用僵局早停**

用户原话：「50秒内未打掉塔不该被作为一个正确的减少训练时间的行为，为了那些对局，我们接受这些
时间损失，更别提我们的平局跟失败都扣10分了」

**改动**（单变量：是否允许"零塔损 50 s"截断对局）：

| 落点 | 改动 |
|---|---|
| `rl/config.py` | `train_stall_stop: True → **False**`（默认关；`--train-stall-stop` 正向复现旧行为，`--no-train-stall-stop` 保留兼容） |
| `rl/train_solo.py` | 串行 `eval_solo` 与并行 worker 的早停改为受开关控制（此前**硬编码**）；worker 签名加 `stall_stop` 并随 spawn 传参 |
| `rl/run_league.py` | `_run_side0` / `_run_side0_scripted` 加 `stall_stop=False` 参数并受控；**修一个真 bug**：`_run_side0` 对 ScriptedPolicy 的转发漏传 `stall_stop`（会让开关静默失效） |
| `rl/selftest.py` | `test_eval_stall_early_stop` 重写为"默认不早停（打满 300 s）∧ 显式开启可复现旧行为（50 s）" |

**代价实测（同一批 280 局回放，脚本复算）**：

| 项 | 值 |
|---|---|
| 原本被早停截断的对局 | **271 / 280 = 96.8%**（不只是那 32 局平局！其帧数中位 **153** = 76 s） |
| 总帧数 | 现状 51,559 → 停用后 **101,029（+95.9%，下界）~ 166,069（+222.1%，上界）** |
| 同 `--total-steps 20000` 对应局数 | **109 → 34~55** |
| 评估墙钟 | 近似同比例上升（评估占 20k 协议墙钟 ~73%） |

**⚠️ 必须知道的副作用（与用户意图可能冲突，如实报告）**：僵局早停原本**同时**是"让终局罚可见"的
信用分配装置（`config.py:149` 原注释：「否则躺平要拖满 max_ep_steps 才在 360 帧末罚一次 −10，
`(γλ)^k` 视野内完全不可见」）。停用后每步看到的终局罚权重 `(γλ)^k`：
**100 帧 ≈ 0.27 → 360 帧 ≈ 0.009 → 600 帧 ≈ 3e-4**（γλ≈0.987）⇒
**平局/失败的 −10 反而变得更难学**（用户希望它更有效）。三条可选补偿（均属**另一个变量**，须另预注册）：
1. 按比例提高 `--total-steps`，让"局数"回到 ~109（接受墙钟 2~3×）；
2. 改奖励侧：给"零塔损"加**逐帧**惩罚（不依赖终局罚）；
3. 截断但**不判平**（记 `truncated` 走 bootstrap）——但本项目的 critic 是常数（【C3】/【O2】），
   bootstrap 目前无效 ⇒ 这条实际不可用。
