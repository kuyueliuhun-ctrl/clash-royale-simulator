# D1 长跑预注册：100k 步（2026-09-13，跑前写死）

本文件在**启动之前**固定协议、判据、对照与失败分支。任何事后修改都必须以"追加修订"形式
留在文末，不得改写本节的判据（D1 20k 曾因预注册里手抄基线数字出错而浪费一轮判别力，
教训见 `docs/d1_league_20k_verdict_2026-09-13.md` §披露）。

## 0. 要回答的问题

- **Q1（主）防崩是否在 4× 训练量下仍成立**：D1 在 20k 只证明了"不崩"（C1 区间与无变化组不相交），
  100k（≈300 局）下是否仍成立？
- **Q2（次）末段是否上移**：D1 20k 已判定"末 4 点滚动均值不可判别（相位主导）"
  ⇒ 100k 只输出**描述性**轨迹，不设判决线（理由见 §3）。

## 1. 协议（唯一变量 = 训练量：20k → 100k）

```bash
cd src/clasher_new
PYTHONIOENCODING=utf-8 ../../.venv/Scripts/python.exe rl/run_league.py \
  --mode solo --config economy --config-name d1_long_100k --fresh \
  --total-steps 100000 --steps-per-eval 10000 --anchor-every 2500 \
  --n-eval-games 40 --eval-workers 12 --device cuda \
  --value-norm running --adv-norm scale --diagnose-every 10 \
  --hist-seed-dir runs/economy_9k_ft --hist-seed-dir runs/economy_9j \
  --ppo-epochs 4 --ppo-minibatch 32 --ppo-shuffle
```

- 代码 = `main`（D1：对手分布去镜像化 + 动态历史自身联赛 + PFSP 门禁），与 D1 20k 三跑同代码；
- 评估节奏 = C 方案（`docs/eval_cadence_c_2026-09-13.md`）：全点每 10000 步（11 个，含 eval@0）
  + 轻量锚点每 2500 步（30 个）⇒ **锚点序列与 2500 全点协议逐点相同**（确定性论证见该文 §5）；
- 预期墙钟 ≈ **2.15 h**（训练 1.07 h + 全点 0.64 h + 轻点 0.44 h）；
- 日志 `docs/train_d1_long_100k.log`，产物 `runs/d1_long_100k/`。

## 2. 预注册判据（主）

**C1-块口径**（把 41 个锚点按 20k 分 5 块，每块 9 点 = 与 D1 20k 基线的 9 点最差点**同构**）：

- 每块 `worst_b = min(该块 9 个锚点胜率)`，b = 1..5；
- **P1**：`mean(worst_1..5) ≥ 0.10` **且** `min(worst_1..5) ≥ 0.05` → 判
  **"防崩在 4× 训练量下成立"**；
- 对照基线（已有、同一口径，9 点/worst）：

| 组 | 单跑 worst | worst 均值 | worst 最小 |
|---|---|---|---|
| D1 20k 三跑 | 0.125 / 0.200 / 0.250 | 0.192 | 0.125 |
| 无变化三跑（fprime / fprime_ev / gfix） | 0.000 / 0.000 / 0.025 | 0.008 | 0.000 |

- **判读规则**：P1 通过 **且** 100k 的 worst 区间与无变化组不重叠 → 判"成立"；
  P1 通过但与无变化组重叠 → 判"部分成立（判据力不足）"；P1 不通过 → 判"4× 量级下失效"。

## 3. 预注册读数（次，描述性；**不判决**）

- 块中位数序列 `median_1..5`（每块 9 点）与 `median_5 − median_1`：
  ≥ +0.10 记"提示上移"、≤ −0.10 记"提示下移"、其间记"不可判"。
  **为什么不设判决线**：n=1/arm，且自对弈 cycling 未消除（D1 20k 的对照曲线相邻点可差 0.6+），
  块中位数在单跑上无法与相位效应区分。此量只作为"天花板问题"的线索，不得写进结论句。
- 诊断读数（同样不判决，只记录异常）：`EV`（池化）、`h_std` / `gru_n_abs`、`vstd/rstd`、
  行为门禁相对退化、`kind_counts`（对手池实际配比）、`对手池刷新` 的"本目录 N"、
  降级次数（必须为 0）、`Traceback`（必须为 0）。

## 4. 披露（跑前已知的偏差，不得当成发现）

1. **补种 ckpt 会被挤出**：`_HIST_POOL_MAX=12` 且本目录优先 ⇒ 20k 时池子 = 本目录 9 + 外部 3，
   100k 时本目录快照 ≥12 ⇒ 池子 12 个**全是本 run 自身快照**。这是训练长度的固有副作用
   （与评估节奏无关），意味着 100k 的对手分布与 20k 并非同构。
2. **n=1/arm 且同 seed 不可复现**（`docs/fprime_rerun_20k_verdict_2026-09-13.md` §8）⇒ 本跑与
   历史基线**非同批**；C1 只回答"是否落在防崩区间"，不回答"比 D1 20k 好多少"。
3. **锚点数 41 vs 基线 9** ⇒ 直接比"全局最差点"是不同严格度；§2 用块口径对齐。
4. **resume 粒度 = 2500**（轻点也落 Adam/run_state），崩溃续训不会一次丢 10000 步。
5. 运行期间**不改代码/配置**；若必须变，则新建分支并单独记录（否则两个实验拼在一起）。

## 5. 失败分支（事先写死，跑完不得现编）

- P1 不通过 → 结论 = "D1 的防崩只覆盖 20k 量级"；下一步候选（择一，需另行预注册）：
  ① 提高 hist 池上限 `_HIST_POOL_MAX`（12→24）让长 run 的自身联赛更密；
  ② 提高 `defend` 槽权重（课程式，逼出对牌能力）；
  ③ 回退到"20k × 5 段续训"的分段评估口径（把量级问题切成可比段落）。
- P1 通过但 worst 与无变化组重叠 → 结论 = "判据力不足"，下一步 = 加大 `n_eval_games`
  （40→80）或先做跨 run 重复（n=3）再判。
- 出现降级/崩溃 → 按 AGENTS 全局约定**暂停留证等人工**，不自动降级、不改配置。

## 6. 判读产出

跑完写 `docs/d1_long_100k_verdict_2026-09-13.md`：判据逐条对账表（含上式基线表原样转载）、
锚点序列全 41 点、块 worst/median、诊断读数、披露与修订记录。

**判读工具（钉死基线口径，禁止手抄）**：`scripts/judge_anchor_blocks.py`

```bash
python scripts/judge_anchor_blocks.py --groups                    # 复算对照基线表（D1 三跑 / 无变化三跑）
python scripts/judge_anchor_blocks.py --run d1_long_100k --expect-total 100000
```

- 数据源 = `runs/<run>/solo_state.json` 的 `_controls_history`（`vs == "baseline_rand"`），
  轻点与全点写同一字段 ⇒ 2500 分辨率锚点序列天然可读；
- 分块**按锚点序号**（每块 9 点，`--per-block-points`）：20k 的 run 自动 = 1 块（全程最差点，
  与 D1 20k 口径一致），100k = 5 块（9,8,8,8,8）；
- **首版按 `step//20000` 切块的写法已废弃**：step=20000 会单独成块，20k run 的
  `mean(worst)` 算成 0.400（文档值 0.192）——这正是"基线必须脚本复算"纪律要防的错；
- `--expect-total` 未达到时输出显式标注"数据不完整，此读数不得作为判决"（防中途读数被当结论）。
