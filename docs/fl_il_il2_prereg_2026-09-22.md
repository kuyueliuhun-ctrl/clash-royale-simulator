## 0. 一句话目标

现在的塌陷（部署 **0.3 次/局**、10 局全平、出牌帧 top1 **0.4042→0.0174**）**同时符合两种机制**，必须先分开再花钱：

* **H-A 优化/混比**：save 帧占 **77.1%**，共享 `slot_head` 的 STOP logit 被多数类推高；且 Adam+bs=1 下**逐样本 loss 加权是 no-op**（尺度无关）⇒ 只有**改混比**能动。
* **H-B 表示不足**（用户假设）：act 决策所需的量（对手手牌/循环/圣水、双方距下一点圣水的帧数、对手刚下了什么）**不在输入里** ⇒「何时出牌」原则上不可判 ⇒ 最优解就是多数类。

**Stage 0 用「信息增益上界」把两者分开，再按性价比排后续。**

## 1. 口径（跑前定死）

### 1.1 观测量 vs 不可观测量（**这条决定 F_obs / F_oracle 的分界**）

| 量 | 人类回放里 | 判定 |
|---|---|---|
| 我手牌（重建 4 槽）、我圣水（重建）、时间、`next_card` | 可重建 | **F_obs** |
| 对手**已出牌**（卡 + 位置 + tick） | **真值可读**（回放事件） | **F_obs** |
| 对手手牌**后验** `hand_probs(8)`、下一张后验 `next_probs(8)`、`elixir_mean/uncertainty`、事件 token | **推断量**（`CycleBayesFilter`，128 粒子） | **F_obs** |
| 我/对手「距下 1 点圣水还有几帧」 | **精确可算**（`battle.py:2881`：2.8 / 1.4 / 2.8÷3 s 每点 ⇒ 每决策帧 **0.1786 / 0.357 / 0.536** 点） | **F_obs 候选**（EBK，【R12】） |
| 对手**真值**手牌 `opp_hand(4)` / 循环 `opp_cycle(8)` / 下一张 `opp_next` / **真值圣水** `opp_elixir` | **不可观测**（回放里没有） | **仅 F_oracle**（诊断用，**不进最终策略**） |

⚠️ **真值只作标签 / 辅助任务 / 上界诊断，不进主观测**（用户已确认的纪律②）——否则「预判」退化成读答案。
⚠️ 对手圣水在回放里不可观测：我方引擎侧是 `_force_elixir` 重建值（出牌强制率 **2.17%**）⇒ 凡用它的结论都标「重建口径」（【R10】）。

### 1.2 帧总体与标签

* 总体 = **掩码放行 ≥1 个「有合法落点」出牌槽的决策帧**（= `save` 帧 ∪ `play` 帧；2200 局里 **686k** 帧）。
* 标签 `act ∈ {0,1}`：该帧人类是否打出牌（`play` 帧 = 1）。
* **切分 = 按局（`tag`）分组留出**（【R9】）：5 折 GroupKFold，AUC 的 CI 用**按局 bootstrap**（不是按帧——帧间强相关）。
* 样本量：**先 200 局**；若 `ΔAUC ∈ [0.03, 0.07)`（边界带）⇒ **自动扩到 600 局再判**（写死，不许事后挑样本量）。
* 分类器 = logistic 回归（`C` 由内层按局 CV 选）+ 直方图 GBM 各一；**两族同向才算数**（防单模型假象）。

### 6.1 ★ 被证伪的旧断言（**先记，不许再引用**）

`docs/fl_il_il2_mix_2026-09-22.md:102-103` 原文逐字：

> **留出侧的性质是恒等式（无需再测）**：组合模型的 act-AUC ≡ 门的 0.7354，play top1/NLL ≡ `R00` 的 0.4188/5.5955
> ——即**同时满足 J8.1 与 J8.2**。

**证伪（2026-09-22 独立复现，只读取证）**：

| 事实 | 读数 |
|---|---|
| 留出集 `runs/_fl_il_bc_save/holdout` | **39,761 帧 = 8,916 play + 30,845 stop**，基率 **0.2242** |
| R337 连续分数 `1−p(STOP)` 的 act-AUC | **0.7353786**（复现 0.7354 ✓） |
| **τ 判决（0/1）后的 act-AUC** | **上界 0.6713**（BA 最大点 τ=0.7407）⇒ **< J8.1 阈值 0.6948** |
| 基率匹配 τ=0.6610（预测出牌率 = 0.2242）下的 play top1 | **0.1749** ⇒ **≪ J8.2 的 0.35** |
| 根因 | **R00 在全部 39,761 帧上 `argmax == STOP` 出现 0 次**（`holdout_mixR00.json`：`model_stop_rate_argmax: 0.0`）⇒ **门的每一次否决都必然丢掉一帧人类出牌帧** |

⇒ **两条路都不是实质检验**：
① 用**连续门分数** ⇒ act-AUC ≡ 0.7354 是**同义反复**（那就是 R337 自己，组合根本没被测量）；
② 用 **τ 判决** ⇒ act-AUC ≤ 0.6713，**J8.1 直接 FAIL**。

⇒ **本节决定：本臂的判决不许用 J8.1**（理由如上，非"放水"）。真正要测的是**闭环**
（共享头诊断预言的是闭环塌陷，不是离线 AUC）。

### 6.8 ★ 但 6.4 的第三条分支被本次数据证明**写得不严谨**（照实记，不改判据文本）

6.4 第三分支原文是「若 K1 也不成立 ⇒ 组合臂路线关闭，**诊断转「不是头耦合」**」。

| 证据 | 读数 | 含义 |
|---|---|---|
| 门的加入把 **playable_rate 从 0.1037 抬到 0.8900（8.6×）** | — | 状态分布发生**巨变** |
| 圣水中位 1.50 → **4.36**（人类 6.43）、≥9 费 0 → **0.055**（人类 0.142）、出牌 38.2 → **34.70**（人类 22.8） | 三条轴**全部朝人类方向移动**，但**都没到** | 门确实诱导了攒费，只是不够 |

⇒ 该臂的**机制签名属于 6.4 第二分支（off-policy 状态分布不匹配）**，不属于第三分支。
根因可指认：**R00 的动作头是在「永不 STOP」的分布下训出来的**（`stop_when_playable = 0.0000`），
把它接到硬门下，其 cell/slot 输入分布是**训练时从未见过**的。
⇒ **零成本组合臂在原理上无法隔离「头耦合」这一个变量** —— 它同时改了状态分布。
**正确的结论是「组合臂不是有效的解耦检验」，而不是「诊断转向不是头耦合」。**

⇒ 下一步**不做**更多组合臂；直接把「独立 act 头」放进**联合训练**（Stage 2）—— 那才是唯一能在
训练分布下隔离该变量的做法。（本小节只登记该推断的失效，**不改** 6.3/6.4 判据文本，符合「只增不改历史结论」。）

## 7. 独立 act 头（把「出不出牌」从 6 类头里拆出来）：设计与判据

> **增补于 2026-09-22（C23 的直接下游）**。来源 = §6.8 的结论：零成本组合臂**原理上无法隔离「头耦合」**，
> 唯一路径是**联合训练**下一个独立的 act 头。本节在**跑之前**写死全部判据与口径（【R3】）。

### 7.0 ⚠️ 命名：本节的「独立 act 头」**不是** §3 的「Stage 2」

本仓已有占用者：§3（`:75-81`）的 **J9「Stage 2 多任务输出 / 回喂」**指的是**对手头 / belief 回喂**，
与 act 头**无关**，J9.x 判据**不适用**于本节。⇒ 本节一律写「**独立 act 头**」，**不叫 Stage 2**。
（`AGENTS.md` C23 行里的「Stage 2」当时指的就是本节这件事，属**措辞不规范**，此处更正。）

### 7.1 根因（写死，来自 C23 实测）

组合臂的门把 **`playable_rate` 从 0.1037 抬到 0.8900（8.6×）** ⇒ 动作头面对**训练时从未见过**的输入分布。
⇒ 「门 + 独立动作头」的**离线拼接**必然混淆两个变量；只有**联合训练**才能隔离。

### 7.2 架构设计（写死）

| 项 | 设计 | 理由（必须有） |
|---|---|---|
| `SUB_SPACE_DIM` | **新常量 = `K_MAX + 2` = 6**，专供 GRU 的 `sub_emb` one-hot 空间 | 把 **GRU 输入空间**与**头出维**解耦 ⇒ `sub_emb`(128,8) 与 `enc_fc`(128,2731) **保持可加载**，形状破坏面收缩到 `slot_head` + 新 `act_head` |
| `act_head` | `nn.Linear(hidden, 2)`，`0 = STOP`、`1 = ACT` | 二值门 |
| `slot_head` | 出维 **6 → `K_MAX + 1` = 5**（`0..3` 槽 + `4 = ABILITY`） | `ABILITY_IDX = K_MAX = 4` **数值不变** ⇒ 该处索引语义零迁移 |
| act 掩码 | `ACT` 合法 ⟺ 任一槽合法 ∨ `ability_legal`；`STOP` **恒合法** | 无牌可出 ⇒ 强制 STOP（不产生 NaN） |
| **不加新观测通道** | 保持 `grid/hand/scalar/plan/belief` 五路不变 | Stage 0 **已否证 H-B**（oracle 特征 ΔAUC **+0.0006/−0.010**）⇒ 无证据支持加输入 |

**前向形态（写死）** —— 两级嵌套，`act` 先决、`slot` 后决：

- **stop 帧**：`lp = log p₂(STOP)`（1 次抽样）
- **play 帧**：`lp = log p₂(ACT) + log p₅(槽 | ACT) + log p(cell | 槽) + log p₂(终止步 STOP)`（4 次抽样）

⚠️ **`evaluate` 的循环必须重构为嵌套**（每步先 act 后 slot），**不是**只改一个出维常量。
`evaluate` / `evaluate_batch` / `act` / `act_parallel` **四处必须同源**，否则 PPO `ratio ≠ 1`。

### 7.3 ★★ 判据可比性（本节最重要的一条；【R15】【R17】）

**数学事实（构造性，不是疗效）**：
- **play 帧（严格定理）**：解耦 `lp` 比共享头口径**多一项** `log p₂(ACT) ≤ 0`，且槽/落点项形式相同
  ⇒ 即使槽与落点分布完全一致，play 帧的 NLL 也被**结构性抬高** ≥ `−log p₂(ACT)`。
- **stop 帧（★ 只是倾向，不是定理 —— 2026-09-22 自我更正）**：解耦后 STOP 只需在 **2 类**里竞争
  （vs 共享头的 **6 类**），`p₂(STOP)` **倾向于**远大于 `p₆(STOP)` ⇒ stop NLL **倾向于**大幅变低。
  ⚠️ **但这不是恒等式**：`p₂` 与 `p₆` 是两套独立训练出的参数，不存在「一个 ≤ 另一个」的必然关系。
  （初稿把它写成「恒 ≤（边缘）」是**过度断言**，此处按【R10】更正。真正**必然**的只有 play 帧那一项。）

⇒ 无论哪一侧，**J8.2（`top1 ≥ 0.35` / `NLL ≤ 5.75`）与 J9.2（`ΔNLL ≤ 0.15`）都是共享头口径的阈值，
禁止直接照搬到解耦架构**（【R15】）。

**写死的对账口径 = 嵌入 6 类分布**：

```
p₆'(i)   = p₂(ACT) · p₅(i)      i = 0..4（4 槽 + ABILITY）
p₆'(STOP)= p₂(STOP)
```

**可比性证明（逐值）**：嵌入式 play 帧
`log p₆'(槽) + log p(cell) + log p₆'(终止 STOP)`
`= log[p₂(ACT)·p₅(槽)] + log p(cell) + log p₂(STOP)`
`= log p₂(ACT) + log p₅(槽) + log p(cell) + log p₂(STOP)` ≡ **解耦损失本身**。

⇒ 用 `p₆'` 计算 NLL/top1，**J8.2 原样可比**。
⚠️ 报告里**必须显式声明**这是「**嵌入口径**」（秩 1 约束下的联合分布），**不是采样口径**（实际采样是先 act 后 slot）。

**结论（据此关闭 C19/O13 的「下一刀 = 解耦」）**：R00↔R337 那条**单调帕累托前沿**
**不是头架构的性质，而是池构成的性质**（混入多少 save 帧）。
⇒ 下一刀**不该再动「头」**，而应动：
① **数据/标签分布**（save 帧到底在教什么 —— 注意 §7.11 已证 play-only 池里 `act_head`
从未见过「不出牌」当标签）；② **机制侧**（**O7** 让攒费值得做 / **O11** 承诺锁定修目标抖动）。

**拆头路线到此关闭**。`decoupled_act` 开关**保留**（默认关、零成本、旧路径逐位不变），
理由：它是目前**唯一被证明「不引入闭环状态漂移」**的架构改动（§7.10 的 `playable_rate`
0.1022 vs 0.1037），有二次利用价值；但**不再投入**。
