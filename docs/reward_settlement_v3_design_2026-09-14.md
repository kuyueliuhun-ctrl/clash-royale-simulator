# 奖励结算 v3 方案（2026-09-14）

> **触发**：用户要求"给我一个新版本结算方式的方案"。
> **本文件的性质**：**方案（设计稿）**，不是已落地改动。所有"该做/不该做"的判断都带**今天的实测读数**
> 与复算命令；凡未实测的标 **待确认**。
> **三份前置**：改动点清单与判据框架见 [`reward_settlement_prereg_2026-09-14.md`](reward_settlement_prereg_2026-09-14.md)；
> 核系数读数见 `scripts/probe_gae_kernel.py`；本文件的新读数由 `scripts/probe_credit_baseline.py` 复算。

## §0 摘要（先给结论，再给证据）

**v3 = 四层，其中两层"开"、两层"关并附恢复条件"：**

| 层 | 名称 | 状态 | 一句话理由（今天的实测） |
|---|---|---|---|
| **L0** | **可审计结算台账** | ✅ **立即做** | 今天所有关键判断都靠离线复算得出；把结构指标变成常规仪表，是唯一零风险且立刻有价值的改动 |
| **L1** | **结算字段化**（水平分量 / 变化分量分列） | ✅ **立即做** | 实测方差 **92.3% 在窗口间、7.7% 在窗口内** ⇒ 必须先让仪表说出"该动哪一块" |
| **L2** | **基线层**（闭式状态基线，替代死 critic） | ⛔ **本版关闭** | **四协议实测全部 ≤0**（最好 +0.0035，可在线口径 −0.06~−0.31），而学习型 critic 是常数 ⇒ 该层无可用实现 |
| **L3** | **段级结算**（段内共享优势） | ⛔ **本版不做** | 帧间自相关 **+0.987**、窗口内方差仅 **7.7%** ⇒ 段内**没有可去除的噪声**，预期收益 ≈0 |
| **L4** | **目标层修正**：势函数补齐 γ | ✅ 单变量实验 | 唯一**可证明正确**的改动（policy invariance），量级 +0.0012/帧（6%） |

**并且必须说清一件更重要的事**：本次实测把"换结算方式"的**可动空间压得很小**——
尾部收缩、段粒度、闭式基线**三条路今天全部被读数否掉**（§3）。剩下的 92.3% 是**跨窗口漂移**，
它只能由一个"能泛化到新 episode 的 baseline"来消，而那是 critic 的职责，critic 现在是常数。
⇒ **结算层不是当前瓶颈的首要候选**；证据指向**探索/数据覆盖**（§6）。

## §1 诊断：新版要修的是什么（全部有读数）

| # | 事实 | 读数 | 来源 |
|---|---|---|---|
| D1 | **critic 恒为常数** | `v` 在 29991 帧里**唯一值 = 1**，`std(v_within) = 0.000000`（mean +0.1425） | 本探针（第二个独立产物，与 `_probe_value_path` 的 600 帧读数一致） |
| D2 | **因此优势 ≈ 无基线的 MC 回报** | `δ_t = r_t + (γ−1)c = r_t − 0.000428` ⇒ V 项几乎不构成减法 | 本探针 + `probe_gae_kernel` §F |
| D3 | **优势方差** | `std(A)=14.68`、kurtosis **2.31**（尾部不厚） | 本探针 `--a-structure` |
| D4 | **尾部不是问题** | 顶部 1% 帧只占 `ΣA²` 的 **4.8%**（顶部 10% 占 36.8%） | 同上 |
| D5 | **优势在帧间几乎不变** | 局内 lag-1 自相关 **+0.987（中位 0.990）** | 同上 |
| D6 | **方差几乎全在"窗口之间"** | 128 帧窗口分解：**窗口内 7.7% / 窗口间 92.3%** | 同上 |
| D7 | **信用时间分辨粗** | `(γλ)^1=0.987` vs `(γλ)^9=0.889` ⇒ 8 帧差只换 9.9% 权重差；半衰期 53 帧 | `scripts/probe_gae_kernel.py` |
| D8 | **逐帧分数未被平均** | 核系数 k=0 恰 1.000000；守恒相对偏差 3.8e-10 | 同上 |

**诊断结论**：现在送进损失的 `A` 是"**在帧间几乎不变化（D5）、方差又几乎全在窗口间（D6）**"的量，
而它里面**没有任何状态相关的基线**（D1/D2）。⇒ 想靠改"结算的粒度/形状"（段、尾部、逐帧 vs 分段）
去显著改变信号，**可动的是那 7.7%**——而它同时被 D5 说明"几乎不可再压缩"。

## §2 v3 规格（逐层：公式 + 开关 + 默认值 + 兼容性）

> **兼容性总则（【红线 R2】）**：所有新字段默认值 = **旧行为逐位不变**；新能力只经 `TrainConfig`
> 显式开启（`value_norm="none"` + `vf_coef=0.5` + `adv_norm="batch"` = 逐位回旧）。

### L0｜可审计结算台账（`settlement_ledger`）

**做什么**：每个评估点把一次"结算快照"落盘成 json（不参与训练，纯记录）：

```
{
  "step": ..., "frames": ..., "episodes": ...,
  "reward_terms": {"crown":..., "tower":..., "edw":..., "unit":..., "terminal":...},   # Σ|·| 占比
  "gae": {"gamma": 0.997, "lambda": 0.99, "half_life_frames": 53.1},
  "advantage": {"mean":..., "std":..., "kurtosis":..., "lag1_autocorr":...,
                "var_within_win128_pct": 7.7, "var_between_win_pct": 92.3},
  "value": {"std_within": 0.0, "unique_ratio": 1/29991}
}
```
**开关**：`settlement_ledger: bool = False`（默认关，不影响训练）；`settlement_ledger_every: int = 1`
（每 N 个评估点落一次）。
**为什么优先做**：今天四个结论（尾部不厚 / 帧间自相关 0.99 / 窗口内 7.7% / critic 常数）
**全部来自离线复算**，而且其中两个**推翻了本仓既有文档的乐观假设**（§3）。
没有常备仪表，下一次结算改动还会重演"改了却动到 7.7% 那块"的白跑。

### L1｜结算字段化：把 A 拆成"水平 / 变化"两列

**做什么**：训练循环里对每次更新的批额外记录（**只记录，不改梯度**）：

```
A_lvl_t = mean_{t ∈ 窗口}(A_t)      # 窗口水平（实测承载 92.3% 方差）
A_dev_t = A_t − A_lvl_t             # 窗口内变化（7.7%）
```
**用途**：任何未来结算改动先声明"动哪一列"，再用 L0 的台账验收；避免再次出现
**用只影响 7.7% 的手段去解释 92.3% 的现象**（这类口径错配正是【R15/R16/R17】的家族）。
**开关**：随 L0 一起（`settlement_ledger=True` 时生效）。

### L2｜基线层 —— **本版关闭**（理由见 §3，附恢复条件）

**原设计（作废，仅存档）**：`credit_baseline: str = "none" | "linear_closed_form"`，
在每次更新内用闭式岭回归拟合 `Φ(s) → 回报`，`A ← A − b̂`，截距不受罚、按局留出、只减不缩放。

**为什么关闭**：**§3 的四协议实测**——闭式状态基线在**任何可在线实现**的口径下都**差于"什么都不做"**
（常数基线 EV_within = 0.0000）。

**恢复条件（写死，满足其一才重启该层）**：
1. `std(v_within)/std(y_within) > 0.10`（今天实测 = **0.000**）⇒ critic 恢复了局内活动，问题性质变了；或
2. 出现"可在线拟合成功"的证据：**因果滚动协议下 `EV_within > +0.05`**（今天最好 −0.199）；或
3. 奖励改为**事件稀疏型**（D6 的 92.3/7.7 结构倒转）后重测。

**开关预留**：字段与默认值先落地（`credit_baseline: str = "none"`），实现留空 —— 避免将来改动触及
`ppo.py` 的默认参数（【R2】共用入口红线）。

### L3｜段级结算 —— **本版不做**（附复活条件）

**原设计（存档）**：按决策事件（部署帧 / 相位切换 / 塔被拆 / 局终）切段，
段内奖励求和后做**段级 GAE**，再把段级优势**平均分给段内各帧**（semi-MDP/options 形式，
数学上是正确的宏动作策略梯度）。

**为什么不做的实测理由**：该设计的收益来自"去掉段内独立噪声"，但今天实测
**窗口内方差只占 7.7%、且帧间自相关 0.987** ⇒ 段内**几乎没有可去除的噪声**，
而代价（段内时间分辨率归零、与"无 BPTT"叠加后段内所有帧梯度方向完全一致）是实打实的。
**复活条件**：若将来（L2 恢复后或有其它改动）出现 `var_within_win128_pct > 30%` 或
`lag1_autocorr < 0.7`，重估本层。

### L4｜目标层修正：势函数补齐 γ（单变量实验）

**公式**（`rl/env_wrapper.py:252`）：

```
现在： reward += edw · [Φ(s') − Φ(s)]           # 缺 γ ⇒ 不满足 Ng et al. 1999 的 policy-invariance
v3 ： reward += edw · [γ·Φ(s') − Φ(s)]          # 恢复不变性
```
**量级**（已有判读）：额外偏置 `edw·(1−γ)·E[Φ'] ≈ +0.00122/帧 = 每帧奖励的 6.0%`，且近似为
**近状态常数偏移**（优势里大部分抵消）⇒ **预期收益小、但这是唯一可证明正确的改动**。
**开关**：`shaping_gamma_fix: bool = False`（默认关 ⇒ 逐位回旧）。
**为什么仍要做**：它是 v3 里唯一"不依赖任何未证实前提"的一块砖；且它把"目标层"与"信用层"
彻底分开（v3 的方法论主张：**目标只定义要最大化什么，方差削减一律走信用层**）。

### 尺度层｜**不动**（并加一道守卫）

保持 `adv_norm="scale"`（只除 std、不中心化）、`value_norm="running"`。
**新增守卫（文档级）**：整体缩放奖励 ×k 在 `scale` 分支下**是数学恒等操作**
（`probe_gae_kernel` 家族 + `ppo.py:224-226,392` 直接可读），因此**任何"把奖励调大/调小"的实验
一律不做**；若将来有人要做，必须先给出噪声地板。

## §3 ⛔ 本版最重要的一节：三条路被读数否掉

仪器：`scripts/probe_credit_baseline.py`（**只读、离线**，用固定 npz
`src/clasher_new/runs/_probe_cache_v2_stoch.npz`：**29991 帧 / 138 局**，`y` = GAE 回报、
`v` = 网络 V、`ep` = 局号；`A = y − v`）。

**协议定义**（差别是决定性的）：
- **OOF**：留一局拟合（用其它局训、预测该局）——**不可在线**（真训练只能看见过去）；
- **因果滚动**：只用**之前**的局拟合、预测当前局（**可在线**）；
- **窗口 128×8**：每 128 帧窗口用**其前面 1024 帧**拟合（**最接近训练循环的真实机制**）。

### 3.1 闭式状态基线：全部 ≤0（"什么都不做"= 0.0000）

| 特征基底 | OOF（不可在线，乐观上限） | 因果滚动（可在线） | 窗口 128×8（机制口径） | pred 幅度/`y_within` |
|---|---|---|---|---|
| 19 维手写状态特征 | −0.0995 | **−0.0567** | **+0.0344** | 0.429 |
| `fused` 2731（随机投影 512） | +0.0035 | −0.2508 | −0.1913 | 0.521 |
| `fused` 2731（全维） | (太慢，未测) | **−0.3121** | −0.1947 | 0.788 |
| `raw_obs` 8648（随机投影 1024） | (太慢，未测) | **−0.1992** | −0.1657 | 0.455 |
| **对照：本仓已验证实现**（`probe_value_ln.py --ladder v3`，跨局随机留出、**全维 raw_obs**、α 由 val 选） | **+0.1215** | — | — | — |
| 对照：网络 critic / 常数基线 | **0.0000** | 0.0000 | 0.0000 | — |
| 对照：oracle=y / 纯噪声特征 | +1.0000 / −0.003~−0.36 | — | — | — |

**读法（三条，缺一不可）**：
1. **"什么都不做"（常数基线）在局内口径下 = 0.0000**——因为 `EV_within` 按定义对局内中心化，
   常数的局内贡献恒为 0。所以**任何负值都意味着比不动更糟**。
2. **`+0.1215` 真实存在，但它只出现在"跨局随机留出"协议下**（训练集与测试集在时间上交织）。
   换成**可在线**的因果/窗口协议，同一 npz、同一特征族，读数掉到 **−0.17 ~ −0.31**。
   ⚠️ **口径限定（重要）**：这不否证【P3/H-LEARN】"信息在现有输入里"（那是**信息含量**命题），
   但**否证了把它当作"可实现的方差削减量"来用**——本仓若干文档正是这样用的。
   与【否证 X-16】（未播种 ⇒ 轨迹不可复现）叠加，这类"线性可读 +0.12~+0.30"的数字**不应再被当作工程量**。
3. **控制组全过**（oracle 1.0000、纯噪声 ≈0、打分打散 ≈0）⇒ 负结果不是实现 bug。
   注：`probe_value_ln` 自带阳性对照 +0.7579、时钟基线 0.0000、状态打散 ≈0，也全过。

### 3.2 尾部收缩：**无机制依据**

`A` 的 kurtosis 仅 **2.31**，顶部 1% 帧只占 `ΣA²` 的 **4.8%**、`Σ|A|` 的 2.7%。
⇒ 优势**不是**尖峰主导（终局 ±10 与皇冠事件被 GAE 的 53 帧核摊平了）。
"裁掉尾部降梯度方差"这类手段**能动的量 < 5%** ⇒ 本版**不做**。

### 3.3 段级结算：**无可去除的噪声**

帧间自相关 **+0.987（中位 0.990）**，128 帧窗口内方差仅 **7.7%**。
⇒ 段内共享优势**去掉的是一个本来就不大的量**，而代价是段内时间分辨率归零。
**若不做 3.1 与本节这两步实测，本方案会先改粒度（看起来最"像"结算改动）再白跑一轮 20k。**

## §5 判据（照 `reward_settlement_prereg_2026-09-14.md` §3 执行）

主判据**不用胜率**（【R5】`n=1` 分辨率不足；40 局 1σ≈0.078），用三层：

| 层 | 指标 | 仪器 | 说明 |
|---|---|---|---|
| 机制层 | 批内 EV（**更新前池化**）、`A_lvl/A_dev` 分解、`grad_cos` | 台账 + `judge_critic_inertia.py` | 阈值取**本次 run 前 100 次诊断更新**的 `中位 ± 3×MAD`（脚本复算，不照抄【R15】【R16】） |
| 行为层 | 全帧圣水≥6 占比、Xbow 出手率、部署前圣水中位、同路间隔 | `forensics_card_usage.py`（**本次逐位复现**：0.11% / 0.03% / 3.250 / 5.500 s） | **可作硬判据**（读数可复现） |
| 结构层 | 五项奖励占比 | `probe_reward_composition.py` | **只作描述**：实测散布 ±4~8pp 且同参数重跑不可复现（预注册 §7） |

**阳性对照**（必带）：`elixir_diff_weight: 0.5 → 0.0`（已知会改写结构层与部分行为读数）；
**阴性对照**：同配置重跑（量散布）。
**失败分支（写死）**：阳性对照不过 ⇒ 判 `INVALID`，不解释主判据；
机制层改善而行为层三项全无改善 ⇒ 判"未达行为可见阈值"，**不得**写成"修好了"（【R11】）。

## §6 结算之外：证据指向的真正瓶颈（本方案的诚实边界）

1. **策略几乎从不进入"攒费"状态**：全帧圣水 ≥6 仅 **0.11%**（100860 帧里 111 帧），
   而 6 费赢牌手段 Xbow 出手 **3/9806（0.03%）**；费 ≤3 的 5 张卡占出手 **95.47%**。
   ⇒ "攒费 → 打 Xbow"这条链在**数据上几乎是零覆盖** ⇒ on-policy 探索失败。
   **任何信用/结算改动对"从未访问过的状态"都无从作用**。
2. 这与 D6 互补：92.3% 的方差在窗口间 ⇒ 优势里的绝大部分是"局面水平差"，
   而**能让策略跨局面泛化的东西不是结算口径，是探索覆盖 + 有效的价值基线**。
3. 因此 v3 的**真实定位**是：**把结算层做成"可审计、可证伪、默认不动"**，
   并把算力让给门禁（S2）与探索侧实验；**不承诺** v3 能提升强度。

## §9 用户提案：**训练一个打分器给每帧打分**（2026-09-14 深夜，同日追加）

> **提案**：不再只用"场上圣水"这类简单项，而是**训练一个打分器**，按局面（场上卡牌 / 手内圣水 /
> 手内卡牌 / 敌方已知卡牌）给**每一个决策帧**打分，用它替代/补充现行的逐帧规则奖励。
>
> 本节给两件事：**① 该提案的数学分岔**（两种做法后果完全不同）；**② 可证伪那一半的实测**。

### 9.1 数学分岔：potential 形式 vs 直接打分形式

**做法 A（potential 形式，Ng et al. 1999）**：`r'_t = r_t + γ·S(s_{t+1}) − S(s_t)`

用真 `compute_gae` 验证（`scripts/probe_gae_kernel.py` §H）：

| 断言 | 实测 |
|---|---|
| 回报被**精确平移** `G' = G − S_t` | `max\|G' − (G − S_t)\| = 9.14e-07` ✅ |
| 优势层面不是"简单减 S"，多出 `(1/λ−1)·Σ(γλ)^j S_{t+j}` | `max\|A' − 公式\| = 4.23e-07` ✅（推导吻合） |

⇒ **收敛后 critic 会把 `S` 吸收进 `V`**（回报平移多少、V 就学多少）⇒ **最优解不变**。
⇒ 这正是 policy invariance：**打分器当 potential 教不了策略任何新东西**，只能改变学习过程
（等价于"给优势减一个状态基线"，即 L2 基线层）。
⇒ 而 L2 **今天已被实测否证**（§3.1：三种特征基底 × 三种协议，可在线口径 EV ≤ 0）。

**做法 B（直接打分）**：`r_t = S(s_t)` 或"每帧加一个 `S` 项" ⇒ **改变目标本身**：
策略会去"待在打分器喜欢的局面"而不管能不能赢（刷分/僵持），且**分数的来源**必须另有答案。

### 9.2 分数从哪来？（三条来源，全都被堵）

| 来源 | 等于什么 | 状态 |
|---|---|---|
| 博弈结果（胜负/回报） | **就是 critic（价值函数）** | 已关闭：四代架构【X3】、100k 加量【X4】、critic 侧程序【X6】；今天实测 29991 帧里 `v` **唯一值 = 1** |
| 现行规则奖励 | 自己监督自己 | **循环**，无增量 |
| 外部教师（人类示范 / 搜索） | 模仿学习 / RLHF 路线 | 本仓**没有**教师；`BeliefPlanner` 只产出 PlanToken，不是策略（`replay_behavior_forensics` §9） |

### 9.3 实测（可证伪那一半）：非线性打分器在**可在线口径**下 EV = −0.22

仪器 `scripts/probe_scorer_offline.py`（只读、离线）。协议 = **前向链式分块 CV**：
把 138 局按时间切 5 块，第 i 折**只用它之前的局训练、预测当前块**（训练循环唯一可能的姿势）。

| 预测器（同折同协议，n=24339 帧） | `EV_within` |
|---|---|
| 常数基线（"什么都不做"） | **+0.0000** |
| 线性岭回归（α=1e4） | −0.0936 |
| **非线性打分器 MLP（512→64→64→1，ReLU，Adam+早停）** | **−0.2225** |
| 阴性对照：标签打散 MLP | +0.0023（≈0 ✅） |
| **阳性对照：同块内拟合（in-sample）** | **+0.2710** ✅ |

**读法**：`EV_within ≤ 0` 意味着**比"什么都不做"更糟**；MLP **比线性还差**（−0.22 vs −0.09）；
而阳性对照 **+0.2710** 证明**打分器有足够容量拟合该目标** ⇒ **瓶颈不是容量，是"状态→回报"的
在线可学性**（与 §3.1 的因果/窗口结论一致，此处用的是最强的一档模型）。

### 9.4 输入侧：用户列的四类输入**已经在网络里**

| 提案输入 | 现状 |
|---|---|
| 手内圣水 | `observe()["elixir"]`（`rl/observation.py`）→ 直接进网络 |
| 手内卡牌 | `observe()["hand"]`（5 维）+ `next_card` |
| 场上卡牌 | `observe()["grid"]`（18×32×15 通道，逐格实体属性） |
| **敌方已知卡牌/圣水** | `belief.encode()` → **563 维 belief token**（由 `hidden_labels` 的**特权标签**——对手真实手牌/牌序/圣水——监督训练）→ 进网络 |

⇒ **打分器在输入侧没有增量**。且"敌方信息能带来多少"已有实测上限：
【P3′】特权/oracle 通道对局内回报可预测性的增量 = **+1.1pp**、belief token = **+0.4pp**。

### 9.5 结论与唯一可行变体

**结论**：按"用更丰富的局面信息给每帧打分"的原意做——**不行**。
① 输入无增量（9.4）；② potential 形式不改最优解（9.1）；③ 直接打分形式没有合法分数来源（9.2）；
④ 唯一可证伪的那一半实测为负（9.3，且容量对照证明不是容量问题）。

**唯一值得试的变体（建设性）**：把打分器当**教师**而不当奖励 ——
**离线**训练（标签来自搜索/规划器/示范等**外部**信息），产物用于 **BC 预热 / 课程 / 初始化**，
**不进入奖励、不进入损失以外的任何量**。依据：本仓历史读数【C8】"同网络**监督微调** test EV
可到 +0.22~+0.29，而 PPO 联合训练 ≤0" —— 说明这条线**离线能学、在线学不到**。
⚠️ 但【C8】已被【X6】限定，且今天证明 +0.12~0.30 类数字是非因果划分下的读数 ⇒
**该变体须重新预注册，且不承诺收益**；前置门禁（`§6` S2 手写专家对照）仍应先做。

**红线提示**：【R7】分数尺度必须单源；【R11】不引入 LLM 实时决策；【R12】**能算的不许让网络猜**
（提案里列的四类输入全部是确定性可算量 ⇒ 正确做法是特征注入，本仓已做）；
【R3】引入"第二个网络 + 它自己的训练循环"本身就是新失败面，不得与其它改动同时上。
