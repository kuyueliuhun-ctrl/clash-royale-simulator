日期：2026-09-18 ｜ 阶段：**分析（不实现、不训练、不预注册）**
用户提问：**「我们能否让模型初始通过掷骰子来决定出不出牌？并且让模型可选是否用骰子决定出不出牌？」**

## 0. 结论先行

1. **能实现，但骰子的作用域只有 ~10% 的决策帧**：实测 **88.3%~90.6% 的帧里一个合法项都没有**（掩码只剩 STOP，
   被迫"不出牌"），骰子在这些帧上**没有任何作用点**；而在**有牌可出**的那 ~10% 帧上，模型**本来就 91%~94% 选择出牌**
   （P(不出牌)=0.058~0.090）。⇒ 骰子的全部效果就是把 pass 概率从 ~6–9% 抬到 ~50%，
   **全帧覆盖率从 ~0.5–1.8% 提到 ~5%**（【推论·未验证】，算术见 §3.0）。
2. **i.i.d. 骰子在时域上不可能造出"攒费"**：攒费需要**连续 K(≈10–25) 帧"有牌可出却选择不出"**，
   这是**与状态相关的持续决策**；i.i.d. 骰子给的是 **0.5^K**（K=10 → 1e-3、K=25 → 3e-8）的**与状态无关的固定预算**。
   ⇒ **骰子必须带"时长/承诺"（option）才有时域**（§3 V4），单帧掷骰是恒等变换级别的干预。
3. **「让模型可选是否用骰子」若做成可学元门，大概率退化解**：学成"永远用"或"永远不用"都使这个选项失效；
   且**骰子帧对 slot_head 的 play/pass 维度梯度恒为 0**（动作不是由策略网络采样决定的，与掩码-损失恒等式同型）
   ⇒ **骰子只能当"数据生成器"（喂 critic / 造 off-policy 样本），不能教会策略"该攒费"**。
4. **先做零成本探针、再决定实现**：在现有 14×40 局录像上直接数「有牌可出却不出牌」的帧数与其后 20 s 的圣水/塔血轨迹
   （§6）。**同时老老实实说：机制侧那条路（O7：Xbow 进不了 `save_ace`/`setup_wait`、本卡组攒费偏置是死代码，见 §2.4）
   比骰子更接近病根，成本也更低。** 骰子是"加探索"，而 §2.4 显示**机制里根本没有"攒费"这个意图**——
   探索再多，也没有任何东西告诉模型"攒费是好的"。

### 2.2 三条结构性事实（后面全部论证都建立在它们上面）

- **事实 A：骰子对 ~90% 的帧无效。** 被迫帧**全部因为"买不起"**（`slot_mask` 裸算对账：775/775、900/900、1101/1101），

- **事实 B：可动帧上模型只愿意 pass 6%~9%。** 且**只有一张牌买得起**时也只 pass 6%~9% ⇒
  **"有牌却选择不出"这件事，当前策略 100k 步里几乎没做过**（全帧口径 ≈0.5%~1.8%）。
- **事实 C：机制侧只有"推你出牌"的偏置，没有"让你攒费"的偏置。**（**我回源码逐条核实**，见 §2.4）

## 3. 四个候选设计（逐一给：触及帧 / 梯度路径 / 能否产生时域 / 可falsify预测）

### 3.0 共同前提与覆盖率算术

- 「骰子可作用帧」= 第 0 步掩码里**同时**存在 STOP 与 ≥1 个非 STOP 合法项 = 实测的"可动帧"。
- 覆盖率（全帧口径）= P(可动) × P(选 STOP | 可动)：
  A_et `0.108 × 0.090 ≈ 0.97%`、B_ctrl `0.094 × 0.058 ≈ 0.54%`、未训练 `0.117 × 0.153 ≈ 1.79%`。
- 骰子（p=0.5）把可动帧的 pass 从 ~6–9% 抬到 ~50% ⇒ 覆盖率抬到 **≈5%**（相对放大 **3.3×~8.6×**）。

### V1 · i.i.d. 单帧骰子（骰子说 pass 就 pass，与网络无关）

| 项 | 分析 |
|---|---|
| 触及帧 | 只有可动帧（~10%）；被迫帧无效 |
| 梯度路径 | **无**可学参数；但**破坏重放一致性**：rollout 记录的 `old_logprob = log π(a\|s)` 与实际执行的行为策略 `π_act = 0.5·1[STOP] + 0.5·π(·\|非STOP)` 不同分布 ⇒ PPO 的 `ratio = exp(lp_new − old)` 与信用分配**系统性错位**（【推论·未验证】） |
| 时域 | **不能**：连段长度 ~ 几何分布，`P(≥K) = 0.5^K`，K=10 → **0.1%**、K=15 → **0.003%**、K=25 → **3×10⁻⁸** |
| 可falsify | 开骰子后 ② 层 P(不出牌) 应 ≈ `0.09 + 0.5·(1−0.09) ≈ 0.55`；空 bundle 率应从 ~91% 升到 ~95%。**若实测没动 ⇒ 骰子没接上（不是"没效果"）** |
| 判决 | **不建议**：无参数、破坏 PPO 一致性、时域固定 0.5^K |

### V2 · 拿网络自己的 P(STOP) 当骰子

就是现状的 `Categorical.sample()`。**零信息**（只是把观测口径换个名字）。
可falsify：应与现状**逐位不可区分**（同 RNG 流下全实体状态 digest 相同）；若 digest 变了，说明实现里偷偷改了别的（【R13】）。

### V3 · 混合臂 `π_act(STOP) = (1−λ)·π(STOP|s) + λ·μ`（「可选是否用骰子」的**标准形态**）

- **λ 为常数**：触及帧同上；`∂/∂λ = (μ − π_STOP) > 0` ⇒ λ **有梯度**、方向是把 STOP 推向 μ；
  但 λ 与状态无关 ⇒ 时域上限仍是 `μ^K`（同样的固定预算），且会把可动帧的强制出牌率从 91% 降到 45%
  ⇒ **期望花费速率上升、圣水更低**，与"攒费"**方向相反**（【推论·未验证】）。
- **λ = λ(s)（网络输出 = 可学元门）**：梯度完整、形状上是"策略自己选择要不要随机化"；
  **退化解风险**：λ→0（骰子被梯度否决）或 λ→1（策略放弃在 pass 维度上做决策）都让选项失效。
  【未定】它能否学到**状态相关**的非退化解（例如"只在手牌有 Xbow 时提高 pass 探索"）——必须由实验回答，**不能由设计意图声称**。
- **合规性**：这是四者里**唯一**能同时满足【R2】（默认 `λ≡0` 时逐位回旧）与"模型可选"的形式。
- 可falsify：① 训练后 `λ(s)` 若方差 ≈0 ⇒ 只学到"整体抬/降 STOP"，没学到状态结构；
  ② 若观察到的长 pass 连段频率**远超** `μ^K` 上限 ⇒ "骰子无信息"的判断被推翻。

### V4 · **option 骰子（带时长/承诺）** —— 唯一有时域能力的形态

形式：`u ~ Bernoulli(p)` 决定"是否进入一个持续 K 帧的不出牌承诺"（K 可为常数、可采样、也可由策略输出）。
- 触及帧：**全部帧**（承诺期内即使有牌也不出——这正是攒费需要的行为）。
- 时域：**能**（K 由机制给出，可拉到 10~25 帧以上）。这才是"攒费"所需的量级
  （从圣水中位 1.5 攒到 Xbow 的 6，按引擎回费约 0.26~0.36 圣水/s ⇒ **需要 ~12~17 s ≈ 25~35 决策帧**；
  【未定】实际回费速率我只在一条调试轨迹上量到 ≈0.255/s，**未做标定**）。
- 代价：语义上已经是**动作空间的宏动作**（不是"加噪声"），须【R6】`--fresh`、须预注册、须录像 schema 记录承诺期。
- 可falsify：承诺期内的圣水曲线应呈现**单调爬升且在承诺结束时 ≥ 手牌最贵可出牌的费**；若爬升速率远低 ⇒ 承诺被别处打断（掩码/门禁）。

### 「模型可选是否用骰子」的三种语义（**不要混为一谈**）

| 语义 | 实现 | 风险/成本 |
|---|---|---|
| (a) **可学元门**（每帧选"用/不用骰子"） | 新增一个二元 head（或并入 slot head 的一个新选项）⇒ **架构变更** ⇒ 【R6】必须 `--fresh`；旧 ckpt 不可续训 | 退化解；与策略自身的 pass 概率**共线不可辨识** |
| (b) **课程退火**（初始用骰子，之后逐步关掉） | 训练前 S 步/前 X% 用骰子，之后 `p→0`；**这最贴用户"初始用骰子"的字面** | 不改变架构（不需 `--fresh` 也能做，但语义变了仍须显式开关）；退火曲线须预注册 |
| (c) **option 内嵌**（"用骰子"= 换一个 K 帧承诺） | 即 V4 | 动作语义变更，成本最高 |

## 4. 「初始」的两种读法都要回答（**骰子的原始动机在本 ckpt 上不成立**）

| 读法 | 读数 | 含义 |
|---|---|---|
| **网络初始**（未训练） | 开局帧 P(不出牌) = **0.081**、可动帧 **0.153** | 与已训练的 0.052 / 0.090 **同量级**：随机初始化**并不"爱不出牌"** |
| **对局初始**（开局帧） | A_et **0.052** / B_ctrl **0.034**，`argmax=STOP` **0/30** | 开局**从未**以"不出牌"为最优动作 |

- 初始化时已经把 STOP logit 压低（`stop_logit_bias=-1.0`，`follower.py:253-255`，注释写明目的正是打破
  「开局双双 STOP → 无事件 → 无梯度」的自锁）；
- **100k 步训练后这个偏置几乎没动**：`-1.000 → -0.9711`（A_et）/ `-0.9807`（B_ctrl）。
  ⇒ **"加骰子来修冷启动自锁"这个动机，已经被 `stop_logit_bias` 解决掉了**；
  同时这也说明：**现有数据里没有足以推动 STOP 偏置的梯度**（它是个可学参数，100k 步只动了 0.03）。
  【推论·未验证】骰子能做的只是"造数据"——而 §3.0 的 0.5^K 算术说明造数据效率受时域限制。

## 5. 与既有红线的冲突清单（逐条："要合规必须怎么做"）

| 红线 | 本设计触发点 | 合规做法 |
|---|---|---|
| **R2 训练语义兼容** | 骰子进 `act()` 会改采样分布 ⇒ 所有走 `act` 的路径默认行为变化 | 做成 `TrainConfig` 显式开关、**默认关**；**默认关必须逐位回旧**，配黄金值 digest 回归（比照 `engagement_trade` 默认 0.0 的做法） |
| **R3 单变量 + 预注册** | "骰子"与"可选开关"天然是两个变量 | 一次只改一个；判据**跑前写死**（含失败分支） |
| **R5 n=1/臂** | 极易把小差异读成效应（同配置重跑单点差 **0.60**，§11.13.11） | 判据**不许**用胜率/奖励；只用机制层 + 行为层；n=1 时**只读方向** |
| **R6 架构变更 `--fresh`** | 元门/新 head = 架构变更 | **必须 `--fresh`**；显式 `plan_dim=58`/`belief_dim=563` 语义不变但须核对 |
| **R8 回归 + 跨局边界** | 骰子状态/承诺期若跨局不重置 = 9j 类事故 | 每个修复配回归；**必须跨局边界**；触及共享底层时按【R19】跑全量 |
| **R11 明确不做** | 骰子是"动作语义重构"的入口；也容易被顺手当调参旋钮 | 不改变槽位/掩码语义；不得因"读数没动"写"修好了" |
| **R12 EBK** | 圣水/手牌费/下一张**都是确定性可算量** | 这些量应走**特征注入**；骰子若要留，只能是**探索侧**机制，且必须报出"比特征注入多给了什么" |
| **R13 掩码位图对账** | "把不出牌重定义成骰子结果"极易被写成改掩码 | 骰子**只碰分布层**；不改 `slot_mask`/`legal_cells`/`validate_bundle`；跑 `scripts/_mask_diff_snapshot.py`，**128 张逐位全等** |
| **R16 阈值标定** | 极易用单次读数定阈值 | 阈值须建立在**已量出的 run 间散布**上，或改用**比值/配对**判据 |
| **R17 分子/分母同超参 + 包含关系逐位验证** | "骰子作用帧 ⊆ 全部帧"是包含关系 | 分子分母**同一 run/同一批帧**；`np.array_equal` 逐位验证包含；两套口径时只采信方向一致的部分 |
| **R7 尺度单常量源** | 若把骰子概率写进多处 | 概率/时长常量**单一来源** + 对账 selftest |

### 5.3 ★ 最大的工程坑：**PPO 重放一致性**（也是必须做的接线成本）

`act()` 采样与 `evaluate()`/`evaluate_batch()` 重放**必须同分布**（`_plan_biases` docstring 的原话就是为此）。
因此骰子**不能**在重放时重新掷一次，**必须**：
① 采样时把骰子结果（与该帧的 `logprob` 口径）**写进 rollout**（扩 `masks` 序列或新增通道）；
② `evaluate*` 按**记录值**复现（骰子帧的 play/pass 部分按记录处理，不得让网络重新决定）；
③ 若同时扩录像记录 ⇒ **又一次录像 schema 变更**（本项目已到 schema 5，每次变更都要迁移/兼容测试）。
**做不到①②，就会静默破坏 PPO 的 `ratio` 一致性**（比"骰子没效果"更糟：是污染训练）。

## 6. 判据设计（**若**将来预注册，必须写死的项）

**主判据（行为层，这是唯一有分辨率的地方）**
1. **可动帧 P(不出牌)**（现 0.058~0.090）；
2. **pass-with-option 覆盖率**（现 ~0.54%~1.79% 全帧）；
3. 全帧圣水 ≥6 占比（现 0.52% / 0.05%）；
4. 部署前圣水中位（现 3.25 / 3.286）；
5. Xbow 出手率（S1 口径：POOLED 段次数 ÷ 总打出，现 5/8769、1/8370）。

**不变量（阴性对照，跑前写死）**
6. **被迫帧占比不得变化**（现 88.3%~90.6%）：若变了 ⇒ 实现把骰子加到了不该加的地方（掩码/闸门被污染）；
7. **元门使用率**必须既不是 0 也不是 1（否则是退化解，选项被学到失效）；
8. `--mask-diff` 128 张逐位全等；默认关时 digest 与基线逐字相同。

**阳性对照（本项目血的教训：没有它，"测不出"不能读成"无效"）**
用 S1 的 `token_xbow` 型**手写攒费专家**跑同一套行为层读数（已知能打出 4.69% Xbow）
⇒ 证明"行为层能看见攒费"；否则行为层的零变化无法解释。

**失败分支（预注册时写死）**
- ① 行为层**没动** ⇒ 骰子没接上 / 被掩码吃掉（不是"没效果"）；
- ② 行为层动了但机制层与胜率层**不可分辨** ⇒ 记「本分辨率下无结论」（【R5】），**不得**写疗效；
- ③ 元门学成常量（0 或 1）⇒ 记录为**有信息量的负结果**：在该状态分布下随机化没有期望收益。

## 7. 零成本前置探针（**建议先做这个，再决定是否实现**）

全部在**现有录像**上做，不训练、不改奖励、不改判定：

1. **样本量盘点**：14 个评估点 × 40 局录像里，「有合法选项却选择不出牌」的帧一共多少？
   （按 §3.0 的 ~1% 全帧口径估：若录像总帧数在 10⁵ 量级，则**只有数百帧**。）
2. **这些帧之后发生了什么**：直接用**同一条录像的后续帧**读——圣水爬升轨迹、塔血变化、
   后续是否出现 Xbow/6 费动作。这能量出"当前策略的 pass 分支长什么样"（**只有 pass 分支可观测**，
   "若当时出牌会怎样"没有反事实，**不得**假装能算）。
3. **K 的敏感性**：把 K 从 8 扫到 40，报"承诺期内圣水能否达到手牌最贵可出牌的费"的比例
   ⇒ 直接给出**option 骰子需要多长的承诺才可能有用**。
4. 顺带把 §3.0 的覆盖率算术**用真实录像复算一遍**（现在是探针口径，n=1 seed、4 局）。

**判定用法**：若探针显示"要凑够有统计意义的 pass-with-option 样本需要 >10⁵ 帧 ⇒ 骰子这条路的样本效率不可接受"，
则应把预算投到 §8 的替代手段上（尤其机制侧）。

## 9. 未定与不确定（【R10】）

1. **回费速率未标定**：我只在一条调试轨迹上量到 ≈0.255 圣水/s（0.18 → 3.11，11.5 s），
   据此把"攒到 6 费"估成 ~12~17 s。**引擎标准值 1/2.8s ≈ 0.357**。两个数差 ~40% ⇒ §3 V4 的 K 估计区间应写成 **10~25 帧**。
   **✅ 2026-09-18 晚已标定（本条不再是未定）**：用 `scripts/pass_streak_audit.py` 在**两臂 155,866 帧**上按
   「本帧没花钱的相邻帧差分」测得 **0.1786 圣水/帧 = 0.3571 圣水/s**（与引擎标准一致），
   ⇒ 从 0 攒到 Xbow(6 费) 需 **34 帧 = 16.8 s**。原始读数见
   [`docs/elixir_saving_audit_2026-09-18.md`](elixir_saving_audit_2026-09-18.md) §2。
2. **"可动帧"是否该按"有合法**出牌**项"还是"有合法**非 STOP** 项"定义**：本分析用后者（含 ABILITY）。
   含 ABILITY 的帧极少（实测开局 ability_legal 全 0），但**未逐帧分类**。
3. **元门能否学到非退化解**：完全【未定】，必须实验回答。
4. **骰子对"防对手利用"是否有价值**：本环境是自对弈/冻结副本，单边随机化会破坏自对弈对称性；
   "混合策略防利用"的收益**未量化**，也**未验证**对手有能力拟合我们的 pass 规律。
5. **本次分析的样本基础**：§2 的概率来自 **n=1 seed、各 4 局全程 + 30 局开局采样**（描述性读数），
   §3.0 的覆盖率算术因此只有**量级**意义（②层两次跑就差 0.080 vs 0.090）。

## 10. 建议（一句话）

**骰子可以做，但它解决的问题（冷启动自锁）已经被 `stop_logit_bias` 解决；
它想解决的问题（攒费）需要的是"时域"，而 i.i.d. 骰子的 0.5^K 给不了时域。**
⇒ 先做 §7 的零成本探针与 §8 里零成本的对照（`ent_coef`/温度），**同时把 O7（机制侧）当成主路**；
真要做骰子，**只做 V4（option 带时长）+ 语义(b) 课程退火**，并按 §5.3 把重放一致性接对。
