# 题库预训练可行性评估（2026-09-09）

> 结论先行：**技术管线可行（POC 全链已跑通），但"预训练"定位降级为"数据集工具"更符合收益预期。**
> 引擎判卷 + 现有 checkpoint 答题的实证显示：题库能客观量化当前模型的战术短板
>（EV gap ≈ 1400-2000 等效塔伤/题，top-8 命中率仅 33%），这是当前任何评估口径都给不出的数字；
> 但判卷口径的两个根本性缺口（"等价解"问题与"3 分支盘面"问题）意味着它作为 IL 标签源
> 的质量上限有限。建议按 §5 的路线走：**先当评估/回归工具用（零风险、立即可用），
> 再当数据集用（需先修 §4 的两个口径缺口）。**

POC 脚本：`scripts/question_bank_poc.py`（生成→判卷→对账→checkpoint 答题全链，
`--quiz` 开关切 checkpoint 答题段）。本文所有数字为该脚本实测输出。

---

## 1. 提案与评估范围

用户提案（sess_b383ac6a）：用"题库"（如"3 费刺客完美解 7 费超级骑士"）做预训练。
细化口径：不手写内容——程序生成题目、程序推理得答案：从威胁牌被下出起，
枚举防守方所有手牌的所有合法落点，沿威胁行进线逐位置切片，
产出「威胁卡 × 行进位置 → 最优反制(卡+落点+收益)」的**引擎标定表**。

评估要回答的三个问题：
1. 管线是否跑得通、成本多少？（生成→判卷→对账→评测）
2. 判卷答案是否可信？（"完美解"是否与引擎 EV 一致）
3. 现有模型离答案多远？（评估工具价值的直接证据）

## 2. POC 实测结果

### 2.1 生成与判卷（3 道题，81s）

每题：威胁牌（Giant/HogRider/Minions）从桥头行进到切片位置 → 枚举防守方
手牌 4 张 × 粗网格（每 2 格）合法落点 ≈180 候选 → 逐候选
`simulate_exchange(defender="none")` 引擎结算 → 按训练奖励汇率计分
（塔损 0.0012/血 + 敌军伤害 0.0005/血 + 反打塔伤 0.0010/血 − 费用 0.5/费）。

| 题 | oracle 答案 | score | 不动手基线塔损 | 结算耗时 |
|---|---|---|---|---|
| Giant 已过桥 y=14 | MiniPekka 贴身 | +4.374 | 2277 | 37s/182 候选 |
| HogRider 桥头 y=15 | Skeletons 群殴 | +2.256 | 1590 | 27s/178 候选 |
| Minions 过河 y=15 | Musketeer 击杀 | −0.570 | 214 | 16s/182 候选 |

### 2.2 checkpoint 答题（现有模型 vs oracle）

把构造盘面直接灌进 `FollowerPolicy.act`（复用 `RLEnv.observe` +
`BeliefInference` + `BeliefPlanner.plan`，与训练/评测同链路），取模型答案
重新过引擎判卷得 EV，与 oracle 做差：

| 模型 | ⌀ EV gap | top-8 命中 | 最差题 |
|---|---|---|---|
| economy_100k_v1_ungated（9j 时代） | +1.682（≈1400 等效塔伤） | 1/3 | Giant 题：答 Knight 而非 MiniPekka，gap +3.96 |
| main_ckpt_32000（旧底座） | +2.475（≈2060 等效塔伤） | 1/3 | Giant 题：答 Arrows 空砸，gap +4.38 |

**这组数字本身就是评估工具价值的证明**：9j 的 forensics 只能说"落点几何不对"，
题库直接量出"在 Giant 过桥 y=14 这一格，模型的选择比最优差 3300 等效塔伤"，
且可跨 checkpoint 回归比较（32000→100k 的进步可量化）。

### 2.3 已知解对账：1 PASS + 2"FAIL"，但 FAIL 有信息量

- **MiniPekka 贴 Giant ✓**：教科书解从引擎结算自然涌现（score 领先第二名同为
  MiniPekka 平位），"贴身打满输出"的几何被 EV 汇率自动选中——判卷器通过。
- **Cannon 拉 Hog ✗（输给 Skeletons 群殴）**：取证后确认**不是管线错误，是
  两个口径问题的叠加**，见 §4。
- **Arrows 换 Minions ✗（-0.898 vs Musketeer -0.570）**：同样见 §4——
  这里引擎判卷其实**更合理**：Arrows 只保 214 塔血且要 3 费，Musketeer 留个
  火枪手还能反打。教科书说"换掉"，EV 说"不亏就行、留兵更赚"。**判卷器与
  教科书分歧 ≠ 判卷器错**，但暴露了单选题形式本身的问题。

## 3. 成本外推（实测 → 5 万题）

POC 实测：粗网格（2 格间距）单题 180 候选 ≈ 16-37s（威胁血量越高越慢，
结算视界越长越慢）。注意这是**单题全候选**；正式生成器加两段评分
（短视界粗筛→top-20 全量）可再降 3-5×。

| 规模 | 实测口径 | 两段评分后 |
|---|---|---|
| 单题 | 16-37s | 4-10s |
| 1k 题 | 4-10 CPU 时 | 1-3 CPU 时 |
| 5 万题 | 220-500 CPU 时 | 55-140 CPU 时 |

16 worker 并行（P0 掩码优化后 spawn worker 实测顺畅，economy_10d 16 局 54s）
→ **5 万题一次离线生成 ≈ 1-2 天**。存"生成配方"（种子+摆放+等级+圣水）
而非 pickle 快照，可跨引擎版本重生成；单题落盘 JSON（题面+top-k 分布+判卷上下文）。

维度外推（每项独立乘数）：威胁卡 4 种来源 → ×4；位置切片 5 档 → ×5；
防守圣水档 3 档 → ×3；= 5 万题只覆盖 **4 威胁 × 5 位置 × 3 圣水** 的组合空间。
要覆盖 148 卡池 × 全位置 → 千万题级，不现实。**这直接决定了 §5 的定位结论。**

## 4. 判卷口径的两个根本缺口（决定定位）

### 缺口 1：等价解问题——top-1 不是"标准答案"

引擎判卷给出的是**连续 EV 分布**而非离散对错。同分平位大量存在（Giant 题
top-6 全是 MiniPekka，分数精确相同）；更关键的是**跨卡等价**：Skeletons(1费)
与 Cannon(6费) 都能 100% 拦下 Hog（POC 实测 saved 同为 1590），EV 差全在
"少花 5 费"——教科书"Cannon 拉扯"的优势（拉扯走位、争取时间、被法术反制后
仍有建筑输出）在这些 EV 项里**不可见**。

对 IL 预训练的影响：如果把 top-1 当标签（masked CE / BC），模型学到的会是
"小骷髅堆桥头"这类 **script-defender-blind 的偷费解**（判卷用的是
defender=none 口径），正是 AGENTS 反复警告的判卷器偏差（AlphaStar 教训：
script defender 会教出反脚本习惯）。缓解手段（存 top-k 分布、多源 defender
判卷取交集）能降权但不消除——**"3 费刺客完美解 7 费超级骑士"这种题的
"完美"在引擎 EV 里根本不存在唯一解**。

### 缺口 2：3 分支盘面问题——单卡反制题只覆盖盘面空间的极小角

真实对局的战术决策是三选一：**反制 / 换家 / 憋费等**。POC 的单卡题只能表达
"反制"分支；"这波不防、换家更赚"和"憋 2 费等下一张再防"需要**序列级判卷**
（威胁结算→我方反打→对手再响应的 2-3 层推演），每题成本 ×10 起，
且对手模型偏差问题随序列长度放大。单帧题库**结构性教不了**这三个分支的
选择能力——这正是 9j 诊断出的"模型只会见招拆招、不会判断这招值不值得接"的病理。

### 判卷可信度的正面证据

值得记录：**引擎对"只打建筑"单位的行为处理是正确的**
（battle.py:628-647 `target_only_buildings` 部队不进 troop_targets，实测
HogRider 不被 Skeletons 拉仇恨、Arrows@(1,13) 砸 Giant 实际救塔为 0——
32k 模型那笔 -0.009 的答案被引擎判卷如实打了差分，不冤枉）。
判卷器本身无作弊空间，缺口全在口径设计而非引擎。

## 5. 结论与建议路线

**定位建议：题库 = 评估/回归工具（立即可用）+ 条件威胁评估头的数据集生成器
（修完口径缺口后）+ IL 预训练底座（降级为最后一步，且只做 top-k 蒸馏不做
top-1 模仿）。**

分三步走，每步独立可停：

1. **第 1 步（零风险，建议立即做）：题库先当评估工具**——扩到 50-100 题
   （4 威胁 × 5 位置 × 多卡组），固定成 `scripts/question_bank_eval.py`，
   每次训练 run 结束跑一遍，产出 per-checkpoint 的 EV gap 曲线。
   这解决当前评估体系的真空：winrate 平台期下（vs baseline0 0.42 不动），
   战术质量的**真实爬坡**（9j→9k_ft 的防守行为链改善）没有任何数字能体现，
   题库 EV gap 是第一个可回归的战术能力指标。
   工程量：POC 已跑通，扩规模只是参数化循环 + 并行，约半天。

2. **第 2 步（条件性）：作为交互评估头的数据集**——AGENTS 的条件威胁评估
   路线（threat_calc → simulate_exchange → 交互评估头）正缺训练数据，
   题库的 (状态, 候选, EV) 三元组就是现成标签。**这一步不需要解决
   "top-1 唯一性"问题**（评估头学的是 EV 分布，不是模仿最优解），
   与缺口 1 兼容。工程量：数据落盘格式 + 加载器，约 1-2 天。

3. **第 3 步（可选，收益最不确定）：IL 预训练**——只做 masked CE on top-k
   分布（防熵坍缩），且**必须先补两件事**：①多源 defender 判卷
   （SelfDefenderPolicy + 历史 checkpoint 采样）消除 script-blind 解；
   ②换家/憋费分支至少以"null 选项 EV"进入标签分布（判卷已含 null 基线，
   但需要按 §4 缺口 2 把它放进动作空间）。即便如此，缺 1 的等价解问题
   仍在，预期收益 = "省掉部分 hint 工程"，**不是跳过 RL 训练量瓶颈**。

**不建议的路径**：直接上 5 万题 BC 预训练。理由：①缺口 1+2 未解，学到的
策略会偏向 script-blind 偷费解 + 只会单卡接招；②成本 1-2 天 CPU 换来的
训练数据覆盖不了 148 卡池的组合空间（§3 末段），泛化靠的还是交互评估头
（第 2 步）；③FirstLight 的教训（固定 IL 高胜率歪路）——IL 底座的价值
在"见过多少样的局面"，而题库天然只覆盖"威胁已过河"这一类局面。

## 6. POC 代码与复现

```bash
cd src/clasher_new && python ../../scripts/question_bank_poc.py [--quiz]
# 生成 3 题 + 对账 ≈ 85s；--quiz 追加两个 checkpoint 答题 ≈ 5s
```

关键实现（正式化时直接沿用）：
- 快照构造：`make_battle()`（威胁卡置手牌首位才能部署——`can_play_card`
  只认手牌前 4；直线下移近似行进，攻方冻结语义）
- 候选枚举：`rl.action_mask.legal_cells`（与提交路径同源的合法性）× 粗网格
- 判卷：`simulate_exchange(defender="none")` + `threat_calc` 基线差分，
  汇率取 `rl.config.DEFAULT_REWARD` 前段（塔损 0.0012/unit 0.0005/反打
  0.0010/edw 0.5——**判卷汇率必须随训练奖励同步改**，9k MCTS 的量纲教训）
- 模型答题：`RLEnv.observe` + `BeliefInference` + `BeliefPlanner.plan` 灌
  `FollowerPolicy.act`，答案重过引擎判卷得 EV（合法答案才计分，非法按 null 记）

POC 局限（正式化需替换）：行进用直线下移近似（未走引擎步进，塔仇恨/伴随
单位交互不在切片语义里）；defender="none" 判卷；未做切片间不可组合声明；
题面未带 gamedata hash 版本绑定。
