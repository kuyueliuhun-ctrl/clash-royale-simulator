**三个要如实说的点**：
1. **飞桶落塔那一档，改动是「形状」不是「重叠」**：改前改后都是 0 重叠对，

## §3 实现（3 个接入点，全部「表外 ⇒ 逐字不变」）

新增 `src/clasher_new/formation.py`：形状表 + `shape_positions()`；形状偏移写死在模块顶部。

1. `battle.py:get_spawn_position(..., shape=None)`：显式 `shape` 优先；否则按
   `(卡数据名, 出兵数)` 查 `SHAPE_BY_CARD`；**查不到 ⇒ 走原圆环**（原样保留在函数里）。
2. `battle.py:spawn_arrival_troops(...)`：按 `ARRIVAL_SHAPES` 登记项，用
   `formation.on_tower_rect()` 判「是否落在存活塔的矩形足迹内」⇒ 在
   `barrel_tower` / `barrel_open` 间二选一。
3. `formation.arrival_shape()` / `shape_for_card()`：表驱动，未登记返回 `None`。

**间距的唯一硬依据**：`2 · collision_radius · SPACING_FACTOR`（= 1.05）⇒ 恒 > 半径和。
形状模板里其余数字（`BARREL_BEHIND_Y` / `BARREL_FLANK_X` / `BARREL_FLANK_Y`）是
**用户口径 + 待标定**，集中在模块顶部便于校正。

## §4 用户口径与待标定参数（**要把话说清**）

- 「塔后中央一只，上方左右角对角线各一只」我实现为
  `(0, +2.05)`、`(−2.05, +2.05)`、`(+2.05, +2.05)`（相对塔中心，玩家 0 坐标系）。
  三点**同在塔的远侧**、两翼相对中心是 **45° 对角线** ✓。
- 取 `|y| = 2.05` 的理由是**硬的**：塔半高 1.5 + 哥布林半径 0.5 = 2.0 是
  `_push_troop_out_of_tower` 的推出边界，取 2.05 ⇒ 出生后**不会被第二次挪动**
  （改前那两翼会停在 `y=25.15`，正是被推出的结果）。
- **但「2.05 这个量、以及两翼是否该更靠外」是待标定的**：仓内没有任何可依据的数据，
  真实 CR 的落点我也**没有独立来源**。请你按 dashboard 观感给一个更准的值，改常量即可。
