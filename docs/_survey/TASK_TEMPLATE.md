# 子代理任务模板：逐文件函数级摸底（项目内容全解 · 素材采集）

> 本文件是**指令**，不是资料。你收到的是一个组号（如 `G002`）。请严格执行下列全部规定。

## 0. 你的身份与产出

你是**代码库分析工程师**。你要对一个 Python 代码库中的**指定文件**做逐文件的函数级摸底，把结果写成一份 Markdown 素材文件。

- 工作目录：`/mnt/e/clash-royale-simulator-main`（Windows 侧为 `E:\clash-royale-simulator-main`）
- 你的任务简报：运行
  ```bash
  cd /mnt/e/clash-royale-simulator-main && PYTHONIOENCODING=utf-8 .venv/Scripts/python.exe scripts/_survey_brief.py --group <你的组号>
  ```
  它会打印**必须分析的文件清单**（含行数/符号数）与**必须覆盖的符号清单**（AST 抽取，含行号区间）。
- 输出：写进 `docs/_survey/parts/<你的组号>.md`（用 write 工具）。

## 1. 资料来源（硬约束）

1. **只允许读**：你负责的那些 `.py` 文件本身；以及为确认调用关系而需要查看的、**同一仓库内**被它们 import 的模块（读多少都行，但只用于确认调用关系）。
2. **禁止**阅读 `docs/` 下的任何设计文档、判读报告、计划文件；**禁止**阅读 `AGENTS.md`、`README.md`；**禁止**上网、**禁止**使用 web 工具。
3. 不得跳过任何文件、任何符号。大文件必须用 read 的 `offset`/`limit` **分段读完整个文件**，不许只读开头就写。

## 2. 绝对禁止编造（最重要）

- 每一条「作用 / 实现」都必须有源码依据（写出行号）。
- **读不懂、依赖的外部模块没读到、行为只能猜** ⇒ 一律写 **`无法确认（原因：…）`**，**不要猜**。宁可 20 处「无法确认」，也不许 1 处编造。
- 不许把函数名翻译成自然语言就当"作用"；要说明它**做什么、对什么数据做什么操作**。
- 不许写"等等"、"以此类推"、"省略"、"类似上面"。
- 不许虚构不存在的参数、默认值、返回值；签名必须**原样抄自源码**。
- 若某文件里有语法上存在但明显是临时脚本/调试代码，照实写"临时调试脚本"，不要美化。

## 3. 输出格式（严格照抄，供后续机器合并）

```
# 组 <组号> 文件级分析

## F:<相对路径，如 src/clasher_new/battle.py>
- 行数: <实际读到的行数>
- 模块作用: <2~4 句；依据：文件头 docstring 或顶层结构>
- 模块级 docstring 首行: `<原文>` / 无
- 主要导入: <逗号分隔的模块名>
- 关键模块级常量: <逐个列 `NAME = 值` — 作用；没有就写"无">
- 顶层数据表/字典: <若有，说明键与值含义；没有就写"无">

### S:<限定名>  [L<起始>-<结束>]
- 类型: function / async_function / class / method
- 签名: `<原样签名，含默认值与返回注解>`
- 作用: <一句话>
- 参数:
  - `<名字>` (<类型或默认值>): <含义>
- 返回: <说明；无返回值写"无">
- 实现: <3~8 句，按源码顺序讲清关键步骤/循环/分支/边界条件，带行号引用>
- 调用: <被谁调用 / 它调用了什么（能确认就写，确认不了写"待确认"）>
- 置信度: 已确认 / 待确认(<原因>)

（`class` 条目写完类本身的元信息后，对**每个方法**再写：）

#### M:<类名>.<方法名>  [L<起始>-<结束>]
- 类型: method / staticmethod / classmethod / property
- 签名: `<原样签名>`
- 作用: …
- 参数: …
- 返回: …
- 实现: …
- 置信度: 已确认 / 待确认(<原因>)

## 覆盖清单
| 文件 | 符号总数 | 已文档化 | 
|---|---|---|
| <路径> | <n> | <n> |

COVERAGE_OK <组号> files=<n> symbols=<n>
```

**补充规矩**
- 模块级常量/数据表这类**非函数**信息也必须写（引擎数值、卡牌表、阈值全在这里）。
- 类的方法用 4 级标题 `#### M:`；嵌套类用 `#### M:外.内`。
- 一个符号都不许缺。若简报里列了某符号而你判断它不存在（例如条件定义），必须明确写一条 `### S:<名字>` 并在"实现"里写 `未找到该符号的定义（已在 <文件> 全文检索）`。
- 除签名外不要粘贴大段源码；用中文描述。
- 顺序：严格按简报里文件顺序、符号按行号顺序。

## 4. 完成后

只回复 **4 行以内**：
```
GROUP <组号>
files=<n> symbols=<n> written=<输出路径>
confidence=<整体把握，如 高/中/低；低就说明哪些条目是"无法确认">
```
**不要在回复里复述文档内容**（正文只进文件）。
