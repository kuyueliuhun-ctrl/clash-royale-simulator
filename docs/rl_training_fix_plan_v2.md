# RL 训练整改计划 v2（2026-09-11）

**v2 是 v1（`rl_training_fix_plan_v1.md`）的修订版**，v1 的 P0/P1 结构仍然有效，
本版只改"被 20k 验证跑证伪/证错"的部分，并把剩余项收口到一次 200k 长跑。

依据：`training_audit_2026-09-11.md`（四问审计）+ `ab_valnorm_20k_verdict_2026-09-11.md`
（20k 验证跑 G1 判读）。

---

## 0. v1 → v2 的五处修订（每条都有实测依据）

| # | v1 的写法 | 实测结果 | v2 改成 |
|---|---|---|---|
| 1 | G1 判据含 **`ratio` 离开 1.000** | `ppo.py` 结构性恒等（单轮 on-policy + n_epochs=1），**永不触发** | 判据换成 **`explained_variance ≥ 0.2`**（critic 是否在学） |
| 2 | 用 **`value_loss < 10`** 判 critic | 该数被 `s²` 除过，**跨版本不可比**；且达标时 EV≈0 | 新增 **EV 诊断**，`value_loss` 只作量纲回归 |
| 3 | 门禁阈值 **绝对百分比**（engagement ≥ 9.5） | 阈值来自一次性取证脚本；训练内建指标对**同一批 9k_ft 权重**实测 28.3~38.1，**差约 3 倍** → PASS/FAIL 语义是假的 | 门禁改 **相对本 run 首个评估点**（口径漂移自免疫） |
| 4 | 预算按 **`step`（"训练步"）** | `step` = **决策帧**；20k 步 ≈ 156 次 PPO 更新 ≈ **55~80 局** | 预算改 **"局数"口径**，并落 `cum_games` 到 history |
| 5 | 对手池 `frozen 0.7 / hist 0.2 / defend 0.1` | critic EV≈0 → 怀疑**镜像自对弈对称性**使"状态→胜负"不可预测 | 改为 **`0.5 / 0.3 / 0.2`**（提高非镜像对手占比，给 critic 可学信号） |

另修一处非计划内的结构缺陷（20k 判读 §4 发现）：

| # | 问题 | 修法 |
|---|---|---|
| 6 | **main 曲线结构性无信息**：`copy_every=2000` 与 `steps_per_eval=8000` 整除时，"同步→评估"顺序使评估对手恒为**刚同步的 main 自己** → 镜像局、期望恒 0.5 | 循环内改为**先评估、后同步**：评估对手 = 上一个同步点（step−2000）的副本 |

## 1. 已落地实现（本次）

| 文件 | 改动 |
|---|---|
| `rl/ppo.py` | 新增 `PPOTrainer.explained_variance(values, returns)` 静态方法 + stats 字段 `explained_variance`（用未缩放 MSE 算 → 与 `value_norm` 无关、跨版本可比） |
| `rl/config.py` | `DEFAULT_OPP_MIX = 0.5/0.3/0.2`；`TrainConfig.opp_mix` 字段；`gates` 默认改相对形式 `{"rel":..., "frac":...}`；`economy` 预设 `value_norm="running"`（dataclass 默认仍 `"none"` = 旧行为） |
| `rl/train_solo.py` | `_check_gates` 支持相对门禁（baseline 写进 `gates.json`、续训沿用、首点只建基线不判定）；`_OpponentPool` 读 `cfg.opp_mix`；EV 滚动均值 + `cum_games` 进 history；日志打印 `EV=`；循环内**先评估后同步** |
| `rl/dashboard.py` | solo 表新增 **EV** 列（title 解释含义） |
| `rl/selftest.py` | `test_value_channel_norm_and_gnorm_split` 补 EV 定义性断言（1 / 0 / <0 / 退化 / 长度不匹配 / 与外部复算一致）；`test_history_dedup_and_gates` 改写为相对门禁语义（含 baseline 不漂移）；`test_opponent_pool_mix*` 改为按池自身配比算期望（±35%） |

**兼容性**：`ppo.py` 的**函数默认仍是旧行为**（`value_norm="none"`、`diagnose_every=0`），
新能力全部经 `TrainConfig` 显式开启，不污染 `flow_league` / `train_follower` / `train_prophet`
三个共用入口。

## 2. G1 判据（修订版）

| 判据 | v1 (旧) | v2 | 20k 实测 |
|---|---|---|---|
| critic 是否在学 | `value_loss < 10` | **`EV ≥ 0.2`** | EV ≈ **0.00**（末值 −0.57）→ **未通过** |
| 梯度配比 | `v/p < 3` | 保留 | 0.47 → 0.95 ✅ |
| 策略位移 | ~~`ratio` 离开 1.000~~ | **删除**（结构性恒等，判据无效） | — |
| 行为指标 | 不退化 | **相对首个评估点**不退化 | 中段大幅摆动，末段回落 |

**G1 判定：机制修复生效（v/p 达标、EV 通道打通），但"critic 能学"仍未验证。**
这正是 200k 长跑要回答的核心问题。

## 3. 200k 长跑协议（本次执行）

| 项 | 值 | 与 20k 跑的关系 |
|---|---|---|
| `config` | `economy` | 同 |
| `config-name` | `prod_200k_valnorm_ev` | 新目录 |
| `total_steps` | **200000** | ×10 |
| `steps_per_eval` | **10000** | 20 个评估点（权衡：点够密 + 降低 16-worker 的 1455 暴露） |
| `n_eval_games` | 40 | 同（1σ 胜率 ≈0.078） |
| `eval_workers` | 16 | 同（按用户决定保留；遇异常按 AGENTS 全局约定**暂停等人类**） |
| `value_norm` | `running` | 同（现已是 economy 预设默认） |
| `adv_norm` | `scale` | 同 |
| `diagnose_every` | 10 | 同 |
| `opp_mix` | **0.5/0.3/0.2** | **变更点 #5（唯一行为变量）** |
| `main_init` | `runs/economy_9k_ft/solo_main.pt` | 同（保持与 20k 跑可比起点） |
| `hist_seed_dirs` | `economy_9k_ft`, `economy_9j` | 同（P1-1 补种） |
| 预估墙钟 | **≈5 h**（单 env，实测 12000 步/1097s ≈ 11 步/s 含评估） | — |

**口径换算（重要，勿再按 `step` 高估进度）**

| | `step`（决策帧） | PPO 更新 | 对局数 | 对标 |
|---|---|---|---|---|
| 20k | 20,000 | ~156 | ~60 | Atari PPO 的 ~0.2% |
| **200k** | 200,000 | **~1,562** | **~600–800** | Atari PPO 的 **2%**；FirstLight 25M 动作的 **~4%** |
| v1 的"最小可验证 ≥500 局" | ≈150k–180k | — | 500–800 | **200k 刚好跨过这条线** |

**判读口径（跑完照此读，不另立标准）**

1. **主判据 = `EV`**：`≥0.2` → critic 可救，继续堆量有意义；持续 `≈0` → 停堆量，
   转 P1-2/P1-4（奖励/偏置）或引入更强非镜像对手（`frozen` 再降）。
2. **次判据 = 对照曲线**（vs `baseline0` / `baseline_prev`）：相对 0.5 的净漂移要 **≥2σ**（≈0.16）才算信号。
3. **行为指标**：只读 `gates.json` 的 **相对退化** 报警；绝对数不跨 run 比。
4. **`cum_games`**：确认"局数↔步数"换算，校正后续预算。
5. **不判**：main 曲线（换序后已非镜像，但对手是 2000 步前的自己，仍不是稳定锚点）；
   单点胜率。

## 4. 200k 之后的分支

| 观察 | 下一步 |
|---|---|
| EV 显著 > 0 且对照曲线改善 ≥2σ | 进 P1-2（组波/攒费凹形奖励）+ P1-4（STOP 门控），再谈 500k–1M |
| EV 仍 ≈0，但对局多样性提高后行为指标改善 | critic 是"状态不可预测"而非"没学" → 把价值头从共享 trunk 拆出 + 强化非镜像对手 |
| EV 仍 ≈0 且一切不动 | **停纯 PPO 堆量**（G3）→ IL/BC 底座 + 推理时浅 MCTS（AGENTS 已证 0.19s/次搜索） |

---

## 5. 明确不做（沿用 v1，未变）

1. **不扩模型参数**（629,359；容量分布病态但 NN 只占吞吐 10%，扩容提不了步速）；
2. **不上训练时 MCTS / 专家迭代**（≈120× 每帧经验成本）；
3. **不引入 LLM 实时决策**（延迟进不了 tick 循环）；
4. **不重构动作语义**（`K_MAX=4` 只改偏置与奖励）；
5. **不为了"绕开"外部性能异常而改代码/降配置**（AGENTS 全局操作约定）。

## 6. 风险登记册（v2 增量）

| 风险 | 触发条件 | 缓解 |
|---|---|---|
| 对手池配比变更使训练分布漂移、行为指标短期变差 | `frozen` 0.7→0.5 | 已有行为门禁（相对基线）+ 对照曲线；`opp_mix` 可一键回旧配比 |
| 相对门禁首个评估点自身偏倚（step 0 是热启动权重） | 起点行为指标异常低时，门禁过松 | 首点只建基线不判定；报告里同时记 `baseline` 原值供人工判读 |
| 200k 长跑被打断 | 1455 / 宿主干扰 | 每 10000 步落盘（`--resume` 默认开）；按 AGENTS 约定**暂停等人类** |
| EV 判据被误解为"越大越好" | — | EV 是**诊断**不是目标；PPO 里不设 EV 奖励，只读不优化 |
