# 预注册：平局规则回归"塔血裁决"（2026-09-17）

> 用户指令（逐字）：「修改训练设置：目前的训练设置导致正常防守被判为平局，我们修改所有平局回归它
> 应该的规则，即，**300秒时，双方所有塔血相同即平局**」
>
> 本文件在改动之前写死。遵守【R3】单变量 + 判据先写死（含失败分支）、【R7】单一来源、
> 【R8】配回归测试、【R18】同步维护文档。

## 1 单变量

**平局/胜负裁决口径**。一次只改这一件事；触发条件、奖励权重、加时窗口长度、`max_ep_steps` 全部不动。

## 2 现状（侦察结果：同一件事有三套口径 + 一条"低置信判平"边距）

| # | 落点 | 现规则 |
|---|---|---|
| 1 | `battle.py` 引擎 300 s 硬顶 | 存活塔**最低血量百分比**小者输；百分比完全相等 → `winner=None`（平局） |
| 2 | `rl/run_league.py::timeout_winner`（截断/早停兜底） | 皇冠优先；皇冠平 → 同 #1 的百分比口径 |
| 3 | `rl/run_league.py::settle_stall` + `settle_stall_from_counts` | 皇冠平且百分比差 **< margin(默认 0.05)** → **判平**（C′ 2026-09-12「低置信裁定降噪」） |
| 4 | `config.py::stall_draw_margin = 0.05` | #3 的默认边距 |
| 5 | 僵局早停 `train_stall_stop=True`（100 步零塔血变化 → 早停） | 早停后走 #3 ⇒ **正常防守（打不动塔）极易被这条判成平局** |

**机制判断（待验证）**：用户抱怨的「正常防守被判为平局」最可能来自 **#5 → #3**：
防守成功 ⇒ 100 步无塔损 ⇒ 僵局早停 ⇒ 塔血百分比细差 < 0.05 ⇒ 记 D（且 D 按失败罚 −10）。
（#1 的"百分比完全相等"本身极少发生，不足以解释 demo20k 实测的 14/40、18/40 平局率。）

## 3 新规则（用户指定）

**300 s（或任何提前结算点）**：以**双方三塔血量合计**（绝对 HP）为准 ——

- 塔血合计**完全相等** ⇒ 平局（`winner=None`）；
- 否则**塔血多者胜**；
- 皇冠（被拆塔数）不同时**仍按皇冠判**（常规时间末的领先者，CR 规则，本次不动）。

**单一来源**：裁决只在一处实现 —— `BattleState.tower_hp_total(player_id)` +
`BattleState.timeout_winner()`（引擎）；`rl/overtime.py::timeout_winner` 与
`rl/run_league.py::timeout_winner` / `settle_stall` 一律**委托**给它。

**旧行为保留**：`settle_stall(battle, margin>0)` 仍走 C′ 旧路径（百分比 + 边距），
`--stall-draw-margin 0.05` 可逐位复现旧标签；默认改为 `0.0`（= 新规则）。

**已知取舍（如实记录）**：旧口径用"百分比"是为了兼容**塔兵改变公主塔最大血量**的卡组
（绝对 HP 会失真）。用户要的是绝对塔血 ⇒ 采用绝对值；该失真只在带塔兵的卡组里可能出现，
判读时若见异常需回到这一点。

## 4 判据（跑前写死）

| # | 判据 | 通过线 | 失败分支 |
|---|---|---|---|
| **J1** | 单元级：三处口径一致 | 引擎 300 s、`timeout_winner`、`settle_stall(margin=0)` 在**同一盘面**给出同一 `winner`；塔血相等 → `None`，不等 → 多者 | 不一致 ⇒ 说明还有第二套口径，继续找 |
| **J2** | **配对**（同一批对局、同策略同种子）：平局率 | 新规则下平局数 **< 旧规则**（demo20k `eval@5000` 旧读数 = **14/40**，`eval@12500` = 18/40） | 不降 ⇒ 机制判断错，重查平局来源 |
| **J3** | 平局只在"塔血完全相等"时出现 | 抽样对局中，凡判平者塔血合计差 = 0（脚本复算，误差 < 1e-9） | 出现"塔血不等却判平" ⇒ 未改全 |
| **J4** | 回归：相关 selftest + 新增断言 | 相关测试全绿（【R19】：只跑相关子集，不跑全量） | 任一失败 ⇒ 不提交 |
| **J5** | 成本：加时窗口长度/触发条件未动 | `overtime_open` 逻辑逐字未改 ⇒ 单局最大步数不变（≤600） | 变了 ⇒ 说明误改了别的 |

**不做**：不改加时窗口（180→300 s）、不改 `max_ep_steps`、不改奖励权重、不改僵局早停阈值
（`STALL_WINDOW/STALL_LIMIT`）、不改皇冠优先规则。
