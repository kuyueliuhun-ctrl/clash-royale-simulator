## §2 场景操作化（把用户的口述变成可复现的两步）

1. **p1 在国王塔后放暗夜女巫**：`(9.5, 31.5)`（王塔矩形 `y∈[27,31]` 的后方那一行；
   与 p0 侧 `behind_king=(9.5,0.5)` 同构）。静音 p0 的 AI，避免它自己出牌干扰。
2. **她经过 p0 公主塔时，p0 放戈仑石人**：p0 公主塔在 `y≈6.5`。按「她到 `y≈10` 那一刻」
   在**她正前方**投放石人（`x = 女巫当前 x`，`y = 女巫 y − 4.0`），使石人正好落在她的行进轴上。
   ⇒ 用**触发条件**（"她跨过 y=10"）而不是固定时刻，避免两臂因速度差而错位。

## §3 预注册（**跑前写死**；判据、失败分支、对照齐备）

- **单变量**：只在 `resolve_collisions` 的 e1 位移上乘 `0.5`（上游口径）；
  塔特判、除零守卫、`e2` 侧位移、`geo_cost`、A\* 一切不动。
- **两臂**：`A_full`（现状，e1 全量位移）・`B_half`（e1 位移 ×0.5）。
- **指标（都在触发后的窗口内测，只看女巫）**：
  - `max_stall_frames`：最长「连续位移 < 0.02 格」的 tick 数（1 tick = 1/60 s）。
  - `net_dy_rate`：窗口内 `Δy / Δt`（格/s）。
  - `separation_min`：窗口内两单位中心距的最小值。
- **判据（**比值型**，避免【R16】的「单次观测标定绝对阈值」）**：
  「**碰撞减半能卡住**」= `max_stall_frames(B_half) ≥ 2 × max_stall_frames(A_full)`
  **且** `max_stall_frames(B_half) ≥ 18 tick`（0.3 s —— 这是**下限**而非标定值，
  只用来排除「两臂都≈0」时比值的无意义放大）。
- **失败分支（写死）**：
  - 若 `max_stall_frames(B_half) < 2 × max_stall_frames(A_full)` ⇒ 判「**碰撞减半卡不住**」
    ⇒ 按用户口径**不做这个改动**。
  - 若两臂的 `max_stall_frames` **都 < 18 tick**（都没卡住）⇒ 同样判「**卡不住**」，
    并额外记「本场景下石人根本不构成阻塞」——**不得**反过来写成「所以该改」。
- **阳性对照（必须）**：两臂都必须真的发生「女巫走到石人附近」——即
  `separation_min ≤ 1.30`（= 半径和 1.25 + 0.05 容差）。任一只没接近 ⇒ 本轮**作废**
  （否则测的是「没相遇」，不是「卡位」）。
- **阴性对照**：**不放石人**跑一遍 ⇒ `max_stall_frames` 必须 ≈ 0（女巫自己不会停）。
  若阴性对照也出现大 stall ⇒ 说明 stall 指标被别的东西污染（例如 deploy_time 冻结窗口），
  本轮**作废**。
- **写作禁则**：只写「卡得住 / 卡不住」与比值；**不写**「更好/更差」；
  不得把本实验并进任何训练/疗效判据集（【R3】）。

## §5 未验证 / 未定

1. **「原游戏能卡住」是用户口径**，本文**没有独立来源**可复现；本次实验只能回答
   「**我们引擎在两种碰撞口径下**卡不卡得住」，不能验证原游戏的事实。
2. **`*0.5` 的引入出处不可考**：`git log -S"(1-movement_ratio)*overlap*0.5"` 在当前分支
   历史里 **0 命中** ⇒ 只能确证「现在 A 源码里没有」，**无法**给出「谁去掉了」。
3. **上游未独立实跑**：B 的 separation 数字是按上游源码公式**算术代入**同输入，不是导入
   上游仓跑的（两仓模块同名，同进程导入会冲突）。
4. **女巫的蝙蝠召唤、目标重选、卡死自救（`_stuck_check`）**都可能独立造成 stall ⇒
   即使观察到 stall，也只能写「本场景下 stall 出现/不出现」，
   **因果**要另外做消融才谈得上。
