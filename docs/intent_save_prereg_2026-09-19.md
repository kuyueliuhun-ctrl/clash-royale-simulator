# 攒费意图动作（intent-save）预注册 —— 把「等待」从逐帧抽样变成一次承诺

> 触发（2026-09-19，用户提问）：「能否搞一个**信念**机制：模型想出某张牌但圣水不够时**不再拒绝**它的动作，
> 而是告诉它「现在圣水不够，选这项 = 等下一个或多个决策帧」，且**有权在等待中途改变想法**？」
>
> 本文 = **预注册**（【R3】：判据跑前写死，含失败分支）。**状态 = 未实施**。
> 先纠正一处前提：现在**不是"拒绝了模型的出牌"** —— 买不起的牌被**掩码移出动作空间**（`action_mask._slot_playable` ⇒ `masked_fill(-1e9)`），
> 采样概率恒 0（见 [`illegal_action_layers_2026-09-18.md`](illegal_action_layers_2026-09-18.md) §11.1）。
> 所以本提案的准确表述是：**把"买不起的大费牌"从「不可选」改为「可选，选中即等于对它的攒费承诺」**。

---

## 0. 一句话

**这是本线程里第一个直接打在"轨迹从未被采样"这个根因上的改动**：repo 自己的取证已经把攒费失败定性为**合取结构**
（`p^k`，指数在**帧数**上）而不是随机性不足（O10 三问）；本方案的机制效果 = **把 `k` 次独立抽样的合取，压成 1 次承诺 + 可打断的自动保持**。

### ★ 死锁前科（反面教材，实施前必读）

`rl/plan_space.py` **已经存在这个机制的"规则版"**：`MACRO_INTENTS` 含 `setup_wait`（沉底蓄力）、`save_ace`（藏终结卡）、
`cycle_and_wait`，配 `hold_mask(4)`（bit(slot-1)=1 ⇒ 本帧别出该槽）。
**实测 4 局 898 决策帧 100% `cycle_and_wait`，`setup_wait` 从未触发**——触发要求"血牛在手 ∧ 后排在手 ∧ 攒到 9.95"，

> **教训（本预注册的第一原则）**：攒费意图**必须在动作层由策略采样**，**不得**写成规则触发器。
> 规则版之所以死锁，是因为它的触发条件本身是"策略已经学会了攒费"——把待学的东西写成了前提。
> 本方案反过来：**意图是策略的一个选项，触发条件只有"买不起"**（一个策略无法控制的客观事实）。

## 2. 机制规格（M1 最小版）

### 2.1 动作空间：把 STOP 一个 option 分解为 5 个

| 索引 | 语义 | 掩码条件 |
|---|---|---|
| `0..K_MAX-1` | 出牌槽（**不变**） | `mask["slots"]`（**不变**） |
| `K_MAX` | 英雄技能（**不变**） | `mask["ability_legal"]`（**不变**） |
| `K_MAX+1`（=5，**旧 `STOP_IDX`**） | `STOP(none)` = **旧 STOP 逐位不变** | **恒合法**（**不变**） |
| `K_MAX+2 .. K_MAX+5`（=6..9，**尾部追加**） | `SAVE(slot i)` = 「对槽 i 攒费」 | **仅在槽 i 买不起、卡在手、王塔存活时合法** |

- **尾部追加**：`0..5` 的索引与语义**逐位不变** ⇒ 与仓内既有的「尾部追加 + 尾零兼容」模式同构（belief 23→563、
  观测 13→177 都是这个模式）。
- **掩码零改动**：`STOP` 本来就恒合法，`SAVE(i)` 的合法条件就是 `not mask["slots"][i]` 的镜像。
  ⇒ **不触碰【R13】**（位图对账）。★ 这是本方案刻意选「STOP 分解」而**不是**「放开大费牌的 slot 掩码」的**主要理由**：
  后者会改变**出牌槽**的合法集，直接把新缺口引进 L1/L2/L4。

### 2.2 三件套（缺一不可，按重要性排序）

1. **粘性（stickiness）—— 本方案的**全部价值**所在**
   `pending` 一旦设置就**跨帧保持**，**保持不需要逐帧重抽**。
   ⇒ 34 帧的等待从「34 次独立抽中不出」变成「1 次设置 + 自动保持」。
   ⚠️ **若"保持"仍需逐帧抽样，`p^k` 原封不动回到原点，本机制价值归零**（见 §5 R-1）。
2. **打断（interruptibility）—— 用户明确要求的那一半**
   任意其他合法动作（出牌 / 技能 / `STOP(none)`）⇒ `pending` **清零**。
   这条是**必要**的：对手不会等你（34 帧 = **17 s**），不能守则本机制会主动制造失守。
3. **执行（fire）**
   圣水 ≥ 费用时，该卡经**正常掩码路径**变可出 ⇒ 那一帧是"富帧"，走**正常决策**（含落点）。
   ⇒ ★ **落点在执行帧决定，不作为意图的一部分预提交**。理由：17 s 前预提交的落点会过期
   （盘面变了、格子被建筑占了），那会**主动制造新的 L4 缺口**（`invalid_count += 1` + −0.05 + 白掉该卡）。
   本方案**不得**新增非法动作面。

### 2.3 观测（必须加，否则"等"仍不可辨识）

新增 **+6**：`pending` 目标的 one-hot(5：none + 4 槽) + **已等帧数**（归一化）。
理由：现状 88%~91% 的帧「买不起任何手牌」，`STOP` 覆盖率 ~0.90 而**毫无区分度**
（[`pass_prob_2026-09-18.md`](pass_prob_2026-09-18.md)）。**没有"我在为谁等、等了多久"，等待帧依然匿名，信用分配依然无从下手**——
而"信用分配横跨 20+ 帧"正是本仓反复确认的核心困难。

### 2.4 记账（**只记录、不加奖励**）

`intent_set` / `intent_held_frames` / `intent_fired` / `intent_cancelled_by[action]` 四类计数，
落 `info` + 录像（schema 不变、局内累计）。

**失败分支（跑前写死，照此执行）**：

- **F1 `set > 0 但 fired = 0`** ⇒ **打断过强**（每帧都有防御压力）⇒ 下一刀 = 打断门 / 时长 option（M2），**不是**调奖励。
- **F2 `fired > 0 但 fired 的卡从未造成塔伤/解场** ⇒ **奖励侧问题** ⇒ 转 **O7**（本方案不治这个）。
- **F3 `set = 0`** ⇒ 新 option 初始概率被压死（初始化问题）⇒ 调**初始 logit**（§3 的兼容注意事项），**机制不变**。

## 5. 风险清单（**并列，不调和**）

- **R-1（第一约束）粘性 vs 可打断的张力**：可打断如果实现成"每帧重抽保持"，则 `p^k` 回归、机制价值**归零**。
  ⇒ 实现上必须是「**默认保持，动作只是打断**」，而不是「每帧选择是否继续」。
- **R-2 打断过强**：34 帧 = 17 s，几乎不可能全程无威胁 ⇒ 现实预期是「意图被反复设置、偶尔 fire 成功」。
  若 F1 成立，M2（时长 option / 几何分布 hold）才出场。
- **R-3 观测 +6** ⇒ 旧 ckpt 该通道尾部为零（同 belief 扩容模式）。
- **R-4 执行帧的合法性漂移**：目标是手牌槽，`cycle[:4]` **只在出牌时推进** ⇒ 目标卡不会中途离手；
  但 **Mirror / MergeMaiden 费用是动态的**（`battle.py:3013-3056`）⇒ **必须在执行帧重校验**，
  **校验失败就静默清 `pending`**（不得让它变成一次非法提交）。
- **R-5 与 `plan_space` 语义重叠**：`save_ace` / `hold_mask` 是同一意图的**规则版**。
  必须决定：**共存**（两条攒费通路，互相干扰的量化未知）/ **让规则版退场**（`hold_mask` 恒 0）。
  ⚠️ **未定**，实施前必须选一个，否则 A/B 的"唯一变量"不成立。

## 6. 未定 / 不做

- **M2（时间抽象：`hold d` 成为策略可学的时长）** ⇒ **本预注册不实施**，仅在 F1 触发时**另立预注册**。
- **与 O7 的关系**：本方案治的是**可达性**（0 样本 ⇒ 0 梯度）；**不治**奖励量纲
  （§11.4 已证 `edw` 对"出牌帧"与"白掉帧"**不可分辨**）⇒ **两者是并列的两个病，不要互相顶替**。
- **不做**：不改 `invalid_penalty`（见 §12 的六条理由）；不放开任何 slot/cell 掩码；不加奖励项。

### 8.2 ★ 对 §2.1 的修订：**掩码必须改**，否则机制不成立

§2.1 原写「`mask` 的 `slots`/`cells`/`ability_legal` 一行不改 ⇒ 不触碰【R13】」。实施时发现这与本预注册**自己的第一约束 R-1 矛盾**：

- 若"保持"期间花费仍然合法，则每帧都要在「保持」与「打一张买得起的牌」之间抽一次。
  实测口径：**有牌可出时 `P(STOP)=0.058~0.09`**（[`pass_prob_2026-09-18.md`](pass_prob_2026-09-18.md)）⇒
  34 帧合取 ≈ **1e-14** ⇒ 「≥34 帧意图后真打出」这条轨迹**依然采样不到**（= §1 的 0 样本问题原样保留）。
  「保持不需要逐帧重抽」只是**实现上不必重抽**；只要"别的牌仍可出"，**竞争项**就还在。
- ⇒ 唯一能打破 `p^k` 的做法 = **承诺期内把花费整块掩掉**，合法集只剩
  `{保持(=STOP), CANCEL, 改攒其它槽}`。此时 34 帧保持的路径变成
  **1 次 `SAVE` + 33 次「保持 vs 取消」二选一**，而**取消没有任何即时收益** ⇒
  `P(保持)` 可以学高（初始就 ≈0.5，且没有反向梯度）⇒ 轨迹**可达**。

**代价（必须写清，不调和）**：承诺期内**不能防守**（`ability`/出牌都被掩）⇒ 策略只能先花一帧 `CANCEL` 再出牌。
**这个代价由奖励定价**（挨打 `tower_dmg_self=0.0012` 是即时且重的信号）⇒ 预期策略会学成「低压时才攒」。
★ **这正是 `plan_space.setup_wait` 当年想做的事，区别在于"什么时候该解禁"是学会的，不是写死的**
（手写版本 898 帧 0 触发，见 §1）。
