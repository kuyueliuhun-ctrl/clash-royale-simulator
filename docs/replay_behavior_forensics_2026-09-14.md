## §6 口径缺陷：「幽灵动作 y≥20」是错的（**本条推翻了一个跨脚本复用的假设**）

`scripts/forensics_response.py` 的模块注释与代码里写着：

```python
if b[3] >= 20:
    continue   # 幽灵动作：非法尝试，引擎未执行，不进空间统计
```

**引擎的真实规则**（`rl/action_mask.py:382 _position_legal`）：

- **部队/建筑**：player 0 的 `pos.y >= 21.0` 非法（`pos.y = y + 0.5`）⇒ 本地 **y ≥ 21** 非法；
- **法术**：`if card_info.type == "spell": ... return True`（除"砸已毁塔本体"与"空砸闸门"外）
  ⇒ **法术可以打任意格**，包含打对方半场/塔。

**实测（本 run 全部 440 局）**：

| 项 | 数字 |
|---|---|
| 部队出手 | 7642 次，其中 **y≥21 = 0 次**（最大 y=20） |
| 法术出手 | 2164 次，其中 **y≥21 = 268 次**（最大 y=31，打对方塔） |
| 独立执行证据：`pre > 10 + 0.6`（费用未被扣）的帧 | **0 / 8804** |
| 旧口径会误标的出手 | **452 次 / 458 帧** |

`pre ≤ 10.6` 说明**费用确实被扣了 ⇒ 动作确实被引擎执行了**（8804 个单子动作帧里 0 例外）。
⇒ **本回放里不存在非法部署**；旧口径把**我方进攻法术的落点**（Log 打到 y=21、Fireball 打到
y=31）当成了"幽灵"。

> **教训（可入台账）**：这条口径不是"数值近似"，而是**方向性错误**，却被
> `forensics_response.py` → 外部调研 → 外部调研的结论链**复用了三轮而无人验证**。
> 教训的普适形式：**跨脚本复用的过滤器必须先用独立证据（这里是"费用是否被扣"）验证一次**，
> 不能用"注释里写着非法"当依据。

## §7 因果链（**本轮的合成结论**）：不是"不打 Xbow"，是"**永远没有 6 费**"

把 §3 的出手分布与 §4 的圣水读数并排看，出现一条**用同一批数据闭合**的因果链。

### §7.1 费用可达性表（脚本复算：`§7`）

| 费用 | 张数 | 出手次数 | 档占比 | **每张占比** | **可达窗口**（全帧 `elixir≥费`） | **可达帧数**（共 100860 帧 / 440 局） |
|---|---|---|---|---|---|---|
| 1 | 1（Skeletons） | 2012 | 20.52% | **20.52%** | 0.675768 | 68158 |
| 2 | 1（Log） | 1946 | 19.84% | **19.84%** | 0.330488 | 33333 |
| 3 | 3（Knight/Archer/IceWizard） | 5404 | **55.11%** | **18.37%** | 0.063524 | 6407 |
| 4 | 2（Tesla/Fireball） | 441 | 4.50% | **2.25%** | 0.004511 | 455 |
| **6** | **1（Xbow）** | **3** | **0.03%** | **0.03%** | **0.001110** | **112** |

### §7.2 链条

1. **策略几乎从不停留在高费**（§4）：全帧 `elixir ≥6` 只占 **0.111%**、`≥4` 占 **0.451%**。
2. ⇒ **6 费卡的可达帧数上限 = 112 帧 / 440 局**（而且真实机会还要更少，因为还要"在手上"）。
   **Xbow 实际出手 3 次**——**"从不打 Xbow"里压倒性的部分是"根本没有 6 费"，不是"有 6 费不打"。**
3. ⇒ 4 费卡的可达帧数 = 455，实际出手 441 次（其中 Tesla 223 + Fireball 218）。
4. ⇒ **"一旦攒到 3 费就立刻打掉"**。⚠️ **口径警告**：不要用"3 费卡出手 5404 ÷ 帧末圣水≥3 的帧数 6407"
   这类比率——两者**不是同一样本集**（分子是"出手次数"，分母是"**帧末** elixir≥3 的帧"，
   pre/post 语义不同；R9⑤）。**该结论的正确证据是 §4 里已精确对账的单子动作帧**：
   部署**前**圣水（`pre = post + 卡费`，8804 帧精确）**p10 = 1.32 / 中位 = 3.25 / p90 = 3.64**，
   而 `pre ≥ 6` 只占 **0.02%** ⇒ **出手集中发生在 3 费附近，且从不等到 6 费**。
5. ⇒ 于是出手分布退化为：**"手里有什么便宜的就打什么"**——
   5 张费 ≤3 的卡每张 **18.1%~20.5%**（近乎均匀，彼此差 ≤13% 相对），
   费 4 的 2 张各 **2.25%**，费 6 的 1 张 **0.03%**。

> ### 结论：**Xbow 的 0.03% 不是"战术偏好"，而是"可达性"的算术后果。**
> 想让它打 Xbow，**先得让它攒到 6 费** —— 这与 `AGENTS.md`【未决 O3】
> 记的「`setup_wait` 冷启动死锁已定位但两阶段状态机未实现」是**同一件事**，
> 现在它有了一个**可验收的量化目标**：把"全帧圣水 ≥6 占比"从 **0.11%** 抬上去。

## §8 局限（预先声明）

1. **单 run**（`d1_long_100k`）的 11 个评估点；跨 run 不可比（【红线 R5】）。
2. **只有 player-0 侧被记录**（`bundle`/`cards`/`elixir0`）⇒ 只统计"我方"；
   非 `side0=='main'` 的局被排除（本 run 为 0 局）。
3. **`pre` 只在"恰好 1 个子动作"的帧上精确**（88.19% 的部署帧）；多子动作帧因重复槽位
   /部分执行而无法精确对账，脚本选择**排除而不是估算**。
4. 圣水口径假设"一帧 0.5 s、回复 1/2.8 s⁻¹"（双倍期为 1.4 s⁻¹）；容差 0.6 覆盖两档。
5. **"5 卡策略"是描述，不是判决**：本脚本不判"打便宜牌是错的"。要判"是不是局部最优",
   需要一个**可比的手写专家基线**。**⚠️ 2026-09-14 更正**：`rl/belief_planner.BeliefPlanner`
   **不是**手写策略——它的 `plan()` 只返回 **`PlanToken`（战术意图提示）**，动作仍由 RL 策略出；
   要拿它当基线必须**另建一个"PlanToken 贪心执行器"**（`opponents.py` 里的
   `SelfDefenderPolicy` 是纯防守脚本，不能当进攻专家）。
6. **§7 的因果链是"可达性算术"，不是因果实验**：它证明"没有机会"，**不**证明"有机会就会打"。
   要证后者必须在**攒费修好之后**看 Xbow 出手率是否上升（单变量、预注册）。
