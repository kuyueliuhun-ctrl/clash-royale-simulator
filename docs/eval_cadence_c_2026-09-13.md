# 评估节奏 C 方案：密锚点 + 稀全块（2026-09-13）

**起因（用户提问）**：「100k 步量级训练时，能否减少评估次数以加速训练？」

**结论**：能，但不能均匀地减——因为**主判据 C1（单跑最差锚点）的谷底只有 1 个评估点宽**（实测），
均匀放宽周期会先毁掉判据本身。故拆成两条节奏：

| 评估类型 | 频率 | 内容 | 单点成本 | 100k 点数 |
|---|---|---|---|---|
| **全点** | `--steps-per-eval` | main vs 冻结副本 + baseline0 + baseline_prev + baseline_rand | ≈210 s | 11 |
| **轻点（新）** | `--anchor-every` | 只跑 **baseline_rand 锚点** + 落快照/Adam/run_state | ≈53 s | 30 |

100k 墙钟从 **3.46 h（照抄 2500 全点）降到 ≈2.15 h**，而**主判据的锚点序列逐点与 2500 全点协议相同**
（见 §5 的确定性论证）——即 C 方案是 2500 协议的**真子集**：只丢掉次要块（main/两个对照）在中间点的分辨率。

## 1. 成本实测（先量再改）

| 项 | 值 | 来源 |
|---|---|---|
| 纯训练吞吐 | **26 步/s** | ① D1 三跑 `训练循环耗时` 均值 2427.3 s 扣掉 8 个评估点 = 771 s/20k → 25.9 步/s；② `prod_200k_valnorm_ev` 独立记录 26.2 步/s。两条口径互证。 |
| 100k 纯训练 | **1.07 h** | 100000 / 26 |
| 单个**全点** | **≈210 s** | `eval@0` 实测 212.0 s（覆盖 4 块 × 40 局 = 160 局）。该打印标签写"40局"是历史误标，实际是 4 块合计。 |
| 单个**轻点** | ≈53 s | 锚点块 = 1/4 全点（40 局） |

| 周期方案 | 评估点 | 评估 | 训练 | 总墙钟 |
|---|---|---|---|---|
| A：2500 / 全块（20k 协议原样） | 41 全 | 2.39 h | 1.07 h | **3.46 h** |
| B：5000 / 全块 | 21 全 | 1.23 h | 1.07 h | **2.30 h** |
| **C：2500 锚点 + 10000 全块（已实现）** | 30 轻 + 11 全 | **1.08 h** | 1.07 h | **≈2.15 h** |
| D：10000 / 全块 | 11 全 | 0.64 h | 1.07 h | **1.71 h** |

**20k 协议里评估占 73% 墙钟**（1640 s / 2251 s），所以评估是唯一有效杠杆。

## 2. 为什么不能均匀放宽周期（实测证据，非直觉）

D1 三跑的锚点序列（每 2500 步一点，40 局，固定种子）：

```
r1: 0.625 0.400 0.125 0.463 0.550 0.600 0.750 0.375 0.675   min=0.125
r2: 0.625 0.500 0.500 0.263 0.875 0.200 0.287 0.287 0.475   min=0.200
r3: 0.625 0.750 0.500 0.750 0.825 0.475 0.700 0.250 0.362   min=0.250
```

- 相邻点平均 |Δ| = **0.225 / 0.240 / 0.230**，而单点 1σ=0.078 ⇒ 信号 ≈3σ ⇒
  **（⚠️ 2026-09-13 更正：此"3σ"作废，差分 SE=√2σ=0.110 ⇒ 应读作 ≈2.05σ；
  见 `AGENTS.md` X10。结论方向不变。）**
  **谷底是单点事件，宽度 ≲5000 步**。
- 对同一批真实序列做粗采样回放（保留每 2 个 / 每 4 个点）：

| run | min@2500 | min@5000 | min@10000 |
|---|---|---|---|
| d1 r1 | 0.125 | 0.125 | 0.550 |
| d1 r2 | 0.200 | 0.287 | 0.475 |
| d1 r3 | 0.250 | 0.362 | 0.362 |
| 无变化 fprime_20k | 0.000 | 0.000 | 0.000 |
| 无变化 fprime_ev_20k | 0.000 | 0.000 | 0.075 |
| 无变化 gfix_20k | 0.025 | 0.025 | 0.025 |

- 5000：**判据结论与非重叠性都还在**（D1 组 0.125/0.287/0.362 vs 无变化 0.000/0.000/0.025），
  但 D1 组最差点均值从 0.192 抬到 0.258（漏掉一半真谷底）。
- 10000：两组仍分得开，但 D1 组最差点被系统性抬到 0.462（**≈2.4× 乐观**）。
- **关键不对称**：病态组的塌陷是**持续性**的（多个点 0.000，任何粗采样都留得住），
  而 D1/健康组的低点是**周期性瞬态**（粗采样直接丢）。⇒ 粗采样只会让被判对象显得更好，
  恰是"长 run 会不会真塌"最不该失真的地方。

## 3. 实现（已完成）

- `rl/config.py`：`TrainConfig.anchor_every: int = 0`（**默认 0 = 关闭，旧行为不变**）。
- `rl/run_league.py`：CLI `--anchor-every`，并进 overrides 元组。
- `rl/train_solo.py`：
  - 新增 `anchor_point(step)`：`_sync_controls_once()` → 跑 `baseline_rand`（固定种子
    `RAND_ANCHOR_EVAL_SEED=90000`）→ 锚点警报线 → `_persist(step)` → 写 `solo_state.json`
    的 `_controls_history` → 打印 `anchor@<step>`。
  - `eval_and_write` 尾部落盘抽成 `_persist(step)`，两处共用 ⇒ **轻点也落
    `solo_main.pt` / `solo_main_<step>.pt` / Adam / `run_state.json`**，
    崩溃续训粒度仍是 2500（不是 10000）。
  - 主循环：全点 `if` / 轻点 `elif`（全点已含锚点，不重复跑）；末步交给收尾全点。
  - 启动打印评估节奏自述：`评估节奏: 全点每 N 步（M 个，含 eval@0）/ 轻量锚点每 K 步（L 个…）`
    —— 事后凭日志即可复原协议，不必翻命令行。
- `rl/selftest.py`：`test_anchor_light_point_state()`（默认关 / CLI 已接线 / 轻点与全点
  对照共存可复原 / 同 step 幂等）。

## 4. 冒烟验收（两跑，均官方入口、跨局边界 `--max-ep-steps 40`）

`docs/smoke_anchor_c.log`（1600 步，全点 1000 / 轻点 500）：

```
[solo] 评估节奏: 全点每 1000 步（2 个，含 eval@0）/ 轻量锚点每 500 步（2 个，只跑 baseline_rand + 落盘）
[solo] anchor@500:  vs baseline_rand 胜率 0.250±0.216 (1W/3L/0D, 4局)
[solo] anchor@1500: vs baseline_rand 胜率 0.750±0.216 (2W/0L/2D, 4局)
```

落盘核验：

```

snapshots      = [0, 500, 1000, 1500, 1600]     # 轻点也落快照
history pts    = [0, 1000, 1600]                # 胜率曲线仍只由全点产生
_controls_history: step=0/1000/1600 各三条；step=500/1500 各一条 baseline_rand

`docs/smoke_anchor_c2.log`（同参数 + `--solo-copy-every 500`，验 D1 联赛池是否吃到轻点快照）：

```

⇒ 轻点快照确实进 hist 联赛池，"对手池密度不因评估节奏变稀"这条成立。

## 5. 为什么 C ⊇ A 的主判据（确定性论证）

锚点 = `main(step) 权重` × 固定随机策略 × 固定评估种子 × 40 局固定对局。
全点里 main/baseline0/baseline_prev 三块**只读权重、不改权重**，且锚点种子硬编码
（`RAND_ANCHOR_EVAL_SEED=90000`，与 `cfg.seed + step` 无关）⇒
**C 方案在 step=0,2500,…,100000 上的锚点读数与 A 协议逐点相同**。
差别只在中间点的次要块（行为门禁、cycling 指纹）分辨率，以及 main 曲线采样变稀。

附带好处：全点周期 10000 是 `solo_copy_every=2000` 的整数倍（相位周期 1），
而锚点周期 2500 与 2000 的最大公约数是 500（**相位周期 4**，与 20k 基线同构）
⇒ 主判据的相位轮转被保住了，工程上更干净。

## 6. 明确不动的三项

- **`--n-eval-games 40` 不降**：锚点 1σ=0.078 是 C1 判别力的来源（D1 0.192 vs 无变化 0.008
  的分离就靠它）；降到 20 局会把"最差点"的噪声往下推，凭空造出假谷底。
- **`--eval-workers 12` 不升**：12 是实测安全档（AGENTS 全局约定：16 有 commit/页面文件压力风险）。
- **主评估块不删**：它是行为门禁（engagement/ghost）与胜率曲线的唯一数据来源，删了就断证据链。

## 7. 局限与披露

1. 粗采样回放用的是**历史 9 点序列**（20k 窗口），100k 上谷底宽度是否仍是 ≲5000 步未验证；
   C 方案正是为了不依赖这个假设（锚点保持 2500），但它也意味着 100k 的锚点序列会
   **同时**暴露更多真谷底 ⇒ 与 20k 的 9 点最差点直接比是不同严格度，判读见 100k 预注册的块口径。
2. `--anchor-every` 与 `--steps-per-eval` 若设置成非整除关系，轻点会出现在任意相位（功能正确，
   但相位混合更难解释）；推荐整除设置（如 2500/10000）。
3. 本改动是**测量通道**改动（默认关；开启时对训练的作用仅等价于原 2500 协议的快照密度），
   不是训练逻辑改动。
