# 奖励结算方式改造预注册（2026-09-14）

> **触发问题（用户）**：能否换一种奖励结算方式？
> 本文件只做三件事：① 把"结算链路"的**改动点**与**零代码可用开关**钉在源码行号上；
> ② **先证明两类改动是无效操作**（整体缩放 / 调权重），避免白跑（【R3】【R15】【R16】）；
> ③ 把**第一批单变量实验**的判据在跑前写死，并列出**已被既有证据排除**的候选。

## §0 摘要（三句话）

1. **能改**：结算链路只有 5 个改动点（§1），其中 4 个**已有 CLI/配置开关（零代码）**。
2. **两类改动先被排除**：① 调奖励权重 —— 【W4】逐帧奖励**无主导项**（30.95/29.84/21.47/10.11/7.63%），

   它是**数学恒等操作**（§2 给出推导），跑了也读不到东西。
3. **顺序**：先做**零成本门禁**（手写专家对照，§5，不训练）→ 再跑第一个结算实验（§4 的 **E-A**）。
   **在 §5 出结果前不改任何代码。**

## §2 先证明：整体缩放奖励是**恒等操作**（做了 = 白跑）

设把每帧奖励整体乘 `k>0`：

1. `compute_gae` 对奖励**线性**（`ppo.py:168-192` 只有加乘）⇒ `adv → k·adv`；
2. `adv_norm="scale"`：`advs = adv / std(adv)`（`ppo.py:224-226`）⇒ **`k` 精确约掉**，
   策略损失 `−min(ratio·A, clip·ratio·A)` 逐位不变；
3. `value_norm="running"`：回报 `R → kR`，`ReturnScaler.std()` 同步 `→ k·s`，
   `v_loss = MSE(V,R)/s²`（`ppo.py:392`）⇒ 若 `V` 也同尺度则不变。

⇒ **策略侧：整体缩放是恒等操作**（`scale` 分支的除法使然）。
**唯一例外**：`V` 尚未与奖励同尺度时的**瞬态**——本项目 `V ≡ const`（`c=+0.1425485`）是最极端情形，
此时 `δ_t = k·r_t + (γ−1)c`，`std(adv) ≈ k·std(r)`，`k` 仍在除法里约掉；但价值损失的**目标尺度**
（`R` 绝对值 vs 常数 `V`）会变 ⇒ **只有 critic 的瞬态受影响**。

**预注册声明**：本轮**不含任何整体缩放实验**（改 `crown_weight` 之类的"放大/缩小奖励"一律不做）。
若将来必须缩放，必须先给出**噪声地板**（用 §3 的阳性/阴性对照臂标定），否则读数不可判决。

> 这条也是**历史教训的推论**：【W4】"奖励被某一项主导"已被排除，而缩放连"改变结构"都做不到。

## §3 判据（跑前写死）

**主判据不使用胜率**——`n=1` 分辨率不足（【R5】：同 seed 两次 run 都不可复现；40 局 1σ≈0.078），
且 run 内自引用指标全部失真（§3 判读禁则）。改用三层可复算仪器：

| 层 | 指标 | 仪器（已存在） | 对照（脚本复算，禁手抄【R4】） |
|---|---|---|---|
| **机制层（主）** | 批内 EV、优势形状残差 `resid_norm`、`grad_cos` | `diagnose_every` 日志 / `scripts/judge_critic_inertia.py` | 本实验 run 自己前 100 次诊断更新 |
| **行为层（可复算）** | 全帧圣水 ≥6 占比、Xbow 出手率、部署前圣水中位、同路部署间隔 | `scripts/forensics_card_usage.py`（只读，~10 s） | `d1_long_100k`：**0.11% / 0.03% / 3.25 / 5.5 s** |
| **结构层**（**只作描述，不作判据**） | 逐帧奖励五项占比（Σ\|项\| 归一） | `scripts/probe_reward_composition.py`（只读） | `d1_long_100k`：约 crown 24~31% / edw 30~36% / tower 20~22% / unit 8~12% / terminal 8~10%（**散布见 §7**） |

> 上表"对照"列的数字来自 `src/clasher_new/runs/d1_long_100k`（**单 run、单 ckpt、且读数本身有散布**），
> 只作**量级参照**：按【R16】它们**不得**直接当作阈值（是单次观测），按 §7 更**不得**当基线（不可复现）。
> 命令见 §7（均已实跑）。

**阈值标定程序（写死的是程序，不是数字）**：
- 阈值取**本实验同一 run** 的**前 100 次诊断更新**作对照池，由脚本复算中位数与 MAD，
  判定线 = 中位数 ± 3×MAD；**禁止**沿用其它实验的阈值（【R15】）、
  **禁止**用单次观测标定（【R16】）、分子分母必须同超参约定（【R17】）。
- 为什么不在本文件写死数字：本项目**没有**"结算口径改动"的历史散布读数可作余量依据，
  任何此刻写下的数字都会是单次观测（`d1_long_100k` 一个 run）⇒ 直接违反【R16】。
  **这是对"判据跑前写死"的有意偏差，理由与做法在此公开登记。**

**阳性对照（必须包含，否则"无变化"不可解释）**：
同一仪器上跑一个**已知会改变读数**的干预臂——**`elixir_diff_weight: 0.5 → 0.0`**（关掉资源账）；
预期它能明显改写结构层占比（edw 项 → 0%）与行为层部分读数。
- 阳性对照**过** + 主判据**不过** ⇒ 判"该结算改动无效应"，记入台账；
- 阳性对照**不过** ⇒ 判 **`INVALID`（不判决）**，先修仪器/流程，禁止解释主判据。

**阴性对照**：**同配置重跑**（不同 seed）——用于量出"无改动时的散布"，是判定"有变化"的前提
（【R5】：跨 run 数字不可直接比，故对照必须是**同批次**的）。

**预先声明的失败分支**：若 E-A 的机制层读数改善但行为层三项**全部**无改善 ⇒
判"**未达行为可见阈值**"，**不得**写成"修复了策略行为"（【R11】：不因 EV≈0 宣称修好，反之亦然）。

## §4 候选清单（按机制强度排序，逐个独立预注册）

| 编号 | 改动 | 机制（为什么可能有用） | 成本 / 风险 | 状态 |
|---|---|---|---|---|
| **E-A** | **价值目标去 DC**：新增 `value_norm="center"`（`v_target=(R−mean)/std`，读回时反变换；**GAE 的 bootstrap 必须用反变换后的 V**） | critic 现在学的是**慢漂移水平**（批内 EV 145/145 为负、批内 `Var(R)` 仅全局 0.32 倍）⇒ 把目标中心化，等于把"学 DC"这件事从任务里删掉，只留状态可解释部分。不改奖励、不改优势、不动架构 | 小（`ppo.py` 一处 + 反变换读回）；**必须默认关闭**（【R2】逐位回旧） | **本轮首推** |
| **E-D** | **结算窗口**：`--gae-lambda 0.99 → 0.95` | γλ 半衰期 53→13 帧（`scripts/probe_gae_kernel.py` 实测），时间分辨率提高 4 倍；8 帧时间差的权重差 9.9%→38% | **零代码**；但会同时缩短终端 ±10 的可见视野（λ 的原始取舍理由）⇒ 判据必须同时看行为层 | 第二 |
| **E-C** | **反事实结算**：只结算"本帧动作引起的增量"，剥离引擎自发漂移（圣水回复 / 引擎自推伤害） | 决策帧之外的奖励里含大量**与任何动作无关**的项，它们构成优势的 DC，对策略梯度期望贡献为 0、纯抬方差。需要一次"影子推进"或解析出自发项 | **大**（引擎侧影子推进 ⇒ 单帧成本 ×2；或为每项写解析基线） | 第三（成本高，先做 E-A/E-D） |
| **E-B** | **优势去 DC**（按局/按时间桶基线） | 与 E-A 同机制但作用在优势上 | 小 | **与既有取舍冲突**：`adv_norm` 之所以选 `scale`（不中心化），理由正是"躺平零优势帧被批均值抬成伪正优势"（`config.py:134-139`）。**要做必须先解释该病理为何在本变体下不成立**，否则不做 |
| **E-E** | **势函数补齐 γ**：`edw·[Φ'−Φ] → edw·[γΦ'−Φ]` | 恢复 Ng et al. 1999 的 policy-invariance（理论缺陷，唯一"一行能修好"的） | 极小 | **不单独跑**：偏差量级 **+0.0012/帧 = 6%**，`reward_composition_verdict` 已判"量级不足"。登记为"将来若做 A 类结构改动可顺带修正"，**不作为独立变量** |

> **不预注册**：任何奖励权重数值调整（【W4】无主导项）、任何整体缩放（§2 恒等）、
> 任何"加训练量救 critic"（【X4】已否证 100k）、任何价值头结构改造（【X3】四代全否）。

## §6 红线与局限（预先声明）

1. **【R2】**：所有改动必须落 `TrainConfig` 显式开关后，**默认逐位回旧**（`ppo.py` 的函数默认参数
   被 4 个入口共用）；E-A 尤其要注意"`value_norm="none"` + `vf_coef=0.5` + `adv_norm="batch"` = 逐位回旧"。
2. **【R3】**：一次只改一个变量；§1.1 的陷阱说明**工具本身**会破坏这条，必须用 `--save-config` 往返。
3. **【R6】**：若实验涉及 `value_bypass`/`value_independent`，必须 `--fresh` 且**不得**传 `--main-init`。
4. **【R1】**：长跑前先量 `wmic OS get FreeVirtualMemory`、清理孤儿 spawn worker、
   **显式**传 `--eval-workers 12`（`economy` 预设**不设置**该字段 ⇒ 不传就落到 16 的风险档位）。
5. **【R9】**：`step` = 决策帧；EV 用**更新前池化**口径；但**池化 EV 不是状态级价值质量指标**——
   判"结算是否让 critic 学到状态依赖"必须看**批内 EV / 优势形状残差**（【O2】结论）。
6. **【R5】局限**：`n=1/臂` 只能看大效应；跨 run 数字不可直接比 ⇒ 对照必须同批次、多 seed 或拉大局数。
7. **本文件的局限**：§2 的恒等性由**源码线性性**导出（`ppo.py:168-192, 224-226, 392`），
   **未做数值验证**；若要把 §2 当判据用，应先补一个 30 行脚本做端到端数值对账（用 selftest 的合成 batch），
   标为待确认。§1.1 的表格是**本机实测**（economy 往返 + 最小 JSON 对照），可复算。

   与【R5】（同 seed 同代码两次 run 不可复现）同类：**该仪器的读数必须以"同批配对"方式使用**。
3. ⇒ 预注册要求：① 结构层仪器**固定 `--frames`**；② 判"变化"必须**同批配对**
   （同一进程内跑对照臂与干预臂，或多次重复取聚合），**禁止**拿历史的单次占比当基线；
   ③ 单项占比**不作为主判据**。

> **对照组可复现性对照**：行为层仪器（`forensics_card_usage.py`，只读回放文件、不跑 rollout）
> **本次逐位复现**了记录值（全帧圣水≥6 = 0.11%、Xbow 3 次、部署前圣水中位 3.250、同路间隔 5.500 s）
