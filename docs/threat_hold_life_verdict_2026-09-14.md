## 1 单变量改动

`rl/threat_precise.py`：`PreciseThreat` 新增**保持寿命上限** `MAX_HOLD_S = 4 × HORIZON_S = 20 s`
（每实例可覆盖，`max_hold_s=inf` = 关闭该机制）。到期 ⇒ 保持失效；若触发条件仍成立，
**同一帧**重新推演一次（刷新），否则回退粗糙值直到下一次上升沿。
**不动**触发条件、折常量、半场口径、默认开关（仍默认关闭，【R2】）。顺带删掉了未使用的 `HOLD_FRAMES`。

## 3 ⚠️ J1/J3 不能用原口径判：跨 run 比较被【R5】污染

J1/J3 的写法是「跑一次新配置，与上一轮旧配置的数字比」。但【红线 R5】明确：**同 seed 同代码的
两次 run 也不可复现**，跨 run 之差不可归因。本轮我实测到这个散布有多大：

- 同一仪器、同一协议、同一 ckpt、同一算子（规划器走粗糙口径）两次 900 帧 run，
  触发率 **2.1% vs 4.37%**（2 倍）；保持段数 37 vs 41；
- 验收协议（规划器吃精确值）三轮旧读数 **3.41/2.19/2.44**、三轮新读数 **4.03/2.90/6.23**，
  而**寿命上限的机制上限**（见 §4）只有 **+6.8% 推演次数**——**不足以把 3.41 变成 6.23**。

⇒ 正确做法是**同轨迹配对**：把「有上限」与「无上限」两个提供器挂在**同一条盘面序列**上
（两者都只做观测者，规划器走生产默认，见 `scripts/probe_hold_life_ab.py`）。

## 5 自披露（本轮我自己的三处错误）

1. **"值龄"口径被污染（原仪器）**：`probe_hold_recompute.py` 用"保持段已持续帧数"当年龄，
   但**带寿命上限后，「到期 + 同帧重算」在帧序列上仍是一个连续保持段** ⇒ 段年龄系统性偏大
   （after-run 里最大 119 帧 = 59.5 s，而真实值龄被上限封在 20 s）。新仪器改用
   `_hold_t`（该值算出的游戏时刻）直接算值龄 ⇒ §4 的 §2 数字才是对的。
2. **抽样没按方向过滤**：`probe_hold_life_ab.py` 第一版对 A/B 两个方向都记录了样本，
   而某方向可能没有精确值（`None`）⇒ 全部预测成假 ⇒ BA≡0.5 的假读数（TP=0/FP=0）。
   已改为只记录"至少一臂有精确值"的方向，并记录两臂的**实际输出**（无精确值时即该臂的粗糙回退值）。
3. **对 J1 的第一反应是错的**：我一度准备按 J1 FAIL 回退。是配对仪器（+6.8% 上限）否掉了
   "寿命上限导致摊销 2.5×"这个归因——**没有配对就没有归因**。

## 6 结论

- **保留寿命上限**：配对实测成本 **+0.26 ms/帧（+6.8% 推演）**、值龄尾部 **5.0% → 0.0%**、
  受影响桶 BA **0.2500 → 0.5417**，且前四桶**逐位不变**（无副作用）。
- 形式判决按预注册照读：**J2 PASS、J4 PASS、J1 FAIL、J3 FAIL**；其中 **J1/J3 的失败口径
  被【R5】污染 ⇒ 记为「不可判」**，不作为回退依据（配对判据替代之）。
- **真正需要处理的是另一件事**：验收协议（规划器吃精确值）下，摊销跨 run 在
  **2.90 ~ 6.23 ms/帧** 之间摆动、多次越过 3.85 预算——这与寿命上限无关（机制上限 +6.8%），
  而是**该协议下触发率的 run 间散布太大**（4.0%~8.0%）⇒ 想拿"成本达标"当验收结论，
  必须把帧数/seed 数提上去或改用配对口径。

## 7 未决 / 待办

1. **验收协议的成本判据重做**（当前 200 帧/seed、3 seed 的分辨率不足；触发次数仅 8~16 次/run）。
2. **顺手武装**（方向 B 42% 的保持段来自另一侧上升沿）仍未处理；本轮配对仪器显示它对
   寿命上限无干扰，但**它本身是否该存在**没有判据。
3. **端到端训练 A/B（开关 on/off，20k）**：仍是改任何生产默认值的前置条件（【R11】）。
4. seed 11 原方向 BA −0.240 的归因（本轮的退出分布证据 134 次 × 50.7% ≈0）**仍未定**。
