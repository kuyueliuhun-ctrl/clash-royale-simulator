# 攒费意图（intent-save）**目标归因** ＋ J1 判读仪器的**卡组缺陷**（2026-09-20）

> **起因**：用户的复核问题——「**你所谓的攒费帧，是不是依旧在为一张最便宜的卡等待？**」
> 追这个问题时先撞出**一处更严重的事故**：J1 判读跑的卡组**不是训练卡组**（§1）。
> ⇒ 旧的 J1 读数（`set=2674 / held≈37% / ready=17 / fired=2`）**作废**；本文给出重测与全新的**按卡归因**。

**三行结论**

1. **仪器跑错卡组 ⇒ 旧读数作废**（不是"偏低"，是**判据失效**）：原版审计构造 `RLEnv(opponent=None...)`
   **不传 deck** ⇒ 落到 `DEFAULT_DECK_1`（原版 8 卡，**最高 5 费、没有 Xbow**），而训练用
   `DEFAULT_SOLO_DECK`（Xbow 2.9）。⇒ J1 的「**≥6 费卡**」过滤在**那个卡组上按构造恒为 0**（**空判据**），
   且被测策略**从未见过**那副牌（**OOD**）。三层独立证据：源码 / 常量 / **录像产物**（§1）。
2. **修好卡组后重测（两 seed）：J1 仍 = 0 ⇒ FAIL 结论不变，但形状完全不同** —— 正确读数是
   **`fired = 0`（零转化）**，不是旧读数说的 `ready=17→fired=2`（部分转化）。⇒ 预注册的
   **F1 分支（`set>0 但 fired=0`）触发**，其处置**跑前就写死**（「下一刀 = M2 时长 option」）
   ⇒ 我此前"**三条分支都没覆盖、预注册有缺口**"的推论**撤回**（那是错卡组上的 `fired=2` 造出来的假象）。
3. **回答用户的问题：不是**（而且**偏反方向**）。训练卡组 20 局里，`held` 帧的
   **61.1% 落在最贵的 Xbow（6 费）**，最便宜的 Skeletons（1 费）只有 **0.2%**；在**有真实选择**的
   2,653 次下意图里，选最便宜 **38.6%** / 选最贵 **35.4%** / 中间 26.0% ⇒ **没有"只挑最便宜的"这回事**
   （未训练的 step-0 才是偏便宜 48.1% vs 25.1%）。★ 但用户的怀疑指向了一个**真实且更糟的病灶**：
   **目标抖动** —— 74.8% 的段以"换目标"结束、段均持有 **1.84 帧**、**攒够 457 段 / 真打出 0 段**（§3.4）。

## 1. 事故：J1 判读仪器跑在**错的卡组**上（三层独立证据）

| 层 | 证据（可复跑） |
|---|---|
| **源码** | `scripts/audit_intent_save.py` 的 `_run()` 原先构造 `RLEnv(opponent=None, seed=args.seed, intent_save=True)`——**不传 `deck0`/`deck1`** ⇒ 按 `rl/env_wrapper.py` 的缺省落到 `DEFAULT_DECK` / `DEFAULT_DECK_1` |
| **常量** | 训练用 `rl/train_solo.DEFAULT_SOLO_DECK`（`resolve_deck_set("default")` 的返回值）：`Xbow:6, Tesla:4, Skeletons:1, IceWizard:3, Archer:3, Knight:3, Log:2, Fireball:4`；审计实际用的 `DEFAULT_DECK_1`：`Minions:3, Archer:3, MiniPekka:4, Musketeer:4, Giant:5, Fireball:4, Arrows:3, Knight:3` ⇒ **两套卡组逐张不同；后者最高只有 5 费、不存在 `cost ≥ 6` 的卡** |
| **录像产物** | `runs/intent_on_100k/replays/league_*.pkl` 里出现的卡只有 `Xbow/Tesla/Skeletons/IceWizard/Archer/Knight/Log/Fireball`，原版 8 卡中的 `Giant/MiniPekka/Musketeer/Minions` **出现 0 次**；而旧判读的 `fired_events` 报出的却是 **`Giant`(5 费) 与 `MiniPekka`(4 费)**——**只可能在 `DEFAULT_DECK_1` 上出现** |

⇒ **同一份 `solo_main.pt`，训练/评估在 Xbow 卡组上，审计却在原版卡组上。**

### 1.1 两个后果（都不是"读数偏低"）

- **A. 空判据**：J1 原文 = 「同一张 **≥6 费**卡被 pending 覆盖 ≥34 帧后真打出」。在 `DEFAULT_DECK_1` 上
  **没有任何 ≥6 费卡** ⇒ 费用过滤**按构造恒为 0** ⇒ 无论机制多好都只会打印 FAIL；
  连"34 帧阈值"对应的那张牌（Xbow = 6 费 ÷ 0.3571 圣水/s ÷ 0.5 s/帧 ≈ 33.6 ≈ 34）都**不在场上**。
- **B. OOD**：B 臂策略在 Xbow 卡组上训练，`DEFAULT_DECK_1` **从未见过** ⇒
  `set/held/ready/fired` 描述的不是训练分布下的行为；"机制被大量使用"这句的**量级也不可信**。

★ 这是**我自己的仪器缺陷**，且它与判据缺陷**叠加**：一个空判据 + 一个 OOD 被试，
合起来让"J1 FAIL"这个判决既**必然**（空判据）又**无意义**（OOD）。

## 3. ★ 目标归因：回答「是不是依旧在为一张最便宜的卡等待？」

仪器：`scripts/probe_intent_target.py`（新增）。**口径**：`RLEnv(deck0=deck1=DEFAULT_SOLO_DECK)`、
随机对手、20 局 × 400 帧、seed 0、按分布采样（与判读仪器同协议）；**逐段归因**：pending 槽 → 卡名/费用；
段 = pending 从设到结束；`held` = **env 口径**（判定列取 env 自己的 `_intent_age` 最大值
= `intent_stats["held"]` 的同源计数器，**不含每段的 set 帧**）。

**对账（每次运行都打印在 ⑤）**：`held env=3151 / 本仪器=3151 ⇒ 一致`、`set env=2977 / 意图段=2977`、
`fired env=0 / 逐段=0` ⇒ **仪器与被测系统的计数器逐值相等**（这一行是首版缺的那一步，见 §5.1）。

### 3.1 逐帧归因（= 表 B）

**最贵的 Xbow 占 61.1% 的 held 帧；最便宜的 Skeletons 占 0.2%。**
`held` 的**费用构成**：`1-2 费 = 1.5%` ｜ `3 费 = 8.7%` ｜ `4 费 = 28.9%` ｜ **`6 费 = 61.1%`**。

### 3.2 ★ 判据性统计：**有真实选择**时它挑了谁（仪器**自己**打印这一行，`③★`）

「最便宜的买不起的卡」这个比例**单独看会骗人**：当下意图那一刻**只有一张牌买不起**时，
"最便宜"与"最贵"必然是同一张。故只在**有真实选择**（买不起的槽 ≥ 2 **且**它们的费用不全相同）时统计：

| 统计 | @100k（训练后） | @step0（同架构、未训练） | vanilla 卡组（旧读数的来源） |
|---|---:|---:|---:|
| 有真实选择的 set 事件 | 2,653 / 2,977（**89.1%**） | 3,114 / 3,318（93.9%） | 2,190 / 2,466（88.8%） |
| 选**最便宜**的买不起的卡 | **38.6%** | **48.1%** | 43.1% |
| 选**最贵**的买不起的卡 | **35.4%** | 25.1% | 32.8% |
| 选中间 | 26.0% | 26.8% | 24.1% |

⇒ ① 在**训练后**的 B 臂上，"最便宜"与"最贵"几乎**打平**（38.6% vs 35.4%，仪器自己的判词 = **基本打平**）；
② **未训练**时确有"挑最便宜"的偏向（48.1% vs 25.1%，仪器判词 = **偏便宜**）
⇒ **训练把目标偏好推向了贵牌**（描述性，n=1/臂）；
③ 所以**"依旧在为一张最便宜的卡等待"不成立**——包括错卡组上的旧读数也不是这样。

### 3.4 病灶不是「攒错牌」，而是「**目标抖动**」

| 指标（训练卡组 @100k） | 值 |
|---|---|
| 意图段数 | **2,977**（7,203 帧 ⇒ **每 2.4 帧换一段**） |
| 段均 held | **1.84 帧**（中位 1 帧） |
| held 分布 | `≤1 帧 = 2,398 段（80.6%）`｜`2-3 = 313`｜`4-9 = 210`｜`10-19 = 56`｜`≥20 = 0`｜**`≥34 = 0`** |
| **段结局** | **`switched`（换目标）= 2,228（74.8%）**｜`cancelled = 423`｜`dropped = 311`｜`open = 15`｜**`fired = 0`** |
| Xbow 段（1,047）结局 | `switched 698`｜`cancelled 201`｜`dropped 142`｜`open 6`｜**`fired 0`** |
| **攒够（ready）的段** | **457**；其中 **真打出 = 0**（**100% 转化丢失**） |
| 那 457 段的 ready 时长 | **448 段只有 1 帧 ready 就结束了**、8 段 2 帧、1 段 3 帧 |
| 对照 @step0 | 段均 held 0.65；ready 348 / fired **6**（1.7%）；fired 全是 ≤4 费且 held ≤1 |
| 对照 vanilla 卡组 | ready 350 / fired **1**；`switched` 80.8% |

⇒ 一句话：**43.7% 的帧"有一个想攒的牌"，但几乎没有一帧真的把它攒下去**——
模型**每 ~2.4 帧就重新选一次攒费目标**，而"攒够"的那一刻（448/457 只维持 1 帧）**恰好是它松手的地方**。
这与我在代码里已记录的**设计缺口**一致：`ready` 一出现 `pending` 就被清、花费合法性立刻恢复
⇒ **目标卡在"攒够那一帧"不再被特权化**，策略必须凭记忆主动选它。

### 3.5 缺口（`gap`）分布与一处口径说明

`gap = 费用 − 圣水`（下意图那一刻）：`≤0.5 = 361`｜`0.5-1 = 392`｜`1-2 = 731`｜`2-3 = 668`｜`3-4 = 386`｜`≥4 = 285`
⇒ **48.3% 的下单发生时缺口 ≥ 2 圣水**（不是"只差一点就买得起"的小修小补）。
⚠️ 另有 **154 段（5.2%）的 `gap ≤ 0`**（落进打印里的 `?` 桶）：这是仪器 docstring 已声明的
**"用步后圣水近似"**——`info` 读取时刻比掩码判定晚、圣水已回一帧 ⇒ 这类段按"已买得起"落在
`ready` 侧，不计入 `held`。

### 5.1 一路修掉的两个**仪器自身**缺陷（都在本文留痕）

1. **终点帧事件丢失**：段在 `fired/cancelled/dropped` 的**同一帧**被清槽，若先按"槽变了"关闭段，
   本帧事件就记不到该段上 ⇒ 首版把 **999 段 Xbow 全记成"换目标"**、`fired/cancelled = 0`。
   修法：**先结算本帧事件，再判是否关闭段**。
2. **`held` 口径自造**：逐帧 `info["intent"]["hold"]` 与 env 的 `intent_stats["held"]` **不是同一个量**
   （env 不计每段的 set 帧；且 step 内 `_apply_intent` 与 `info` 构造之间圣水可能已变）
   ⇒ 首版同协议下报 **5630 vs env 2932**。修法：判定列改用 env 自己的 `_intent_age`

## 6. 未定 / 口径限制（【R10】）

1. **n = 1/臂**：所有归因都是**描述性的**（B 臂终点 vs 其自身 step-0），**不得**写成"训练让它学会了攒费/没学会"的因果断言（【R5】）。
2. **随机对手**：判读仪器用的是随机对手（与训练分布不同）；录像旁证（§4）用的是 `frozen_copy` ⇒ 两处**不可对拍**。
3. **`gap` 用步后圣水近似**：误差 ≤ 1 帧回费（0.1786 圣水），已声明（§3.5 的 5.2% `gap ≤ 0` 就是它的直接读数）。
4. **未定**：「目标抖动」是策略层面的（换目标无成本）还是**实现层面**的（`SAVE` 每帧都能重选、`CANCEL` 免费）
   ⇒ 本仪器**分不开**；要分开需一条"禁止中途换目标"的对照臂。
5. **未定**：`ready → 0 打出` 是"松手缺口"单一原因，还是也含"策略根本不想打 Xbow"⇒ 需把
   `ready` 帧继续特权化（或 pending 保留到真打出）后重跑同一仪器对照。
6. **不得**引用旧读数：`set=2674 / held≈37% / ready=17 / fired=2 / fired_held∈{2,4,6}`
   以及由此推出的"第四种情形 / 预注册缺口"**全部作废**（见 §7 勘误）。
