## §0 动机：行为取证提出的因果候选

`docs/replay_behavior_forensics_2026-09-14.md` 把策略行为定量了：

| 事实 | 数字（`d1_long_100k`，440 局） |
|---|---|
| 唯一赢牌手段 Xbow 出手 | **3 / 9806（0.03%）** |
| 5 张费 ≤3 的便宜卡占比 | **95.47%** |
| 部署前圣水 ≥6 的占比 | **0.02%** |
| 全部帧（含不出手帧）圣水 ≥6 的占比 | **0.11%** |

**为什么一个 PPO 策略会退化成"只打便宜牌、从不攒费"？** 第一个该排除的候选是
**奖励塑形**——如果逐帧奖励的**主要量级来自"资源账"（`elixir_diff_weight` 项的
ΔΦ，Φ = 手牌圣水 + 场上部署费）**，那么策略实际上在优化"资源对账"而不是"赢"，
"从不攒费"就是这个目标的直接后果。

**读源码得到的先验（写在这里，是为了让后面的读数可被质疑）**：

- `reward = 8.0·Δcrown_opp − 10.0·Δcrown_me + 0.001·塔伤_opp − 0.0012·塔伤_self
  + 0.0·my_elixir + edw·Δ(Φ_me − Φ_opp) + 0.0005·(敌单位掉血 − 我单位掉血)
  + 10/胜负 − 10/平 − 0.05·非法次数`（`rl/env_wrapper.py:181 compute_reward` + `:701`）
- `edw = 0.5`（t<120s）/ `0.1`（t≥120s）；`elixir_bonus = 0.0`（那一项**恒为 0**）
- **对非法术部署，ΔΦ = 0（E−c 与 V+c 同帧抵消）⇒ 下牌不罚、也不奖，与卡费无关**
  ⇒ "打便宜牌"**不能**由这一项直接解释；
- **但法术（Log / Fireball）走"成本挂 E 账、产物免费"**（`_deploy_ledger` 对 spell 提前
  return）⇒ **每次施法 Φ 直接下降 edw×费用**，只有打死敌方单位才由 `ΔΦ_opp` 找回。

⇒ 所以"奖励主导"这个候选**未必成立**，必须**测**，不能推。

## §2 方法（引擎真值，不做重建）

**不**从回放重建（回放的 `field_v` / 单位掉血都缺）。改用**引擎自己的函数**：

1. 在内存里把 `rl.env_wrapper.compute_reward` 包一层记录器（**不修改磁盘上的代码**）：
   对同一组输入额外算出 5 个变体——`full` / 去掉 `edw` 项 / 去掉 crown 项 /
   去掉塔伤项 / 去掉终局项。每项都是**权重线性**的 ⇒ 差值是**精确项**，不是近似。
2. 用 `runs/d1_long_100k/solo_main_100000.pt` 跑一次 stoch rollout（**CPU**，
   `--frames 4000`，`seed 7`），逐帧记录 6 个量：
   `full`（= 单位项之前的奖励）、`edw`、`crown`、`tower`、`terminal`、`step_reward`；
   单位项 = `step_reward − full`（`env_wrapper.py:701` 在 `compute_reward` 之外加）。
3. 读 `info["field_v"]`、双方圣水、`t`。

**为什么用 CPU**：GPU 上还有 `probe_value_ln.py` 在跑（【红线 R1】精神：不制造资源争用）。
本探针是**描述性分解**，不需要 GPU。

## §3 判据（跑前写死）

设 `A = Σ|edw|`、`B = Σ|tower|`、`C = Σ|crown|`、`D = Σ|unit|`、`E = Σ|terminal|`，
`S = A+B+C+D+E`（全部绝对值之和）。

| 分支 | 条件 | 判决 | 含义 |
|---|---|---|---|
| **W1** | `A / S ≥ 0.50` | **奖励被资源账主导** | "从不攒费 / 只打便宜牌"有了奖励侧根因；"上限不动"的首要候选从网络转到**奖励设计** |
| **W2** | `B / S ≥ 0.50` | **奖励被塔伤主导** | 奖励侧不是根因 ⇒ 行为病理出在优化/探索侧 |
| **W3** | `E / S < 0.10` | **终局信号被淹没** | 与 W1/W2 **并行成立**（不是互斥分支）：胜负只贡献 <10% 的量级 |
| **W4** | 以上都不成立 | **无主导项**（描述） | 只描述分量分布，不下因果结论 |

> W1/W2 互斥（`A+B ≤ S`，不可能同时 ≥0.5S 除非 A=B=0.5S 且 C=D=E=0——按 `≥` 记为同时命中，
> 届时记 `W1+W2` 并**不判决**）。W3 独立判定。
> **反预注册声明**：落地读数若落在四行之外，一律 `NOT_PREREGISTERED`，只作描述。

## §4 次要描述量（不参与判决）

1. **分期占比**：t<120s（edw=0.5）与 t≥120s（edw=0.1）两段的各项占比——验证"双倍期切价"是否真的改变结构。
2. **每帧平均 |reward|** 与各项每帧均值（带符号）——看是否存在**系统性偏移**（例如 edw 项长期为正/负）。
3. **Φ 轨迹**：`Φ_me = elixir0 + field_v[0]`、`Φ_opp`、`ΔΦ` 的分布；策略是否长期"Φ 落后"。
4. **法术账**：施法帧的 `edw` 项均值 vs 非施法帧 —— 验证"法术直接扣 Φ"这条机制。

---

## §5 局限（预先声明）

1. **单 ckpt / 单 seed / 4000 帧**（≈18 局）；只报**该策略在该段**的分量结构，不跨 run 比。
2. 分解是**权重线性**意义上的精确项；但项与项之间存在**行为耦合**
   （例如改 edw 会改变策略行为）⇒ **本探针只能证明"信号结构的量级归属"，不能证明因果**。
   要证因果必须做**单变量消融**（改 `elixir_diff_weight` 重训），本探针的输出只用来决定
   **值不值得做那个消融**。
3. CPU rollout 的 `frames` 以内含的完整局为准（末局不完整则丢弃，与其它探针一致）。
4. **`unit` 项由差值得到**（`step_reward − full`），依赖"`step` 里除单位项外不改 reward"这一
   当前实现事实；脚本会断言 `|差值| ≥ 0` 且打印其量级，若出现异常符号则整体记 `NOT_PREREGISTERED`。
