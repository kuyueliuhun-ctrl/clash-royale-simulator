## 2. 可证明安全的地理剪枝（路线 C 的第一级）

**判据**：对每个敌方非塔单位 `u` 算到达我方最近塔的**下界时间**

```
t_a(u) = max(0, 直线距离(u, 最近塔) − 射程(u) − 拉拽余量) / (移速(u) × 移速余量)
若 min_u t_a(u) > H  ⇒  该视界内物理上不可能接触塔  ⇒  精确塔伤 = 0
```

**为什么是可证明的**（不是近似）：
- 直线距离 ≤ 引擎实际路径长度（路径必绕行）⇒ 用直线**低估**到达时间；
- 射程取该单位**自身**射程（可从其射程外开始输出）；
- 移速乘 `1.5×` 余量（狂暴类加成）、距离再减 `2.0` 格（钩爪/击退类一次性位移）。

**保守豁免**（任一命中 ⇒ 该单位不可剪枝，`t_a := 0`）：移速 ≤0/未知、建筑、有周期出兵
（`summonCharacterData.spawnCharacterData` + `spawnPauseTime`）、有亡语出兵（`death_spawn_data`）、
觉醒态。（依据均为**引擎自身**的出兵管线：`battle.py:247-300`。）

### 2.1 实测结果

| H (s) | 剪枝率 | 需调用率 | **可靠性反例** | 摊销成本（含 T2） |
|---|---|---|---|---|
| 3 | **51.2%** | 48.8% | **0** | 21.3 ms（未叠加采样） |
| 5 | 32.2% | 67.8% | **0** | 34.0 ms |
| 8 | 17.5% | 82.5% | **0** | 56.3 ms |
| 20 | 15.5% | 84.5% | **0** | 86.6 ms |

**可靠性反例 = 0**：在 205/129/70/62 个被剪枝的帧里，引擎实测塔伤**恒为 0**
⇒ 剪枝没有漏掉任何真实威胁。T1 自身成本 **0.0043 ms**（可忽略）。

> **自披露（我自己的参数选错）**：第一版剪枝把"**全卡池最大射程 11.5**"与
> "**拉拽余量 8.0**"一起从距离里减掉 = **19.5 格 ≈ 半张地图**，导致 315/400 帧都判 `t_a=0`、
> 剪枝率只有 **19.8%**，我据此一度得出"剪枝不可行"。改为**每个单位自身的射程** +
> 适度余量（2.0 格 / 1.5×）后剪枝率升到 **51.2%**，可靠性反例仍为 0。
> 第一版的数字与结论已作废。

### 2.2 单独剪枝不够，必须叠加采样保持

H=3s 时剪枝后仍需调用 48.8% 的帧 ⇒ 摊销 13.8~21.3 ms，**仍超预算 3.6~5.5 倍**。
⇒ 必须叠加路线 B 的采样保持。

## 3. 采样保持的滞后误差（路线 B/C 的第二级）

"每 K 帧才调一次精确工具、其余帧沿用旧值"造成的闸门误判率：

| H | 真值口径 | K=4 | K=8 | K=16 | K=32 | 逐帧翻转率 |
|---|---|---|---|---|---|---|
| 3 | E>0 | 5.8% | **11.8%** | 25.2% | 30.8% | 3.8% |
| 3 | E≥434 HP | 4.2% | **7.8%** | 19.8% | 20.8% | 3.5% |
| 5 | E>0 | 6.0% | 10.0% | 21.0% | 32.0% | 4.3% |
| 20 | E>0 | 5.8% | 8.2% | 14.8% | 17.8% | 3.8% |

**闸门本身逐帧翻转率只有 1.8~4.3%**（很好），所以滞后误差主要来自缓慢漂移而非跳变。

### 3.1 路线 C 的合成预算（H=3s + 剪枝 + K=8）

```
摊销 = T1(0.004) + 剪枝后需调用率(48.8%) × 单次成本(28.2 ms) / K(8)
     ≈ 0.004 + 0.488 × 28.2 / 8  ≈  1.72 ms/帧
```

⇒ **占训练帧 38.5 ms 的 4.5%**（预算 10% 内，余量 2.2×）。
**决策误判率 ≈ 11.8%（E>0）/ 7.8%（实质威胁）**，对照近似公式的硬矛盾率 **24.3%**。

**⇒ 路线 C 是可行的：误差至少减半，成本在预算内。**

## 4. 路线 C 的**语义代价**（必须先说清，不能藏）

1. **视界从"默认 20 s"变成 3 s**。3 s 回答的是"**未来 3 秒会不会掉塔血**"，
   而不是"敌方这波推进有多强"。⇒ 直接替换会让 `PRESSURE_THRESHOLD = 2.0` 的触发率
   **大幅下降**（远端单位一律判 0），`_setup_wait` / `plan():799` 的防守分支会更少触发。
   **这是行为语义的改变，不是无损替换。**
2. 因此 **【R7】** 要求：`HP_PER_PRESSURE` 折算常量必须**单源**且**重新标定**，
   且 `PRESSURE_THRESHOLD = 2.0` 与 `threat ≥ 0.8·my_pressure` **不得改动**（保持接口不变）。
3. `value_estimate = tanh(my_pressure − threat)` 这一维（plan 58 维之一）会随之改变分布；
   近似版已有 **30.2% 的帧 tanh 饱和**（P3-1 §3.1），新刻度若不匹配会让饱和更严重。
   ⇒ 折算常量必须让新标量的分布与旧标量**同量级**（等阳性率/等中位标定），否则这一维退化。

## 6. 局限（【R10】）

- 单 rollout（400 帧，随机对手）、单 seed、单 ckpt；剪枝可靠性"反例 0"是**这一批帧**上的读数，
  不是全称证明（全称证明依赖对引擎加速机制枚举的完备性，未做）⇒ 必须**常驻 selftest**（§5.4①）。
- 成本数字来自本机当时状态，可能受 CPU 竞争影响；`probe_search_cost.py` 记录的 2.4 ms/模拟秒
  与这里的 7.5 ms/模拟秒**口径不同**（后者含 `deepcopy` + 每 tick 的 `_hostiles_present` 全实体扫描），
  **差异未完全归因，标"待确认"**。
- 未测 `_closest_threat`（共享同一粗糙公式）；未测 cell decoder 侧。
- 采样保持的 K=8 是**按成本预算反推**的上界选择，未做"K 对最终行为/性能影响"的端到端实验。
