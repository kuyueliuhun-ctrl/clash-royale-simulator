# 预注册：IL 的「不够」是算力/步数问题吗？—— BC 预算剂量-反应（epochs × lr）

> **状态：本文件在跑任何一格之前写完**（【R3】：判据跑前写死，含失败分支）。
> 上游判读：[`docs/fl_il_2026-09-20.md`](fl_il_2026-09-20.md)；上游预注册：[`docs/fl_il_prereg_2026-09-20.md`](fl_il_prereg_2026-09-20.md)。
> 一句话：用户判断「**IL 还不够，要更多轮训练或者调高学习率**」。本实验把这个判断变成**可证伪的**：
> 固定数据/口径/初始化，只动 `epochs` 与 `lr`，看留出集读数**是否出现实质改善**——而**不是** NLL 下降。

---

## 0. 一句话判据

**预算能不能买到「卡牌选择」？** 若不能（NLL 掉、slot 选择仍不超随机），则「IL 不够」在本数据/本损失/本口径下**被否证**，
缺口被判到**数据与损失形态侧**（§6 F5′），而不是「再跑几轮就好了」。

---

## 2. 单变量与不变量

* **只动两个量**：`epochs`、`lr`。其余**逐字不动**：数据目录、样本顺序、模型结构（`hidden=128` / `plan_dim=58` / `belief_dim=563`）、
  `batch=1`、Adam、损失 = `-logprob`、`hidden=None`（逐帧，与 `human_play.py:224` 同口径）、掩码重建同 `il_eval_holdout.py`。
* **同初始化、同样本序**（【R17】分子/分母同超参约定）：每格开跑前 `torch.manual_seed(0)` + `np.random.seed(0)` ⇒ 各格**同初值、同 permutation**；
  唯一差别是训练强度。⇒ 差异只能归因于预算，不能归因于抽签。
* **不改既有代码**（承接上游 §5.3 不变量）：新增 `scripts/il_bc_sweep.py`（复刻 `human_play.py:205-233` 的训练循环，逐行同序），
  `human_play.py` / `follower.py` / 掩码一行不改。**F0 检查**见 §4。

## 3. 剂量表（先跑的先看，不回头改阈值）

lr 固定 1e-3 的**步数轴**，与 epochs 固定 10 的**学习率轴**：

| 格 | epochs | lr | 角色 |
|---|---|---|---|
| **M0** | 3 | 1e-3 | **对照 = 复现已提交 ckpt**（F0 等价性检查） |
| M1 | 10 | 1e-3 | 步数 ×3.3 |
| M2 | 30 | 1e-3 | 步数 ×10（若 M1 仍单调，才值得等） |
| M3 | 10 | 3e-3 | lr ×3 |
| M4 | 10 | 1e-2 | lr ×10（**发散探针**） |

**早停规则**（跑前写死）：M1 若 `nll ≥ M0.nll − 0.05` **且** top1 未升，则 **M2 照跑不误**（不能以「没动」为由跳过最关键的步数格），
但 M4 可降级为只记 `mean_logprob` 曲线；反之若 M3 出现 `nll` 暴涨（>`M0.nll + 0.5`）则 M4 只为**定发散阈值**记录。

## 4. 判据

### F0（仪器/复刻缺陷，先于一切）
`il_bc_sweep.py` 的 M0（3 ep / 1e-3）必须复现已提交 ckpt 的留出读数：
`nll ≈ 5.596222589020527`、`top1 ≈ 0.40419060493409936`、`cell_exact_given_option ≈ 0.120958751393534`。

* **容差 = 绝对 5e-4**（不是 1e-9），理由（**跑前写死**）：本实验的各格以 `--threads 1` 运行
  （见 §7 实测：batch=1 是**开销瓶颈**，1 线程与 8 线程每步耗时相同 11.5 ms，故用「多进程 × 单线程」提吞吐），
  而已提交 ckpt 是 torch 默认线程数（8）跑的 ⇒ 归约顺序不同会引入 ~1e-7 级差异，经 3 个 epoch 反向传播可放大到 1e-4 量级。
  该差异**语义无关**；而**语义缺陷**（漏播种 / 换样本序 / 漏 `hidden=None` / 漏 `zero_grad`）会给出 **≫0.01** 的偏离。
  一并核对 M0 的逐 epoch `mean_logprob` 曲线与日志 `bc_train.log`（-5.973 / -5.725 / -5.612）**逐值 ≤0.01**。
* **不满足 ⇒ F0 成立，全部结论作废**，先修仪器。

### J-M1（弱式：预算还买得到 NLL 吗）
在 lr=1e-3 的**步数轴**上：`nll(3) > nll(10) > nll(30)`（**单调**），且 `nll(3) − nll(30) ≥ 0.28`（≈5% 相对）。
*阈值依据*：上游 3 个 epoch 的**训练** `mean_logprob` 逐 epoch 降幅为 0.248 / 0.113（5.973→5.725→5.612），
0.28 落在「一个 epoch 的量级」之上、不靠单点观测标定（【R15】【R16】）；并附**配对**（同 8,877 条）逐样本 NLL 差的中位数与胜/负计数。
PASS ⇒ 「算力/步数**仍有边际**」；FAIL ⇒ 3 epoch 已到该数据的 NLL 平台。

### J-M2（强式：预算买得到「卡牌选择」吗 —— **本实验的实质判据**）
**合取**，任一项不满足即 FAIL，全部用**同一 run 的读数**：

1. `top1_option ≥ 0.39844542075025347 + 0.05 = 0.4484`（trivial 恒选槽 4 + **5 pp**）。
   *5 pp 的依据*：上游实测只超 trivial **+0.58 pp**；5 pp 是它的 8.6 倍，且 > `_force_hand` 造成的人为槽 4 抬升（9.3 pp）的一半
   ⇒ 再小就分不清「学到选择」与「跟着先验走」。
2. **槽 1/2/3 的 recall 全部高于同脚本随机初始化基线**：`> 0.41054 / 0.35213 / 0.34661`。
3. 槽 1 recall `≥ 0.45`（比随机基线 0.41054 高 ~4 pp）。

PASS ⇒ 「IL 不够」**成立**，预算确实能买到选择，下一刀 = 加数据/加轮数；
FAIL ⇒ §6 F5′。

### J-M3（学习率方向，描述性 + 健康度）
对 M3/M4：报 `nll` 剂量-反应与 `logprob < -1e8` 计数（必须为 **0**；非 0 = 样本落出掩码支撑集，读数不可用）。
判读口径：**lr 提高只是更快到达同一个平台**，还是**到达不同的平台**（发散/更差）。**不作为**「IL 不够」的证据。

### J-M4（行为面，描述性，非闸门）
对 J-M2 表现最好的格子，用 `scripts/il_readout_games.py --decks solo --hidden none --games 10` 跑一遍，
与上游 §12 臂 A（3 ep 对照）比：出牌数 / 牌种类分布 / `stop_when_playable`。**只作观测，不构成判决**（n=10、同源对手、R5）。

### J-M5（描述性，非闸门：算力买到的**是哪一项**）
`FollowerPolicy.evaluate` 返回的是一个和（`follower.py:887-928`）＝ `log p(选牌) + log p(落点) + log p(终止)`；
本仓每帧恰 1 子动作 ⇒ 三项可分离。`scripts/il_nll_decompose.py` **不改 `follower.py`**，而是**复刻**该前向并自带闸门：

* **复刻一致性闸门**：逐帧 `|三项之和 − evaluate 的 lp| ≤ 1e-5`，否则脚本退出码 3、该格读数**作废**。
  （实测：committed ckpt / random-init 两次探针均 `max|Δ| = 9.54e-07` ⇒ 闸门通过。）
* **★ 勘误（2026-09-20 15:09，在**任何扫参结果到达之前**、M0 的第 1 个 epoch 刚落地时）**：
  本小节初稿把参考值写成「恒选槽 4 的 NLL `−ln(3537/8877) = 0.9200 nats`」——**这是错的**：
  恒选槽是**确定性**预测器，它在被它选错的 60.2% 帧上 NLL `= +∞`；`−ln 0.3984` 不是任何合法预测器的 NLL。
  正确的「只依赖先验」下界 = **槽标签经验熵 `H = 1.3219 nats`**（不看特征的最好 NLL）。判读口径随之更正为
  `nll_slot` vs `H`：`nll_slot ≈ H` ⇒ 只用了先验；`nll_slot < H` ⇒ 用上了帧特征（条件信息 ≥ `H − nll_slot`）。
* **（追补）归因口径**：`Δnll_x = nll_x(随机初始化) − nll_x(ckpt)`，份额 `= Δnll_x / Δnll_total`。
  **探针预跑读数**（committed 3-epoch ckpt vs 随机初始化，**先于任何扫参结果**）：

  | 项 | 随机初始化 | 3 ep / 1e-3 | Δ（学习量） | 占 Δtotal |
  |---|---|---|---|---|
  | 选牌（slot） | 1.4350 | **1.2025** | 0.2325 | **7.6%** |
  | 落点（cell） | 5.6429 | **4.3937** | 1.2492 | **40.9%** |
  | 终止（stop） | 1.5707 | **0.0000** | 1.5707 | **51.5%** |
  | **合计** | 8.6486 | **5.5962** | **3.0524** | 100% |

  ⇒ 超过一半的 NLL 改善花在「**出完一张牌就 STOP**」这个**数据集自带的平凡模式**上（本仓每条标签恰好 1 个子动作），
  落点占四成，**选牌只占 7.6%**。参考值：`uniform6 = 1.7918`、先验下界 `H(槽) = 1.3219`、
  均匀撒在合法格上 `= 5.6279`（≈ 随机初始化的落点项 5.6429 ⇒ 未训练落点头 ≈ 均匀）。
* **判读口径（更正后）**：
  - 若扫参把 `nll_slot` 压到 `H = 1.3219` 以下**更多**（当前 1.2025，已比先验下界低 0.1194）**且**逐槽 recall 起色 ⇒ 预算买到了选择；
  - 若 `nll_slot` 基本不动而 `nll_cell`/`nll_stop` 继续降 ⇒ **买到的仍是落点与平凡终止**（F5′ 的 nats 版证据）。

### J-M6（不变量：跨进程确定性 + 把「更多轮」做成**曲线**）
* **曲线**：M2（30 ep / 1e-3）逐 epoch 落快照（`--save-every 1`；只序列化参数、**不消耗任何 RNG** ⇒ 不影响轨迹），
  留出读数在 `{1,2,3,5,10,20,30}` 上取点 ⇒ 「更多轮」是**曲线**，不是单个终点。
* **跨进程确定性闸门**（仪器 `scripts/il_ckpt_equal.py`，PASS 条件 = 逐张量 `torch.equal`）：
  各格同 seed ⇒ 同初值、同 permutation 序列 ⇒ **M2@3 快照必须与 M0 的 ckpt 逐张量相同**、
  **M2@10 必须与 M1 相同**（逐张量报告；「几乎相同但不 equal」同样报 FAIL）。
  不成立 ⇒ 存在未控随机源 ⇒ 各格之间**不得**做单变量比较，全部判据降级为**描述性**。

## 5. 失败分支（跑前写死）
* **F0**：M0 复现不上 ⇒ 复刻语义有差，先修仪器，本实验结论作废（不写「预算无用」）。
* **F5′（核心失败分支）**：J-M1 PASS 而 J-M2 FAIL（NLL 掉，槽选择仍不超随机）⇒
  **「IL 不够（步数/lr）」在本数据 + 本损失 + 逐帧口径下被否证**。缺口判到（**按优先级**）：
  1. **`_force_hand` 先验偏移**（槽 4 人为 +9.3 pp）⇒ 标签分布本身在教「选槽 4」；
  2. **逐帧无历史**（`hidden=None`，L6）⇒ 卡牌选择的证据在时序里，单帧克隆**在原理上**学不到；
  3. **损失未加权/无时序结构**（逐样本 `-logprob`，batch=1）；
  4. 标签量（47,715 条）是否够——**只有**在前面三条被排除后才轮到。
* **F6′**：M4（lr 1e-2）发散（nll 暴涨 / `logprob<-1e8` 非 0）⇒ 记录发散阈值，**高 lr 不是通路**，不代表步数无用。
* 任何一格出现 `logprob < -1e8 > 0` ⇒ 该格读数**降级为描述性**（不可与其它格并列比较）。

## 6. 成本与留证

* 预算：batch=1 / CPU。**跑前环境标定**（本机 16 核 / 15 GB，实测）：
  * 单步 fwd+bwd = **11.5 ms**（`scripts/il_bc_bench.py`，417 样本 ×300 步）；`threads=1` 与 `threads=8` **无差别**
    （11.55 / 11.73 / 11.68 / 11.37 ms）⇒ **开销瓶颈**，加线程无用、**多进程单线程**才是吞吐路径。
  * 每进程 RSS **2.49 GB**、加载训练集 1.6 GB 仅 2.1 s（页缓存热）⇒ 4 进程 ≈ 10 GB，安全。
* **执行方案（跑前写死）**：4 个并行进程、全部 `--threads 1`、逐格一格一进程 ⇒ 结果**按格独立落盘**：
  P1=M0(3,1e-3) / P2=M1(10,1e-3) / P3=M2(30,1e-3) / P4=M3+M4(10:3e-3 然后 10:1e-2)。
  预估墙钟：M0 ≈16 min、M1/M3/M4 ≈55 min/格、M2 ≈2.5–3 h（**最长杆**）。超预算**只砍 M2**，M1/M3/M4 必跑；
  若 M2 未跑完而 M1 已给出清晰读数，按「M2 未完」如实报告，**不得**用 M1 的结果替代 M2 的判据。
* **执行期实测修正（跑前记录）**：单 epoch 实测 **≈7.5 min/格**（11.5 ms × 38,838），比上一条预估慢 ~1.4× ⇒
  实际墙钟 M0 ≈23 min、M1/M3/M4 ≈75/150 min、M2 ≈3.8 h。因此 **M2 以 `--save-every 1` 重启**（见 J-M6）：
  其 epoch 快照同时给出曲线与「跨进程确定性」验证，被砍的代价因而降到最低。
