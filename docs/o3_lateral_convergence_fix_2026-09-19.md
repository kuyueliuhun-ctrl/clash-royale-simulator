## §1 成因：一条**严格相等**的 tie，被我方 2026-09-10 的改动制造出来

### 1.1 实测现象（原版引擎，`behind_king` 局，左道某只）

单位位置随时间的走向：`(6.7,0.5) (5.5,0.8) … (6.0,5.0) (6.0,7.1) (6.0,9.2) (6.0,11.3)
(6.0,13.4) (4.9,15.0) (4.5,17.1)`
⇒ **x = 6.00 一条垂直线走到 y≈13.4，最后 1.6 格里才横移 1.1 格。**
上游同一场景：`(7.0,2.5) (5.5,4.0) (5.2,5.7) (4.8,7.7) (4.3,9.6) (4.3,11.7) (4.2,13.9)` ⇒ 持续收拢。

### 1.2 dogleg **在 A\* 路径里**，不是跟随方式造成的

`scripts/_path_shape_probe.py` 直接打印 `Troop.path`（46 点全量）：

```
(5.75,0.75) (5.75,1.25) … (5.75,13.75)   ← 27 点，垂直直线
(5.25,14.25) (4.75,14.75) (4.25,15.25)   ← 3 个斜步，集中在末段
(4.25,15.75) … (4.25,22.75)
(4.75,23.25)
```

### 1.3 为什么 A\* 会这么选：**代价严格相等**

8 邻接网格里，斜步 = `14 × tile`、直步 = `10 × tile`；`1`/`2`（车道走廊）与 `.`（走廊外）
在原版里**同价 5**。于是把 3 个横向单位位移放在**哪一段**都完全等价：

| 路径 | 组成 | 代价 |
|---|---|---|
| 早收拢 | 3 斜 + 26 直 | `3×70 + 26×50` = **1510** |
| 晚收拢（实测） | 26 直 + 3 斜 | `26×50 + 3×70` = **1510** |

⇒ **不是"错"，是"等价"**：A\* 只按堆内 tie-break 出结果，于是「直走到底再拐」。
我方 2026-09-10 把 `.` 从 8 改成 5 的注释自称「代价相同，单位保持部署时的横向车道」——
**代价相同正是 dogleg 的来源**。

### 1.4 离线判定（同一张 tilemap、同一起终点、同一份 A\*）

`scripts/_astar_cost_compare.py`（纯 stdlib，不碰引擎），起点格 `(11,1)`、终点格 `(9,46)`：

| 变体 | 路径 x 随 y | 形状 |
|---|---|---|
| **我方现状**：`.`=5、`W`=800、河带只放行两条桥 | `11,11,11,11,13,13,13,9,8,8,8` | 直走，**中途还往右偏**，末段才拐 |
| **上游**：`.`=8、`W`=50、河面可走 | `11,11,9,9,8,8,8,8,7,7,7` | **全程逐步收拢** |
| **只改代价**：`.`=8、`W`=800、河带只放行两条桥 | `11,11,9,6,5,5,5,5,6,6,6` | 更早收拢 |

⇒ **成因 = 代价表抹掉了 `1`/`2` 走廊相对 `.` 的 3 点价差**（不是可走性，也不是跟随方式）。
恢复价差后，「越早进入通往桥口的正对走廊越省」成立 ⇒ 横向收拢成为**本征最优**。

同时这也解释了「中途往右偏」：全图同价时 A\* 会在等价路径间乱走，看起来就是**寻路混乱**。

## §2 预注册（**跑前写死**；在任何引擎改动与新读数之前落盘）

- **改动（单变量，一行）**：`src/clasher_new/pathfinding_heap.py` 代价表里 `.` 分支
  `tile_cost = 5` → `8`。**`1`/`2` 走廊保持 5、`W` 保持 800、`heuristic`/`geo_cost`/
  `arena.is_walkable`/`pathfind_ground_walkable` 全部不动**。
- **不做的**：`W` 800→50（那是 P2 桥面实际宽度问题）、河面改为可走（那是
  `arena.is_walkable`，属【R13】位图对账范围）——**两项都不是本次单变量**。
- **基线（脚本复算，禁手抄）**：`runs/skarmy_probe/replays/league_1800.pkl`（改前）
  ⇒ `behind_king` 局横向行程完成度 y=6/10/14 = **0.363 / 0.35 / 0.528**；
  平均 `|Δ桥心|` y=4→12 = **2.53 → 2.57（持平）**。
- **主判据（两条同时满足 ⇒ H1 成立）**：
  (a) y=10 的横向行程完成度 **≥ 0.60**（基线 0.35；上游参考 0.83）；
  (b) 平均 `|Δ桥心|` 在 y=12 比 y=4 **低 ≥ 0.5 格**（基线是 +0.04，即不降反升）。
- **失败分支（写死）**：若 y=10 完成度 **≤ 0.45** ⇒ 判「离线 A\* 的结论**在全引擎里不复现**」，
  O3 成因记「未定」，**不得**写成「改了但没用」以外的任何结论。
- **中间带**：0.45 < 完成度 < 0.60 ⇒ 记「部分复现」，并**不**宣称 H1。
- **阳性对照（必须）**：改后录像 sha256 **必须与改前不同**，否则判「改动未生效」、本轮作废。
- **必须一并报出的旁证（不设阈值，只报数）**：分道数量（`behind_king` 6/9、桥头 15/0）、
  桥廊内最大同时在员、河带内越出桥廊帧数、过桥后横向跨度中位。
  ⚠️ 用户曾明确赞赏「桥上三只小骷髅同时通过」⇒ 若分道或同时在员**变差**，必须如实报出，
  因为它与「恢复车道价差」是同一个改动的两面（取舍，不是纯收益）。
- **写作禁则**：只写「是否复现上游那种逐步收拢」；**不写**「更好/更差」「修好了」。

## §3 结果（已跑完；判据按 §2 **机械判定**）

**阳性对照（必须先过）**：改后录像 sha256 `29bcd771048c09ce…` ≠ 改前 `254c661efbba45a4…`
⇒ **通过**，改动确实生效。

| 判据 | 基线（改前） | 改后（`.`=8） | 门槛 | 判定 |
|---|---|---|---|---|
| **(a)** y=10 横向行程完成度 | 0.35 | **0.804** | ≥ 0.60 | **满足**（且≈上游参考 0.833） |
| **(b)** 平均 \|Δ桥心\| y=12 比 y=4 低 | **+0.04**（不降反升） | **−1.557**（2.347 → 0.790） | ≥ 0.5 | **满足** |

⇒ **H1 成立**：恢复 `.` = 8 之后，**全引擎**里复现了上游那种「全程逐步收拢」
（y=14 完成度 **0.812** vs 上游 **0.833**），而不是只在离线 A\* 里成立。

### 旁证（按 §2 要求，不设阈值、只报数）

| 指标 | 改前（`.`=5） | 改后（`.`=8） | 上游 |
|---|---|---|---|
| `behind_king` 平均 \|Δ桥心\| y4→12 | 2.533 → 2.573（**持平**） | **2.347 → 0.790** | 1.973 → 0.850 |
| 横向完成度 y=6 / 10 / 14 | 0.363 / 0.350 / 0.528 | **0.475 / 0.804 / 0.812** | 0.600 / 0.833 / 0.833 |
| **分道**（王塔后 / 左桥 / 右桥） | 6/9 、 15/0 、 0/15 | **6/9 、 15/0 、 0/15（逐值不变）** | 同左 |
| **桥廊内最大同时在员** | 3 、 7 、 7 | **3 、 7 、 7（逐值不变）** | 3 、 6 、 6 |
| **河带内越出桥廊帧数** | L2/75 R3/117 、 L2/222 、 R2/222 | **全 0**（0/76、0/115、0/243） | 全 0（0/76、0/113、0/280） |
| 过桥后横向跨度中位（桥头局） | 1.3 | **0.5** | 0.2 |
| 过河中位（桥头局） | 4.1 s | **4.4 s** | 5.22 s |

### 三条必须如实说的话

1. **分道与「桥上同时几只」没有退化**：分道三局逐值相同；桥廊内最大同时在员
   `3 / 7 / 7` 与改前**逐值相同**（上游是 `3 / 6 / 6`）⇒ 用户赞赏的「桥上三只（我方最多 7 只）
   同时通过」在本次改动里**没有被牺牲**。
2. **越出桥廊帧数从 2+5 帧归零**，与上游一致——这是「提前进入正对走廊」的连带效果，
   属**顺带收益**，不是本次判据的一部分。
3. **过桥略慢 0.3 s**（4.1 → 4.4 s）是这次改动的**代价面**，如实报出；上游是 5.22 s，
   所以方向上仍是「比上游快、比改前慢」。

## §4 未验证 / 未定

- **`W` = 800 vs 上游 50 的影响未测**：它是 P2（桥面名义 3 格、实际 2 格）的同一个旋钮，
  本轮**刻意不动**。
- **河面可走性未跟**：上游把河面从 `BLOCKED_TILES` 移除（河面可走但贵），我方仍硬阻挡。
  离线变体显示**只改代价就够**（变体 C 比变体 B 收拢更早），故本轮不跟；但这意味着
  「我方与上游的路线在**河带**内仍可能不同」——未取证。
- **跟随侧未动**：`_lane_offset`、`min_point` 路点选择、每 10 tick 重算全部不变。
- **改动的下游影响未评估**：`gamedata`/训练/评估的所有历史读数都是旧代价下表出的，
  本次改动**会改变已训练权重在同一局面下的走位**（不是权重失效，是环境变了）⇒
  凡与旧 run 对拍走位/胜率的比较，都必须先声明这一条。**本轮未跑任何训练/评估**。
