## 0. 一页结论（六条设计律）

| # | 结论 | 依据（哪个项目让它可证） |
|---|---|---|
| **1** | **惩罚项放在哪里，决定它可靠不可靠**：环境奖励内 < 损失内 < 结构内 < **契约内**。越靠近奖励，越容易变成"货币泵"；越靠近契约（掩码/API/校验），越不可能被优化掉。**四类各有代表，且没有一家只用一类。** | RLHF 把 KL 惩罚放进**奖励**；DAPG/TD3+BC/AWAC 放进**损失**；DT/RLPD/IQL/Cal-QL 改用**结构**；绝悟 `legal_action`+`sub_action_mask`、FL「掩码委托引擎」放进**契约** |
| **2** | **「把奖励塑形权重退火到 0」在整个调查里没有一手实例**：OpenAI Five 全文 `anneal` 7 处**无一**指奖励权重（是超参与新环境/动作特性的 0%→100% 渐进引入）；绝悟全库 `anneal/schedule/reward weight` 只命中 2 个表头；VPT 衰减的是 **KL 系数 ρ**，不是奖励。 | OpenAI Five / 绝悟 / VPT |
| **3** | **密集手工奖励可能与胜率脱钩，而且看不出来**：OpenAI Five 的消融里**把 128 个参数置零反而让胜率提高约 55%**，而塑形奖励几乎没变。这与我们 **C14**（「放弃一张买得起的牌」75,891 帧 0 次 ⇒ 0 样本 ⇒ 0 梯度）**同型**：**"奖励在涨"不等于"能力在长"**。 | OpenAI Five（一手 LaTeX）；我们 C14 |
| **4** | **零和性有三种处境，且我们是最不利的那种**：OpenAI Five **方法层零和**（减对手均值）+ team spirit 混合；FL **引擎层零和**但被训练侧 6 项**破坏**；我们**训练侧逐项加减、根本不零和** ⇒ 自对弈下同一网络吃两份不对冲奖励。 | 三家对照 |
| **5** | **归一化三问（奖励/价值/优势）没有任何两家答案相同**，因此**任何跨项目的"学习率/损失曲线"比较都是无效的**。我们与 FL 各占"更完整的一半"（我们：`v_loss /= v_scale²`；FL：优势全局中心化 + 除 std）。 | 全部 |
| **6** | **价值头分解（绝悟 5 头）在我们这里暂时无意义**：我们是**唯一已确证 critic 沉睡**的一方（C3/O2：价值头隐藏层对几乎全部帧输出恒零），而绝悟的多头分解**依赖价值头活着**（且其 `w_k` 论文未给、只用"累计价值损失"当头的划分依据）。 | 绝悟 vs 我们 C3/O2 |

## 1. 先立三条"不可比"（否则所有对比都是假的）

| 项 | 差异 | 后果 |
|---|---|---|
| **时间单位** | 我们 `step` = **决策帧（0.5 s）**；OpenAI Five = **update / ckpt `update_step`**；VPT = **20 Hz 键鼠 tick**；绝悟 = **帧**（论文未统一到秒）；FL = **update** | 任何"多少步学会"的对比**无意义** |
| **折扣分母** | 我们 `γ=0.997/决策帧`；FL `γ=0.9997/决策步`（5 tick @50 ms）；绝悟 `0.997`(1v1/开悟) **vs** `0.998`(5v5)（**口径冲突并列**）；VPT `0.999` | `γ` **不可跨项目比**（`0.997^17=0.95` 与 `0.9997^17=0.995` 差 10×） |
| **奖励量纲** | 我们 ±10 级（`win_bonus=10`，`tower_dmg_opp=0.001/HP`）；FL ±1 级 + `β=0.05` PBRS；OpenAI Five 的 win=5 与 `XP 0.002` 同为"权重"但**未定义标量单位**；绝悟同名项**量纲不同**（1v1 的 `hp point` 是绝对值 / 5v5 是**四次幂** / 开悟是 **rate**） | 权重**不可移植**（【R15】） |

> **本文的写法约定**：只做**结构对比**（谁把什么放在哪、用什么机制、踩了什么坑），
> 单元格内**不出现跨项目算术**。

## 3. 六个维度的横向对比（真正有价值的部分）

### 3.1 「惩罚项放在哪里」——四级分类（最重要）

| 级 | 机制形态 | 代表 | 优点 | 代价 |
|---|---|---|---|---|
| **L1 环境奖励内** | 罚分直接进 `r_t` | RLHF 的 KL；我们的 `invalid_penalty`；OpenAI Five 的负权重项 | 实现最简、可微、能塑造"倾向" | ★ **可以被优化掉/绕过**：RLHF 一手证据说 KL 的效果「**akin to early stopping**」；我们的 `invalid_penalty` 累计 ≈ **−11.25 > 胜利奖励 +10** ⇒ **罚分在承担纠错职能** |
| **L2 损失内** | 加在训练损失上（不进环境奖励） | DAPG `λ₀λ₁^k max A^π`；TD3+BC `λQ−(π−a)²`；AWAC/IQL 优势加权；VPT 的 KL（**替代熵正则**） | 不影响环境语义 ⇒ **不改 MDP**；有现成的"权重衰减"旋钮 | 需要额外前向/参考策略；**权重口径易冲突**（`exp(A/λ)` vs 批内 softmax **两套约定并列**） |
| **L3 结构内** | 改网络/算法结构，让坏行为**不可表达** | DT（无 critic）；RLPD（LayerNorm 当"界"，逐字「it does **not explicitly constrain** the policy」）；IQL（expectile **不查询数据集外动作**）；Cal-QL（保守下界） | 无需调参、不会被"优化穿" | 表达力受限；RLPD 的 LayerNorm 在我们这里是**反例**（我们 **O2** 已定位价值头末端 LayerNorm 是 critic 死亡的第一性原因之一 ⇒ **同名机制、相反作用**，**不得照搬**） |
| **L4 契约内（API/掩码/校验）** | 把"不可能"与"不划算"分开：非法直接给不出 | 绝悟 `legal_action`+`sub_action_mask`（**env API 字段**）；FL「掩码直接委托引擎校验函数」；我们的 `validate_bundle` + 掩码不变式 | ★ **不可被优化掉**；消融最强（绝悟 P6：「**without legal action, the agent quickly converges to a local optimum**」） | 需要"单一权威源"；两套独立实现会**漂移**（我们已查出 C1/C2/C6：MergeMaiden 双向分裂、BarbLog 352 格缺口、Miner 全区豁免） |

**我们的处境（事实陈述，非建议）**：我们**同时**用了 L1 和 L4 来管"非法动作"（`invalid_penalty` + `validate_bundle`），
且 L4 的两套实现**互不推导**（`docs/illegal_action_layers_2026-09-18.md` 的 C1–C10）。
唯一有**实测消融**支持 L4 有效的是绝悟；唯一有**消融证明 KL 近似无效**的是 RLHF（Gao et al.）。

### 3.2 稀疏 / 密集 / 退火：三种路线，没有一家"退火奖励"

| 路线 | 代表 | 关键读数 |
|---|---|---|
| **纯密集 + 一次性构造** | OpenAI Five | 「constructed once at the start of the project」；`anneal` **7 处无一**指奖励权重（是超参 + 新环境/动作特性的 0%→100%） |
| **稀疏 + 用 KL 锚定先验代替熵正则** | VPT | 无 KL ⇒ 「progress stalls after **100,000** episodes … **catastrophically forgotten**」（只学会 4 个早期 item）；ρ=0.2、×0.9995 |
| **二值 + 人类统计量伪奖励 + KL 锚** | AlphaStar | IL 先行，RL 再用 KL 拴住人类策略；**伪奖励权重/退火未找到**（`未验证`） |
| **稀疏 + 里程碑/成就** | MineRL/BASALT | 2019 链式 ×2、2020 表 1→1024；BASALT 直接不要奖励函数，改**成对比较 + TrueSkill** |
| **密集分组 + 课程 + 契约** | 绝悟 | 三阶段 lineup 课程按 Elo 晋升；奖励权重退火**未找到** |
| **密集手工 22 键、无退火、有相位两档** | **我们** | 相位只作用 3 键；`elixir_diff` 是 `Φ′−Φ` 而**无 γ** ⇒ **形式上不是 PBRS** |

⇒ **横向结论**：**"奖励退火"是一个流传很广但没有一手实例的做法**。
真正被退火的是：**超参**（OpenAI Five 的 lr / GAE horizon）、**环境特性引入比例**（0%→100%）、
**KL 系数**（VPT 的 ρ）、**优势权重**（DAPG 的 λ₁）——**都不在环境奖励里**。

### 3.3 塑形与"PBRS 真伪"（三家自称、一家严格成立）

| 项目 | 自称 | 形式核查 |
|---|---|---|
| **FirstLight** | PBRS | ✅ **严格成立**：`β(γΦ′−Φ)`（有 γ、有终态势置零、有 `τ=16664.17` 与 `β=0.05`） |
| **OpenAI Five** | 「modeled loosely after potential-based shaping」 | ⚠️ **自称且自认不成立**（原文明确声明理论保证不适用） |
| **我们** | 代码注释写 *"potential-style shaping"*（`rl/reward.py:183`） | ❌ **形式上不是 PBRS**：纯 `Φ′−Φ`，**无 γ**、**无终态势置零** ⇒ 「语义像势差、形式不满足 Ng et al. 条件」（【R17】：两套口径**并列不调和**） |

### 3.4 零和与信用分配

| 项目 | 零和性 | 信用分配手段 |
|---|---|---|
| OpenAI Five | **方法层零和**（「subtracting from each hero's reward the average of the enemies' rewards」）+ **team spirit** `r_i=(1−τ)ρ_i+τρ̄`（τ 0.3→1.0） | 队友平均 + 局内时间权重 |
| 绝悟 | 奖励表**按功能分组**（含 team 项） | ★ **5 个价值头**（`V̂=Σw_k V̂^k`）+ 用**累计价值损失**当"哪个头值得留"的依据 |
| FL | **引擎层精确零和**（`(r0−r1)/2`），但**训练侧 6 项逐 owner 独立加减** ⇒ 组装后 `r_t` **不再零和** | PBRS 势函数 Φ（王塔 w=3.0 / 公主塔 1.0） |
| **我们** | **非零和**（训练侧逐项加减） | 塔血三层定价 + `edw` 费差 + `unit_dmg_k`；**相位只作用 3 键** |

⇒ **我们唯一"独家"的是塔血经济学与圣水定价**；**零和性上我们处于最不利位置**（自对弈下同一网络吃两份不对冲奖励）。

### 3.5 归一化三问（表见 §2）——三家答案全不同

- **我们**：奖励零归一化 / 价值有（**但 `run` 模式不生效 = H1**）/ 优势 **只除 std 不中心化**。
- **FL**：奖励零 / 价值**无** / 优势**中心化 + 除 std**。
- **OpenAI Five**：奖励 **running std 归一化** / 价值无 / 优势全局中心化 + 除 std。
- **VPT**：只归一化**价值目标**（EWMA）。
- **绝悟 / MineRL / AlphaStar**：**论文未描述** ⇒ `未验证`。

⇒ **任何跨项目的"损失曲线/学习速度"比较都无效**；我们与 FL「各占更完整的一半」已是**最好的写法**。

### 3.6 value head：单头 vs 多头分解

| 项目 | 头数 | 备注 |
|---|---|---|
| 绝悟 | ★ **5 头**（Farming/KDA/Damage/Pushing/Win-Lose），逐头 MSE，`V̂=Σw_k V̂^k` | **`w_k` 论文未给**；唯一可核实的"按损失调奖励"机制（无形式化算法） |
| 其他全部 | **单标量**（含复现件里的 AlphaStar、VPT、OpenAI Five、我们、FL） | — |
| **我们** | 单标量 + `value_independent` / `value_bypass` 开关 | ⚠️ **C3/O2 已确证 critic 沉睡**（隐藏层对几乎全部帧输出恒零；`vstd/rstd ≈ 0.001`）⇒ **在价值头活着之前，多头分解只会把"常数"复制 5 份**（且【R11】禁止在 A′ 类取证前拆价值头） |

## 4. 已知坑的横向对照（全部带出处，方向化）

| 坑 | 实例 | 对我们的意义 |
|---|---|---|
| **密集塑形与胜率脱钩** | OpenAI Five：**置零 128 个参数使胜率提高约 55%**，而塑形奖励几乎没变 | 与 **C14** 同型 ⇒ 「奖励在涨」≠「能力在长」 |
| **KL 惩罚 ≈ early stopping** | Gao/Schulman/Hilton（arXiv:2210.10760 §3.6）逐字：「the effect of the penalty on the gold score is **akin to early stopping**」；该文其余实验**把 KL 设为 0** | 「加 KL 防 reward hacking」**不是**一手支持的普适结论 |
| **IL 数据质量 ≫ RLHF** | LIMA：**1,000 条精选**、**不做 RLHF**，65% 胜过做过 RLHF 的 DaVinci003 | 与我们「BC 目标是规则专家在线自产」的路线无直接可比性，但说明**数据侧 > 奖励侧** |
| **return-conditioning 在随机环境失效** | Paster et al.（arXiv:2205.15967）：「fail dramatically … **not due to a lack of data**」 | 我们的环境含强随机 ⇒ 高风险 |
| **BC 与离线 RL 的强弱取决于数据源** | robomimic：人类数据上 BC-RNN **78.0** ≫ BCQ **14.0** / CQL **0.7**；D4RL locomotion：BC **466.7** < IQL **692.4** | **证据分裂**（并列不调和）⇒ 不能一刀切 |
| **奖励 hacking / 卡 bug** | 绝悟：**没有任何一手来源提到**（`[NOT-FOUND]`）；VPT 只有 "deceptive"（有具体例子：拿 cobblestone 最快 ⇒ 把工作台留在原地但让后续更难） | **不得**把"外部项目都遇到 reward hacking"写成事实 |
| **泛化崩溃 / 打法趋同** | 绝悟作者原文：**胜率恒为 0**、**通用奖励函数导致所有阵容打同一种打法**（macro-state entropy 0.000/0.014/0.408） | 与我们的"熵已平台"读数同族（⚠️ 我们的读数**不得**当判据） |

## 6. 反面清单（明确**不建议**照做）

1. **「学 OpenAI Five 把奖励塑形退火掉」** —— 该说法在 v1 文本里**不存在**。
2. **「IL 项目都有 KL 锚定」** —— FL **没有**（默认关）、绝悟**找不到**、AlphaStar 有但参考分布是**人类策略**（我们无人类数据）。
3. **「密集奖励调权重就能把稀有行为调出来」** —— 稀有行为是**合取事件**（我们已实测：连续 34 帧不花钱；逐帧独立随机的成功率是**乘积**），且**0 样本 ⇒ 0 梯度**；OpenAI Five 的"128 参数置零反而更好"是这一点的实证。
4. **「把惩罚都放进奖励，简单」** —— 我们的 `invalid_penalty` 累计量级已 **超过胜利奖励**；绝悟/FL 都把非法性放在**契约**里。
5. **「照抄绝悟的 `No-op` 惩罚」** —— 我们的"不作为"是**圣水经济**造成的（实测：抬 stop 概率把圣水≥6 帧从 0% 抬到 48%，代价是每局回报 −4.46 → −41.5）⇒ 会**误治病灶**。
6. **用外部项目的学习曲线/步数当我们的预期** —— 三大量纲（step / γ / 奖励尺度）全不可比（§1）。
