# 局面圣水交换信用分配 · 预注册（2026-09-18）

> **触发**：用户方案（三轮澄清后的最终形态）——
> ①以**局面**为基准结算，对每个决策帧打分；②评价含「放的牌之后造成的伤害 / 打死的敌方圣水价值 /
> **被索敌时其他己方卡牌的战果**」；③「差分」不是"有价值即加分"而是"**有足够价值才加分**"；
> ④划分条件修正为「仅有建筑与其最近召唤物」；⑤**召唤物本身不用圣水计量，但它的战斗价值（吸引的仇恨 + 造成的伤害）
> 算给召唤它的单位**，再用**召唤者的圣水费用去对标它防守的卡**。
>
> **设计依据与全部论证**：[`frame_credit_proposal_review_2026-09-18.md`](frame_credit_proposal_review_2026-09-18.md)
> §7（缺口确证与改判）、§8（局面划分规格 v1）、§9（溯源路由 / 货币泵否决）。
> **本文件性质**：**预注册**。判据、失败分支、不变量**在写代码之前写死**（【R3】）；跑完照单读。
> 凡**未经实测**的数字一律标 **待标定**，并登记偏离（沿用 `reward_settlement_prereg_2026-09-14.md` §3 的先例）。

## §0 摘要（三句话）

1. **为什么做**：现行奖励里**「被阻止的伤害 / 拉扯」这一格是 0（甚至为负）**——塔血没掉不产生任何正奖励，
   而冰人/骷髅被吃掉还让 `Φ` 掉 2 费 ⇒ **正解被记为负**。本仓当年把这一格交给 `critic + 示范`
   （`rl_reward_plan_v2.md:169`），而 **critic 是常数、示范也没有** ⇒ **缺口确证无人管**。
2. **做什么**：把**已有的 `Φ` 账**从"逐帧"改成"**按局面窗口结算 + 阈值**"，再补一项**真新信息**（塔血保全 / 仇恨），
   并把免费产物的**战斗价值溯源路由给召唤者**（**绝不给产物体估值** —— 估值是货币泵，见 §4）。
3. **判据**：主判据**不用胜率**（【R5】）；用机制层 + 行为层 + **优势兑现率门禁**三层，全部同批配对复算（【R4】）。

## §2 指标规格：**净交换 = 窗口内 ΔΦ + 塔血保全项**

### 2.1 主项（**不是新信息**，只是把已有 Φ 改成窗口结算）

对局面窗口 `[t0,t1]`，`Trade_me` 恒等于（推导见评审 §7.2）：

```
Trade_me = ΔΦ_window + tower_term
ΔΦ_window = [Δ(手牌圣水+残值)_me − Δ(手牌圣水+残值)_op]  在窗口内
```

**等价的自明形式**（便于对账与 selftest）：

```
净支出_x = Σ_{x 在窗口内 deploy 的花费} − (V_x(t1) − V_x(t0))
Trade_me = 净支出_op − 净支出_me + tower_term
```

- **自检算例 A（纯进攻，用户例）**：我 3+3=6 费全下、对方 6 费来解且**全部死光**、我全活 ⇒
  `净支出_me = 6 − 6 = 0`、`净支出_op = 6 − 0 = 6` ⇒ `Trade_me = +6` ✅ 与用户口径一致。
- **自检算例 B（拉扯，用户例）**：1 费骷髅解 4 费小皮卡（骷髅死、皮卡死）⇒
  `净支出_me = 1`、`净支出_op = 4` ⇒ `Trade_me = +3` ✅「1 费解 4 费」。
- **结算时刻的残值必须计入**：对面 5 费小屋仍立在场上 ⇒ 算它 **5 费返场**（否则虚增我方交易）。
- **圣水自然回复不计**（双方对称，且不是任何动作引起的）。

### 2.2 塔血保全 / 仇恨项 `tower_term`（**唯一真新信息**）

**这是全文件唯一不能凭设计写死的量**（真反事实要 43.3 ms/次推演，见评审 §3 P5 ⇒ 只能代理）。
三个候选代理，**按此顺序尝试，前一个无信号才用后一个**：

| 代理 | 公式 | 需要新常量 | 可刷性 |
|---|---|---|---|
| **P3（首选）** | `Σ_{敌方单位 E} cost(E) × [E 在"被我方实体钉住"期间死亡]` | **不需要**（复用既有 `V` 注销 + 索敌关系） | **不可刷**（延长钉住不加分，只有真打死才结算） |
| P1 | `Σ_E dps(E) × 钉住秒数`（`dps` 由引擎 `data.damage/hit_speed` 算） | 不需要（引擎已有），但**会高估**（把"本来就在走路"算成被阻止） | 可刷（延长钉住） |
| P2 | `Σ_E cost(E) × min(1, 钉住秒数 / T_ref)` | **需要 `T_ref`（待标定）** | 可刷（延长钉住） |

- **首选 P3 的理由**：**零新常量**（满足【R7】"单常量源"）、**零和**（信用只在既有 `V` 注销时发生）、
  且**不可刷**（延长钉住不增加信用）。P1/P2 必须**先过 P3 无信号**才启用，且启用时 `T_ref` 的标定程序见 §5。
- **P3 的已知代价（如实记）**：它**只承认"钉住→打死"的路径**，对"钉住→拖住但没打死"（纯节奏收益）
  **仍然为 0** ⇒ 若 S2 显示这类局面占比很低，P3 可能就够了；占比高则必须上 P1/P2。

### 2.3 分数化（"有足够价值才加分"）

```
score = max(0, Trade_me − θ)          # 平滑 hinge（不用硬阈值 ⇒ 不造悬崖）
```
`θ = 1.0` 圣水，**且必须登记为"有原则的选择"而非实测标定**（圣水是游戏自己的单位，"差 1 费才算一次有效交换"）。
⇒ 配 **敏感性臂 `θ ∈ {0, 1, 2}`**（§8），若结论在 θ 上翻转 ⇒ 判"阈值是刀口"、**不判决**。

## §3 溯源路由规格（**用户第四问的答案**）

1. **绝不估值**：`V_product ≡ 0`（沿用既有约定）。**理由见 §4。**
2. **产物体造成的每一项"已有"账目变动**——塔伤、我方单位**死亡注销**、我方单位**掉血**、
   `tower_term` 的 P3 部分——**记到它的 `root_cast` 桶**上。
3. **`root_cast` 必须是"出牌事件"，不是实体**：Graveyard 是**法术、没有召唤者实体**（实测池中 10 局），
   `SuperWitch`/`NightWitch` 是**单位生单位** ⇒ 溯源要**链式取根**（子→父→…→那次出牌）。
4. ★ **溯源指针写在产物体自己身上**（`uid` 存活于实体上），**不能靠"查召唤者"**（召唤者可能已死）。
   ⇒ **账的归属与局面边界解耦** ⇒ 「最近一次/最近两次」的批次计数**不再必要**（评审 §9.5）。
5. **桶独立结算**：每个 `root_cast` 一个桶；局面结算时把窗口内的路由项累加到桶；
   **不回头改写已关闭的局面的账**（避免回溯改写）。
6. **路由层级 = Tier-1（按局面成员 + 溯源）**，**不做 Tier-2 精确归因**
   （Tier-2 需在那 35 处无 `source` 的伤害调用点补 `source` ⇒ 撞上 **Ronin 格挡会开始吞法术**的语义陷阱）。

## §4 ⛔ 免费产物**不得估值**（两条否决证明，写死备查）

| 做法 | 后果 | 判决 |
|---|---|---|
| **给产物体估值** `w>0` | Tombstone `~2.9 s/个`、不被打是整局 ⇒ **60+ 个** ⇒ 一个 **3 费建筑凭空产生 60 费价值** ⇒ **Φ 无界**；`value_norm="running"` + `adv_norm="scale"` 会把整条奖励**尺度**绑到该项 ⇒ 学"下小屋别防守" | **货币泵 ⇒ 否决** |
| 死亡时**零和转移**（杀死者 `+w`、召唤者 `−w`） | 不是货币泵，但杀死者**零成本**拿 `+w` ⇒ 清 60 个免费骷髅 = `+60w`（**一个圣水没花**）⇒ **可无限刷分** | **否决** |

⇒ **唯一允许的形式 = §3 的溯源路由**（战斗价值路由给召唤者，产物体本身始终 0 费）。

## §5 判据（**跑前写死**，含失败分支）

### 5.1 主判据：机制层（不用胜率，【R5】）

| 层 | 指标 | 仪器 | 对照（脚本复算，禁手抄【R4】） |
|---|---|---|---|
| **机制（主）** | 批内 EV（**更新前池化**）、`resid_norm`、`grad_cos`、`EVb` 形状 | `diagnose_every` 日志 + `scripts/judge_critic_inertia.py` | **本实验 run 自己前 100 次诊断更新**的中位 ± 3×MAD |
| **行为（可复算）** | 全帧圣水 ≥6 占比、Xbow 出手率、部署前圣水中位、同路间隔 | `scripts/forensics_card_usage.py`（只读） | `long1m` 起点 / 本实验阴性对照 |
| **★ 门禁（新增）** | **优势兑现率**：`Trade ≥ θ` 后的 **N=20 s** 内，我方累计部署花费 ≥ `Trade` **或** 塔伤 > 0 的比例 | 新仪器（回放 + 部署事件） | 本实验**同批阴性对照**；`N=20 s` 登记为**有原则的选择** |

**阈值标定程序（写死的是程序，不是数字）**：阈值取**本实验同一 run** 的前 100 次诊断更新作对照池，
脚本复算中位 ± 3×MAD；**禁止**沿用其它实验阈值（【R15】）、**禁止**单次观测标定（【R16】）、
分子分母必须同超参（【R17】）。
> **有意偏差登记**：本项目**没有**"结算口径改动"的历史散布读数可作余量依据 ⇒ 此刻写任何数字都是单次观测。
> 与 `reward_settlement_prereg_2026-09-14.md` §3 同样处理：**只写程序，不写数字**。

### 5.2 对照臂（缺一不可）

- **阳性对照**：`elixir_diff_weight: 0.5 → 0.0`（已知会改写结构层与部分行为读数）。
  对照**不过** ⇒ 判 **`INVALID`（不判决）**，先修仪器/流程，**禁止**解释主判据。
- **阴性对照**：**同配置重跑**（不同 seed）——量出"无改动时的散布"，是判"有变化"的前提（【R5】）。

### 5.3 失败分支（写死）

1. 阳性对照不过 ⇒ `INVALID`，不解释主判据。
2. 机制层改善但**行为层三项全无改善** ⇒ 判「**未达行为可见阈值**」，**不得**写成"修好了"（【R11】）。
3. **门禁不过**（兑现率显著低于阴性对照）⇒ 判「**买到只守不推**」⇒ **不接受该改动**（圣水上限 10 ⇒ 只守不推可攒交易打平）。
4. 结论在 **θ 敏感性臂**（§8）上翻转 ⇒ **不判决**。

## §8 实验设计（【R3】单变量）

- **模式 = `solo`**（**必须**）：`run` 模式的 5 个对手是 **mask-随机脚本**，
  既不"应对"我们的推进（对方花费那一半是噪声），也**不组织一次皮卡推进** ⇒ **拉扯没有可学样本**（评审 §7.4 实测）。
- **唯一变量**：`engagement_trade.enable`（on/off）；`θ` 敏感性臂另跑 `{0,1,2}`（每臂 1 跑，只作敏感性）。
- **协议**：标准 20k（§2.2 命令原文照抄），`--eval-workers 12`，`--fresh`。
- **臂**：`A_ctrl`（阴性对照，同配重跑）×2 seed、`B_trade`（干预）×2 seed、`C_pos`（阳性对照：`elixir_diff_weight→0`）×1。
- **成本**：5 跑 × ~47 min ≈ **4 h**（20k 协议评估占 73% 墙钟）。

### 11.13.3 ★ 本轮**不构成判决**（必须写明，否则会误读）

### 11.13.4 失败分支（沿用 §5.3 + 本轮新增）
1. 机制层改善但**行为层三项全无改善** ⇒ 判「**未达行为可见阈值**」，**不得**写成"修好了"（§5.3 第 2 条）。
2. 门禁（兑现率）显著低于 `B_ctrl` ⇒ 判「**买到只守不推**」⇒ 不接受该改动（§5.3 第 3 条）。
3. **新增**：若 `A_et` 与 `B_ctrl` 的机制层差异**小于两者自身的窗口散布** ⇒ 判「**不可分辨**」，
   并把结论记为"本分辨率下无结论"。
4. 若 `A_et` 的训练**跑不动/降级/异常** ⇒ 按【R1】**先归因外部、不自动降档**，留证并报告。

**§11.13.4 注：失败分支 3 的「窗口散布」操作化定义**
（2026-09-18 写定，**在两臂跑完之前**、结果不可见时——【R3】要求把程序性措辞变成可执行判据）：

- 「窗口散布」= `spread = max(MAD_A, MAD_B)`，MAD 取各臂**前 100 个诊断点**的**原始中位绝对偏差**
  （即 §11.13.2 已指定的离散度统计量，**不乘 1.4826**）。
- 「差异」= 两臂**后续窗口**该指标**中位**之差的绝对值：`diff = |median_later(A) − median_later(B)|`。
- 判定：`diff < spread` ⇒ **该指标不可分辨**；**六个指标全部不可分辨** ⇒ 触发失败分支 3。
- **退化处理**：任一臂该指标的基线 MAD = 0（带退化）⇒ 该指标**退出**该判定并标 `⚠退化`
  —— 退化时"散布"无意义，**不得**据此判显著（也不得据此判"不可分辨"）。
- 本操作化由 `scripts/et_solo100k_readout.py` 实现并**脚本复算**（【R4】），输出含六指标逐项判定与总判定。
