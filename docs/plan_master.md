## 0. 一句话现状（2026-09-13）

训练主线 = **solo 自对弈闭环**（`rl/train_solo.py`）。当前状态：

- ✅ **"训练能不能不崩"已解决**：D1（对手分布去镜像化 + 动态历史自身联赛 + PFSP 门禁）消除了
  "整段输给固定随机策略"的相位，20k（三跑区间不相交）与 100k（P1 块口径 PASS）都成立；
- ❌ **"能不能变强（抬上限）"未解决**：100k 的最差锚点 0.237 落在 20k 区间 [0.125,0.250] 内，
  次判据口径敏感（+0.125 / +0.062）⇒ 按预注册**不判决**；cycling 仍在转；
- ⛔ **critic（价值网络）侧已按预注册闭合**：GRU 饱和已修且 100k 耐久，但 EV 仍 ≈0/负，
  `vstd/rstd` 30k 后 ≈0.001；**加训练量（X4）与四代架构（X3）都救不了** ⇒ 不再往 critic 加投入；
- ⚠️ **行为病理部分未修**：防守链三层有真实爬坡（响应 38→62%、接敌 7.4→10.5%），
  但"不会攒费"仍在（`elixir_avg` 低）、`setup_wait` 冷启动死锁已定位**未实现修复**。

**口径提醒**：1 step = 1 决策帧；20k ≈ 156 次 PPO 更新 ≈ 55~80 局；100k ≈ 374 局。
对标 Atari PPO 的 10M~50M 帧，20k 只有其 1/500~1/2500。

## 4. 现在该做什么（优先级 / 判据设计 / 成本）

> **所有实验必须带预注册**（见 §5）。成本按"纯训练 26 步/s、全点 ≈210 s/轻点 ≈53 s"估算，
> 且**必带 `--eval-workers`**（`economy` 预设为串行）。

### P0 · 上限问题：D2 = 把训练侧锚点剂量 0.1→0.3

- **动机**：唯一在 20k 与 100k 上都"有效"的机制是 D1（对手分布）；上限没动。E2 证明 **10% 弱锚点
  压不住自对弈漂移**（X5），但剂量-反应曲线从未测过。
- **协议**：标准 20k 协议，只改 `opp_mix["rand_anchor"]` 0.1→0.3（`config.DEFAULT_OPP_MIX` +
  `train_solo._OPP_MIX` 两处同步），**跑 3 个 config-name**。
- **判据设计要点（吸取 D1 的教训）**：①主判据用**单跑最差锚点**（已被两轮证明有判别力，
  区间不重叠）而不是"末 4 点滚动均值"（相位主导、判不了）；②上限问题建议加**块内中位数**
  做聚合（比滚动均值稳），但须先写死"判决线/不可判带"；③基线列**全部脚本复算**
  （`scripts/judge_anchor_blocks.py --groups`）；④跑前披露"补种 ckpt 会被挤出"等规模效应。
- **成本**：3×20k ≈ 3×(约 13 min 训练 + 8×210 s 评估) ≈ **2.3 h**（12 worker）。
- **风险**：剂量过高可能让 hist 槽被锚点挤掉（mix 归一化）——先做 1 跑冒烟确认 `kind_counts` 实际配比。

### P1 · 行为病理：攒费链两阶段状态机（已定位、未实现）

- **动机**：`setup_wait` **冷启动不可达**（"先攒满才准沉底、先有血牛才准攒"= 鸡生蛋死锁），
  任何 RL 梯度够不着未被采样的分支；`elixir_avg` 长期偏低 = 一够费就花。
- **改动**：窗口条件改为不依赖血牛在手（"无 pressing 威胁 + 圣水≥4 + 双倍期前"即进入 hold，
  仅保留防守豁免），血牛在手才输出 `suggested_card` ⇒ 两阶段状态机。
- **判据**：行为指标只读 `gates.json` **相对退化**（绝对数不跨 run 比、且是相位型）；
  主观察 = `elixir_avg` / 组波率 / 接敌率的**同 run 内**漂移；配 3 跑以降 n=1 风险。
- **成本**：20k×3 ≈ 2.3 h + 取证脚本时间。

### P2 · cycling 深化（若 P0 不足）

- 候选：`_HIST_POOL_MAX` 12→24（长 run 的自身联赛更密，100k 上池子只剩 12 个均匀样本 ⇒ 间距 ≈8300 步）；
  或课程式提高 `defend` 权重。**注意**：改池上限会改变 D1 已验证的机制，需重新跑 20k 三跑基线。

### P3 · critic 重启的前置条件（**不是现在做**）

- 只有在 P0/P1 之后、且**监督设定下确认可达上限**（已有 +0.22~+0.29 的证据链）再谈 PPO 侧；
  **不要再靠加量**（X4）、不要再试第五代价值头结构（X3）。

### P4 · 支线（与主线正交，可随时做）

- MCTS 评估接入（`evaluate.py --mcts`，零训练风险，直接量"搜索赚多少 Elo"）；
- 循环规划器（外置工具④，牌序 depth/ETA 特征，遵守 R12）；
- 数据层残余（个别卡 per-level 查证）。

## 5. 纪律清单（写任何新计划时必须带）

**预注册必备 8 项**：①唯一变量；②完整协议命令；③主判据（含阈值与判定规则）；④次判据
（**只描述不判决**，若口径敏感须注明）；⑤对照与基线（**必须脚本复算**，禁手抄 = R4）；
⑥跑前披露的已知偏差（规模效应 / n=1 / 未消除的循环）；⑦失败分支（事先写死，跑完不许现编）；
⑧运行期冻结代码与配置。

**四条方法学底线**：

1. **单变量 + 预注册**（R3）：一次一个变量；判据先写死。
2. **n=1/臂分辨率不足**（R5）：20k 单跑只能看大效应；优先用同 run 内对照；跨 run 数字不可直读。
3. **噪声地板先记住**：40 局胜率 1σ≈0.078、接击率 1σ≈±5pp；锚点相邻点 |Δ|≈0.23≈3σ、
   谷底只 1 个点宽 ⇒ **评估节奏用 C 方案**（密锚点 2500 + 稀全块 10000），不要均匀放宽（C7）。
4. **不确定就写不确定**（R10）：成因未定 / 样本不足 / 不显著都要写明，不许写自信的错答案。
