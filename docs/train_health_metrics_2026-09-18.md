## 2. 口径（判读前必读，【R9】）

### 2.1 策略熵 = 一次决策内各 decoder 步（掩码后）熵之**和**

$$H=\sum_{j} H\big(\pi(\text{slot}_j)\big)\;+\;\sum_{j:\,\text{deploy}} H\big(\pi(\text{cell}_j)\big)\qquad(\text{nat})$$

三条后果，**判读时必须带**：

1. 它是**求和** ⇒ 随 bundle 长度（decoder 步数）变化。本 run bundle 中位稳定在 **0.07–0.12** ⇒ 混杂很小但**不为零**；
2. 合法集大小随局面变化，而**局面分布本身由策略决定**（自对弈）⇒ 跨时间的熵变化 = 「策略变尖」+「走到了不同局面」
   两种成分**混在一起**，**不是**纯策略锐度；
3. 熵是在 **plan 软偏置之后**的分布上算的。

**好消息**：`masked_fill` 在前 ⇒ 熵只在**合法**动作集上求 ⇒ **不含**"学会别选非法动作"这种平凡下降。

### 2.2 价值损失有**两个**，日志里都打，**别混用**

| 日志字段 | 定义 | 能不能跨时间比 |
|---|---|---|
| `value=` | 原始 MSE **÷ `v_scale²`** | ❌ **不能**（`value_norm=running` 时 `v_scale` 一路长） |
| `vraw=` | **原始 MSE**（未缩放） | ✅ **趋势判读一律用这个**（仅 solo 模式打；run 模式只有 `value=`，**无法**还原 vraw） |

**实测反例（A_et，同一 run 的两端）**：

| step | `value=` | `vraw=` | `scale` |
|---|---|---|---|
| 339 | 0.1268 | 0.39 | 1.75 |
| 99809 | **0.0010** | 0.60 | **24.86** |

恒等式对得上：`0.46 / 24.87² = 0.00074` ✓。⇒ 只看 `value=` 会得到"**损失在降**"的**假读数**，
实际是分母长大了 ~200 倍。**UI 因此两条都画，并在注里写明。**

## 4. 为什么"熵平台"不能**单独**当瓶颈判据：三个混杂

1. **`ent_coef` 固定 ⇒ 熵本就趋于平衡点。** 熵在 loss 里是被**奖励**的项（`- coef * ent_term`，
   `coef=0.01`），平衡点是"变尖的梯度 = 熵奖励的梯度"。⇒ 熵平台可能只是**正则项的平衡**，
   **不是**"环境里没东西可学了"。本 run **未做 schedule**，所以无法把这两种解释分开。
2. **熵平台 ≠ 性能平台。** 熵量的是**锐度**，不是**回报**。完全可能「熵已平但胜率还在涨」（探索够用）
   或「熵已平且胜率也平」（真瓶颈）——本 run 属于**哪一种判不出来**，因为下一节的原因。
3. **胜率层在 n=1 下没有分辨力。** 按预注册 **§11.13.11** 的实测标定：**同 seed 同配置**只改
   `--diagnose-every`（10 vs 1）⇒ `eval@0` 逐字相同，而 **`eval@8000` = 0.800 vs 0.200（差 0.60）**；
   既有同配置三连跑末点 **0.675 / 0.475 / 0.362**（极差 0.313）。⇒ 本 run 的胜率序列
   （0.65/0.20/0.35/0.25/1.00/0.50/0.65/0.50/0.20/0.45/0.70/0.45/0.40，20 局/点、±SE≈0.11）
   **无法**支撑"是否还在进步"的判断 ⇒ **熵层的"平台"无法与性能层对齐**。

**因此本轮的诚实结论只有一句**：
> **熵在 ~20–30k 步后不再有可分辨的变化（本 run 自身噪声量级内）；但"这等于步数瓶颈"这一句在本
> 分辨率下**不可判**（缺阳性对照 + n=1 seed）。**

## 5. 若要把它**变成判据**：预注册必须写死什么（【R3】【R15】【R16】）

本轮的 `k=3`、`win=5% 点数`、`MAD` 取"前 100 点"**都是借来的约定**，不是在本量纲上标定的。
下一轮若要当判据，**开跑前**必须写死：

1. **窗口与阈值**：窗口长度、`k`、基线窗口（前 N 点 / 滚动窗）逐字写死；
2. **`k` 的标定**：`k×MAD ≫ run 间散布`（【R16】禁止单次观测标定）⇒ 需要 **≥3 seed** 的
   同配置重跑来量 run 间散布（这正是本 run 缺的那一半：**无阳性对照、单 seed**）；
3. **判决要求「合取」**：`熵在带内` **且** `性能层（外生对照/门禁）在带内` ⇒ 才可判「平台」；
   只有熵在带内 ⇒ 只能判「锐度已定，性能是否也平台**未知**」；
4. **口径固定**：必须用 `vraw`（不是 `value=`）；熵必须记明"掩码后、求和、`ent_coef` 值"；
5. **跨臂禁止**：`A_et` 多了一项改行为的奖励 ⇒ **熵(A) 与熵(B) 的差含干预本身**，
   在 n=1/臂 下**不得**解释为"训练健康度差异"（沿用 §11.13.4-3 的 `spread=max(MAD_A,MAD_B)` 算子
   也只能读方向）；
6. **可选的去混杂实验**（本方案真正能回答"是不是瓶颈"的做法）：
   **同 seed 跑 `ent_coef ∈ {0.003, 0.01, 0.03}`**，看性能层是否随之变化。
   若熵平台是"正则平衡"造成的，改 `ent_coef` 应能推动熵并暴露性能是否还可提升。

## 8. 三条工程坑（含我自己犯的两个）

### 8.1 GBK 陷阱：`PYTHONIOENCODING=utf-8` 在本环境**不生效**（实测）

本仓已知"新脚本一律自带 UTF-8 stdout reconfigure"（`rl/dashboard.py::_force_utf8_stdout` 的 docstring 记着
一次**整个 dashboard exit 1** 的事故：一句带 `⚠` 的 `print` 在 GBK locale 下抛 `UnicodeEncodeError`）。
本轮补一条更硬的证据：

```
$ PYTHONIOENCODING=utf-8 .venv/Scripts/python.exe -c "import sys; print(sys.stdout.encoding)"
gbk                      # ← 加了环境变量仍然是 gbk
```
**指纹**：不 reconfigure 时，同一次运行的输出里，`import judge_critic_inertia`（它**模块顶层**就
reconfigure 成 utf-8）**之前**的行是 **GBK 字节**、**之后**的行是 **UTF-8 字节** —— 同一个流里两种编码。
**修法**：`sys.stdout.reconfigure(encoding="utf-8", errors="replace")`（与 jci / readout / dashboard 同一实现）。

### 8.2 仓库根推错一层 ⇒ 面板永远"没有日志"（被新回归抓出）

`rl/dashboard.py` 的 `_PARENT = dirname(dirname(__file__))` = **`src/clasher_new`**（供 `import rl.*`），
**不是** `src`。我第一版写 `repo_root=dirname(_PARENT)` ⇒ 得到 `src` ⇒ `<repo>/docs/train_<run>.log`
**一个也推不出来**，面板静默显示"没有日志"。
抓到它的是**新加的正面路径回归**（`check_dashboard_js.py` 打印 `log=None` 而不是让 `SKIP` 悄悄过）。
修法：显式 `_REPO_ROOT = dirname(dirname(_PARENT))`。

### 8.3 我自己的正则漏了正号 ⇒ **错数**（同一类错误第二次）

第一版解析用 `(-?[\d.]+)`，而日志里 `adv=+5.023±…` 有**前导 `+`** ⇒ 774 行里**只解析到 375 行**，
且**静默**（不报错，只是点少了一半）。修法：`[-+]?(?:\d+\.?\d*|\.\d+)`，并把"解析了几行 / 跳过几行"
写进 `parse_log` 的 info、由 CLI 打印。
**教训（与 §11.13 的教训同源）**：读数脚本的**口径错误会静默产生错数**——凡是"读数仪器"，
必须自带**计数**与**自检**（本脚本的 `--selftest` 就含"两种格式都能解析"这一项）。
