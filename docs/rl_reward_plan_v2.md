## 0. 症状与目标

### 0.1 已观察症状
1. economy solo 评估长期 16D/0.0（策略塌缩躺平，僵局早停判平）。
2. 非平局对局中双方常各自在左路堆防守单位，互不推进、"不对牌"。
3. 历史对照（无费差 shaping 时代，用户实测 100k 轮）：模型**空砸法术 + 有圣水必放牌**，
   即"浪费隐形"导致完全不珍惜资源。

### 0.2 目标
让模型学到真实 CR 的经济节奏，而不是两个病态极端的其中一个：

| 病态 | 行为 | 根因 |
|---|---|---|
| 躺平（现在） | 不下牌、各自堆牌、平局 | 下牌即时费差惩罚 > 延迟收益（被 discount 稀释） |
| 乱放（历史） | 空砸法术、有圣水必放 | 资源无即时信号 → 浪费隐形 |

理想行为链：前期珍惜圣水（换费/防守）→ 中期利用节奏（解牌/反打）→
后期塔血优先（双倍圣水期堆兵、法术斩杀）→ 破塔 → 胜利。

## 1. 根因分析（已用代码/历史查证）

### 1.1 下牌即时惩罚（当前 economy 躺平的直接原因）
`env_wrapper.compute_reward`（L109-112）费差项 = `edw × Δ(手牌圣水差)`：
- 放一张 4 费牌 → 部署帧手牌圣水 −4 → **即时 −2.0 全额生效**；
- 单位走到塔打出收益需 20-40 决策步（每步 0.5s），塔伤/胜负奖励被 `γ^N` 折扣；
- 结论：模型看到"下牌帧 = 确定亏"，收益"远且不确定" → 最优反应是不下牌。

### 1.2 终端奖励被 discount 磨掉（独立于费差的深层问题）
- `gamma=0.99`、`max_ep_steps=600`（=300s 游戏时间）：
  `0.99^600 ≈ 0.0024` → 终端 ±10 / 平局 −10 的现值 ≈ **0.024**。
- 即使平局=失败已生效（d5aa7c4），惩罚现值也趋近 0 → "躺平"依然免费。
- **结论：任何不改 discount / 对局长度的终端加码（如 lose/draw=15）都基本无效。**

### 1.3 纯目标奖励的"浪费隐形"（用户历史实证）
去掉资源 shaping 后，唯一即时信号是塔血差：它只奖励"打到塔"，不惩罚"乱花"。
送死单位、空砸法术的代价只在终端出现，被 1.2 的 discount 磨掉 →
模型学"有费就放、见塔就砸"。**这证明 CR 的资源管理不能完全交给稀疏目标**，
需要某种"浪费可见"的短 credit 信号——但形式不能是"下牌即罚"。

### 1.4 手工折价（HP 比例估值）不可行
残血单位"现在值多少"依赖对手手牌/卡组/圣水/前排（弓箭手 vs 滚木反例），
任何静态公式（包括 hp/max × cost）必然在公式看不见的信息上出错；
一旦开始算"走到塔能造成多少伤害"就是在手工重写战斗求解器（力大砖飞）。
**估值是价值网络 V(s) 的职责，不是 reward 公式的职责。**

### 1.5 软控（冰冻/藤蔓）价值是反事实的
- 防守型：价值 = "塔本来会掉的伤害没掉" → 事件流里不存在，任何实际事件 shaping 零信号；
- 进攻型：价值 = "单位本会死/少打，因控制而多打" → 即时伤害 shaping 低估（看不到被阻止的），
  效果期窗口结算则**假归因**（把本来就会发生的伤害记给法术）→ 诱导"打架时乱放软控蹭账"。
- **结论：软控不靠 reward 归因（P3），靠示范 + critic + 真实后果回流。**

### 1.6 plan 通道缺少战术意图语言
`PlanToken`（plan_space.py，21 维）只有 8 个粗意图（defend_*/push_*/counterpush/spell_value/
cycle_and_wait）+ 区域 + 单卡槽位 + combo 数字标签。没有：
- `soft_control` / `spell_trade` / `punish` 类战术意图；
- 目标实体/目标类型（"对哪个单位放冰冻"）；
- 费用预算 / 阶段（combo 进行到哪一步）。
plan 是**可学习的条件提示**（模型可学会忽略坏 plan），意图字典为空 ⇒
模型从未被条件化到这些战术上，30% prophet 注入也不示范 ⇒ 永远学不会。

## 2. 设计原则

| # | 原则 | 含义 |
|---|---|---|
| P1 | **目标项 shaping，手段项不手工定价** | 塔血/皇冠/胜负 = 游戏目标 → 可即时 shaping；圣水/场面 = 手段 → 价值交给 V(s) 学 |
| P2 | **防双算第一原则** | 任何事件只进一次账（窗口结算与死亡清算/塔伤 shaping 不得叠加同一收益） |
| P3 | **不造反事实假账** | 软控/防守价值（被阻止的伤害）不通过事件归因伪造，靠示范+critic+真实后果 |
| P4 | **记账而非估值** | 场上部署费 = 客观投入记账（存活全额、死亡注销），**不做 HP 折价** |
| P5 | **结算配对** | "投入"与"产出"放进同一结算窗口；不在动作帧发确定惩罚（消除下牌即时罚） |
| P6 | **价格时变** | 塔血 vs 圣水的相对价格跟随圣水倍率（120s/240s），行为（后期法术砸塔）自动涌现 |
| P7 | **兼容演进** | plan/reward 扩展可回退：plan 尾部追加旧 ckpt 补零；reward 全走配置开关 |

## 3. Reward 架构 v2：双账本 + 时变价格

### 3.1 总结构

```
目标账（逐帧/事件即时，全局真实目标）
    r_tower  = tower_dmg(t) × Δ敌方塔血 − tower_dmg(t) × Δ我方塔血
    r_crown  = crown_bonus × Δ皇冠差（破塔里程碑）
    r_term   = ±win_bonus / −draw_penalty（对局结束，保留平局=失败）

资源账（窗口结算，只记投入产出配对）
    ΔΦ = edw(t) × [ Δ(手牌圣水 + Σ存活部署实体·部署费) − Δ(对方同款) ]
    结算点：每 30s 固定窗 + 120s/240s 价格切换 + 对局结束（不依赖"清场"）
```

### 3.2 目标账（改动小，独立生效）

| 项 | 现状 | v2 建议 | 理由 |
|---|---|---|---|
| `tower_dmg` | 0.001 恒定 | `0.001 → 0.002` 随 alpha 线性涨 | 后期塔血贵 → 斩杀/法术砸塔自动变正 EV（P6） |
| `crown_weight` | 5.0 | ⚙ 8.0~10.0 或显式破塔 bonus | 破塔是里程碑，应显著强于磨血（胜利太稀疏） |
| win/lose/draw | 10/10/10 | 保持 10/10/10（⚙ 可加 win） | 终端改动需先修 discount（1.2），否则无效 |

`alpha(t) = clip((battle.time − 120) / 120, 0, 1)`，与引擎圣水回复切换点对齐
（battle.py L2474：<120s 2.8s/点 → 120-240s 1.4s → 240s+ 三倍）。

### 3.3 资源账：记账式 Φ（不做 HP 折价）

```python
Φ(s) = edw(t) × [ (手牌圣水 + Σ 存活部署单位/建筑 × 部署费) − 对方同款 ]
```
- **部署单位帧**：E −c 与 V +c 同帧抵消 → ΔΦ=0 → 无下牌惩罚（消除躺平诱因）；
- **单位死亡**：V −c → 我方 Φ −c·edw（送死有代价）；
- **单位存活期间**：不发放任何 shaping → 残血不折价、无逐帧噪声；
- **法术**：无持久实体 → 施放记成本，效果（击杀返还对方 V）在效果期窗口内配对结算；
- **手牌圣水自然回复**：双方对称，不计入 ΔΦ（只结算动作帧引起的差）。

> 与旧"手牌圣水差"的本质区别：旧式把"出牌投资"当损失，账本式只把
> "投入还在不在 / 换回了什么"记账——这是 P4，不是估值。

### 3.4 结算窗口：固定窗 + 阶段点 + 终局（替代逐帧）

| 候选 | 判定 | 结论 |
|---|---|---|
| 逐帧 ΔΦ | 每决策步 | ❌ 下牌帧确定惩罚 → 躺平 |
| 清场触发 | 场上无部署实体 | ⚠ 语义好但稀疏；建筑流/持续下牌导致从不触发 → 仅作附加触发 |
| **固定窗 30s** | 每 60 决策步 | ✅ 无状态机、覆盖一切卡组（P5） |
| **阶段切换 120s/240s** | 价格曲线切换点 | ✅ 与 P6 对齐，账目语义自然 |
| **对局结束** | game_over / 截断 / 僵局 | ✅ 必须（terminal 资源差清算） |

推荐组合：**每 30s + 120s/240s + 终局**。清场触发可作 v2.1 附加项，不阻塞主线。
窗口结算期间 ΔΦ 不在中间帧发放 → "投入"与"产出"（死亡/击杀/法术效果）落在同一窗口配对。

### 3.5 法术记账细则（四类情形，P2 防双算）

| 情形 | 窗口内账目 | 结果 |
|---|---|---|
| 空砸 | 施放 −c，无任何返还 | 净亏 c·edw（惩罚） |
| 只砸塔 | 施放 −c，塔伤只进目标账 `tower(t)` | 前期净亏；后期 tower(t) 高 → 斩杀期自动划算 |
| 只砸单位 | 施放 −c，击杀返还对方 V +c' | 赚费差 c'−c（>0 则赚，=0 打平） |
| 砸塔+单位 | 双收 | 最优，后期最划算 |
| 软控（冰冻/藤蔓） | **不做事件归因**（反事实，P3） | 价值靠示范 + critic + 随后真实事件回流 |

> 控制效果期窗口（用户方案）仅作 v3 备选：它解决"何时结"，但仍需解决
> "结什么"（单位掉血度量），且有假归因风险——优先级低于示范通道（第 6 节）。

### 3.6 单位受伤 shaping（v3 备选，非首期）
若示范后模型仍学不会软控的"创造条件"价值，可加**客观伤害 shaping**：
单位每掉 1 血 → 打击方 +k（k 远小于塔血系数）。它是已发生事实（非估值），
与折价不同；风险是诱导刷单位伤害 → k 必须显著低于塔血 shaping，且需消融验证。

## 5. Plan 通道扩展（软控/combo 的教学语言）

### 5.1 PlanToken 兼容扩展（P7：旧 21 维不动，尾部追加）

| 字段 | 现状 | v2 追加 | 维度 |
|---|---|---|---|

| `target_kind` | 无 | none / troop / building / tower | +4 one-hot |
| `elixir_budget` | 无 | 连续 0..1（允许投入的费） | +1 |
| `combo_hint` | 0-3 数字 | 语义完善：1 坦克+后排 / 2 法术+单位 / 3 双路 | 0（复用） |
| 旧字段 | 21 维 | 语义不动 | 0 |

**维度预算：21 → 30**。加载旧 ckpt：尾部 9 维补零（plan 置零已有先例）。

### 5.2 planner 规则扩展（示范侧，与 reward 正交）

`belief_planner.py` / `prophet.py` 增加规则（全部使用现有 threat/pressure 计算）：

| 场景 | intent | target_kind |
|---|---|---|
| threat 高（敌方单位近塔/正在输出）且手牌有 Freeze/Vines | `soft_control` | troop（威胁单位所在区域） |
| 敌方沉底后排/高价值单位（prophet 特权可判） | `spell_trade` | troop |
| 敌方刚下大费单位 / 圣水 <2（prophet 已有判断） | `punish` | 视局面 |
| 我方坦克过桥、敌方下兵防守 | `spell_trade` | troop |
| 无威胁无压力、手牌差 | `setup_wait` | none |

关键纪律：planner 输出的是**意图 + 目标类型**，不放精确位置/牌序；
具体动作由模型从观测解（plan 是条件提示，不是 teacher forcing 答案）。

### 5.3 plan 的作用机制（备忘）
- 30% prophet（特权）帧 + 70% belief 帧，plan 每帧重新生成、作为输入条件进 actor+critic；
- 无模仿损失：模型学"给定 plan → 输出动作最大化回报"；坏 plan 会被网络学会忽略；
- 因此 plan 扩展的价值上限 = planner 规则质量 → 配第 7 节消融验证。

## 6. 软控/反事实战术的学习路径（明确"不靠 reward"）

1. **示范**：5.2 的 planner 规则让 30% 注入帧包含正确时机的软控轨迹；
2. **critic**：`V(s|plan)` 学"放了软控之后的价值"，advantage 把策略推向高价值动作；
3. **真实后果回流**：塔血 shaping 主位 + Phase 0 discount 修复，让"防守成功 = 避免未来负收益"
   通过 value bootstrap 可见；
4. **不做**：软控事件归因 shaping（P2/P3）；
5. **v3 备选**：单位受伤 shaping（3.6），仅当 1-3 跑完仍学不会再启用。

## 7. 验证方法（诚实红线）

- A/B 同种子、同局数、同对手副本；只信趋势 `|Δ|/SE ≥ 2σ`；
- 评估看 **W/D/L 分布** 而非 mean_reward（16D 但 mean 变化可能是假的）；
- 行为探针（从 replay/统计落盘）：
  - 空砸法术率（法术施放后零命中比例）
  - 单位部署后 30 步存活率（送死率）
  - 解牌事件频率（法术后 5 步内敌方单位死亡）
  - 软控使用率与使用场景（threat 高时是否用 Freeze/Vines）
  - 后期（time>180）法术砸塔率（验证 P6 价格时变生效）
- 消融矩阵：
  - plan 注入 vs plan 置零（README 已有消融先例）
  - edw 时变 on/off
  - gamma/max_ep_steps 新旧
- 每 eval 检查点保留 `league_<step>.pkl` 回放目检关键对局。

## 9. 风险与回退

| 风险 | 缓解 |
|---|---|
| 记账式死亡清算过重 → 压死进攻送死 | 死亡清算系数 ⚙（< edw）；塔血系数同步上调 |
| 时变价格引入非平稳 reward | 窗口结算 + value 适配；观察 value loss |
| gamma 提高 → value 方差大 | vf_coef / batch_size 回调 |
| plan 维度变化 → 旧 ckpt 不兼容 | P7 尾部补零；正式重训一次 |
| 固定窗结算切在"一波中间" | Φ 状态差自洽，跨窗无碍（窗口归因，非波语义） |
| 计算开销（Φ 需遍历实体） | 增量维护：部署 +c / 死亡 −c 钩子，不在每帧全量遍历 |
